# analyze — стоит ли делать пет-проект (Opus 1M, xhigh)

По перспективной работе (уже прошла score) дай **полный разбор**: стоит ли строить продукт
под эту нишу и во что это обойдётся. Думай глубоко и трезво — это дорогой шаг, его гоняют
только на кандидатах со `score > 60`.

## Вход
```
{ "phrase": "...", "freq": 1234, "score": 0-100, "description": "...",
  "yandex": [ {"rank","url","title","snippet"}, ... ],
  "google": [ ... ] }
```

## Контекст рынка (учитывай)
- `freq` — базовая частота Вордстата, **завышена в ~3–10 раз** (широкое соответствие). Реальный
  точный спрос кратно ниже.
- На #1 в выдаче кликают ~30% (CTR). Реальный захватываемый трафик = реальный спрос × ~0.3.
- Рынок — **Россия, рубли**. Монетизация: реклама/РСЯ, партнёрка (Ozon/WB/Я.Маркет), freemium/SaaS,
  донаты, лидоген.
- Ценность = **спрос ÷ конкуренция × лёгкость реализации**. Крошечный спрос при нулевой
  конкуренции и лёгкой сборке — валиден.

## Что оценить
1. **Есть ли реальная незакрытая потребность** (по выдаче: что реально ищут, чем закрывают сейчас, чего не хватает).
2. **Реальный захватываемый спрос** (дефлировать base-freq, прикинуть трафик на #1).
3. **Почему выдача слабая** (конкретные причины из SERP).
4. **Реализация:** тип продукта (инструмент/лендинг+партнёрка/SaaS/контент), стек, ключевые
   фичи, объём работ (S/M/L + оценка в человеко-неделях), риски, монетизация.
5. **Вердикт:** `verdict_score` 0–100 (спрос ÷ конкуренция × лёгкость — численная оценка) и его
   бакет `recommendation`: `BUILD` (≈≥70) / `MAYBE` (≈40–70) / `SKIP` (<40). Границы — ориентир.

## Выход (JSON)
```
{
  "recommendation": "BUILD" | "MAYBE" | "SKIP",
  "verdict_score": 0-100,
  "confidence": 0.0-1.0,
  "report_html": "<весь отчёт одним HTML-документом по шаблону templates/report.html>"
}
```
- `recommendation` + `verdict_score` → колонки `node.verdict` / `verdict_score` (бейдж +
  ранжирование финальных ниш). `verdict_score` 0–100 = спрос ÷ конкуренция × лёгкость.
- `report_html` — **полный человекочитаемый отчёт** одним HTML, заполненный по шаблону
  `templates/report.html`: шапка с вердиктом и `verdict_score`; разделы — незакрытая
  потребность, реальный спрос (с дефляцией base-freq), почему выдача слабая, реализация
  (таблица тип / усилия / человеко-недели / стек / фичи / риски / монетизация) и опорная
  выдача. Система сохранит его в `reports/{id}.html`.
