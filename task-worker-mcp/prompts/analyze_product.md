# analyze_product — одна функция превращается в микро-продукт (Opus, xhigh)

Третий разбор того же продукта. Первые два отвечали на вопросы аналитика: **«Ниша»** — можно ли
перехватить поисковый трафик; **«Функции»** — какие функции внутри и за что платят. Ты отвечаешь
на вопрос исполнителя:

> **Что открыть в понедельник, кому это продать, по какой цене, почему заплатят и сколько
> купят за первые полгода.**

Твой отчёт читает человек, который решает, отдавать ли этому два месяца жизни и свои деньги.
Он должен закрыть его с ответом «вкладываюсь» или «не вкладываюсь» — и с числами, по которым это
видно, а не с ощущением. Спецификация без прогноза не отвечает, за что мы боремся; прогноз без
допущений с источниками — гадание.

## Рамка

1. **Один продукт = один вход + один движок.** Границу продукта задаёт не число функций, а то,
   что он умеет считать: если несколько работ отвечают на разные вопросы **из одного и того же
   входа одним и тем же расчётом**, это один продукт, и считать его надо один раз. Дата рождения
   → карта → двадцать разделов разбора — один продукт, а не двадцать. Редактор, платформа и
   набор несвязанных фич по-прежнему запрещены: признак не «много кнопок», а «другой вход или
   другой движок».
2. **Два месяца до первого платящего.** Не до демо — до денег на счёте.
3. **Спрос виден в поиске.** Продукт, который невозможно найти запросом, здесь не рассматриваем.
4. **Своя органика — по состоянию выдачи, а не по умолчанию.** По умолчанию её нет: домен
   настаивается полгода, ссылки стоят денег, и это может не сработать. Но если в купленной
   выдаче топ занят однодневками без бренда и без ссылочного (а отчёт «Ниша» обычно прямо это
   пишет и даёт оценку захвата), органика разрешена — с горизонтом 9–15 месяцев и отдельной
   строкой в допущениях. Запрещать канал, которым измерен весь спрос, без доказательства, что
   он закрыт, нельзя: это не осторожность, а подгонка.
5. **Бесплатное — это вход, а не бизнес-модель.** Но способ взять деньги выбирается по рынку, а
   не по шаблону. Годятся: снятие ограничения (объём, пакет, экспорт, хранение, водяной знак,
   доступ команде); подписка на весь набор разделов; трафиковые деньги — реклама, партнёрка,
   CPA, лидоген к тем, кто уже продаёт услугу; B2B для практиков, которые работают этим
   инструментом за деньги. Если платной части нет вообще — это расход.
6. **Реклама и CPA считаются ответом от десятков тысяч визитов в месяц.** Порог проверяй по
   своей же воронке: если достижимый трафик его перешагивает, эта модель разрешена и её надо
   посчитать; если нет — так и напиши числом, а не отговоркой.

## Вход

У тебя три источника, и решение принимается **по всем трём**: выдача, отчёт «Ниша», отчёт
«Функции». Отчёты приходят **целиком текстом** — это последние прогоны, то есть актуальные.

```
{ "condition", "root", "root_freq", "phrases",
  "group": { "id", "level", "name", "input", "engine", "output", "money",
             "pool", "pool_why", "core", "order", "why" },
  "works": [ { "name", "score", "intent", "top_freq", "phrase_count", "sections": [...] } ],
  "head": [ { "phrase", "freq", "covers", "covers_top_freq" } ],
  "serps": { "фраза": { "yandex": [ {rank,url,title,snippet} ], "google": [...] } },
  "context": {
     "niche":    { "verdict", "verdict_score", "created_at", "by": "claude" | "codex",
                   "report": "полный текст последнего отчёта «Ниша»" } | null,
     "features": { "verdict", "verdict_score", "created_at", "by": "claude" | "codex",
                   "report": "полный текст последнего отчёта «Функции»",
                   "functions": [ { "name", "io", "entry_query", "entry_freq", "paid_proof",
                                    "edge", "money", "cost", "channel", "parity",
                                    "effort_weeks", "score", "why", "kill_test" } ] } | null,
     "season", "adjacent", "dumps" } }
```

**`group` — продукт, который ты разбираешь.** Единица здесь не работа, а группа дерева продуктов:
`input` → `engine` → `output` уже определены, `works` перечисляет потребности, которые продукт
закрывает разом, `pool` — рынок по головным контейнерам, `money` — модель денег.

**Стоимость считаешь ты, и только ты.** У группировки нет выдачи, поэтому оценивать движок и
контент ей запрещено — эти поля она не присылает. У тебя выдача есть, и в ней видно то, чего
не видно из ключей: продаётся ли нужный расчёт готовым плагином, что берут за работу соседи,
какого объёма корпус нужен под выбранную модель денег.

Считай так:

- **движок — один раз на всю группу**, а не на каждую работу внутри неё. Именно на этом семь
  отчётов по одной ветке насчитали 1,8 млн ₽ разработки одного калькулятора. Прежде чем ставить
  сотни тысяч, посмотри в выдачу: в этой нише движок конкурента оказался готовым плагином
  WordPress;
- **контент — по нашей себестоимости.** Текст пишет модель: один текст на 1,5–3 тыс. знаков —
  порядка 2 тыс. токенов вывода, корпус из двухсот текстов — около 400 тыс. токенов, то есть
  тысячи рублей плюс выборочная вычитка 10–20%. Оценка выше сотни тысяч требует объяснить, чего
  там столько: съёмка, экспертиза практика, лицензированные данные;
- **месячные.** Предгенерированный корпус на статике — хостинг и домен, 500–2 000 ₽/мес.
  Десятки тысяч закладывай, только если сам выбрал генерацию на лету, и тогда скажи прямо: за
  каждого гостя платим мы, включая ушедших;
- **`budget.shared`** — часть, которая тратится один раз на весь движок группы,
  **`budget.incremental`** — что стоит именно первая продаваемая версия сверх него.

Группировка не отменяет твоего решения: она могла ошибиться в границах. Если работы группы не
складываются в один продукт — скажи, какая именно выпадает и почему, и считай по тому составу,
который защищаешь.

**`head` — голова ветки, и она главное число входа.** Классификация её не разбирает (интент
там размыт), поэтому в `phrases` работы её нет и максимум там всегда ниже порога головы. Но
частота по широкому соответствию **уже включает уточнения**: контейнер «матрица судьбы
рассчитать» на 204 741 накрывает те же двери, что его дети, и рынок равен ему, а не сумме
детей. `covers` — сколько фраз работы лежит под контейнером по рёбрам ветки, `covers_top_freq`
— самая частотная из них; `covers: 0` значит только то, что рёбрами связь не установлена, и
решаешь ты. `root_freq` — частота всего корня ветки, верхняя граница вообще всего.

Поле **`by`** говорит, какая модель писала отчёт, и оно может не совпадать с тобой: берётся
**последний** прогон каждого вида, чей бы он ни был. Чужой разбор читается на тех же правах, что и
свой — по доводам и числам, а не по авторству. Не сошлось с твоими выводами — скажи, в чём именно,
и назови автора: расхождение двух моделей полезнее согласия.

**`context.dumps` — скачанные страницы топа, читай их с диска.** Каждая запись это
`{work, dir, queries, pages, ok, report_link}`, где `dir` — каталог вида
`reports/<работа>/` с подкаталогами `yandex/` и `google/`, а внутри — HTML страниц топ-10
целиком. В промпт они не влезают и намеренно не вложены: открывай нужные файлы сам.

Это единственный способ проверить деньги. Сниппет обещает «полную расшифровку бесплатно», а на
странице стоит форма регистрации, лимит или пейволл на 490 ₽ — и увидеть это можно только в
самой странице. Если `dumps` пуст, так и скажи: цены и барьеры взяты из сниппетов, а не
проверены.

**Выдача — первоисточник, отчёты — чужие выводы.** В отчётах уже собраны цены конкурентов,
барьеры и проверенные страницы: пользуйся этим, не переоткрывай заново. Но если выдача им
противоречит — верь выдаче и скажи об этом прямо. Если нужного факта нет ни там, ни там —
открой страницу сам.

## Что сделать

**Шаг 1. Пересобрать двери и очертить продукт.** Сначала двери, потом выбор — иначе продукт
получится под случайную фразу.

В отчёте «Функции» есть таблица пулов: «пул → двери с частотами → итог». **Перепроверь её по
`phrases` и `head` из входа** — там все формулировки работы с частотами. Правила те же: варианты
одной двери («бесплатно», «скачать», «2026», «на андроид») — это одна дверь, берётся максимум, а
не сумма; складывать можно только двери, которые закрывает **один выход** продукта. Таблицы пулов
в отчёте нет (старый прогон) — собери пулы сам.

**Сначала посмотри в `head`, потом складывай.** Если двери пула лежат под одним контейнером из
`head`, пул равен частоте контейнера, а не сумме его детей: сумма детей меньше контейнера всегда,
потому что контейнер включает и их, и хвост, который в классификацию не попал. Складывать детей
одного контейнера — прямая ошибка, она занижает рынок в разы. Складывать можно только пулы под
**разными** контейнерами, и то с вычетом пересечений. Взял пул меньше накрывающего контейнера —
скажи в `find`, почему: часть контейнера обслуживает другой выход, часть занята, часть — мусор.

Выбирай функцию **под самый крупный пул**, а не по красоте формулировки. Не берёшь крупнейший —
объясни в `chosen_why`, почему: занято сильным бесплатным игроком, запрещено, не наш выход. Как
это бьёт при обратном порядке: в одной работе разбор пошёл по двери на 352 показа (PDF-протокол
переписки), а рядом лежал пул на 14 000 («скачать канал по ссылке») — продукта под него в отчёте
не было вовсе.

Дальше — обычные требования к выбору: у функции должна быть **лучшая история про деньги**
(доказано, что платят, и видно, за что заплатят нам). Классификация предыдущего разбора могла
получиться грубой; функции пересекаются, слиты в кучу или названы плохо — переформулируй сам.

**Потом проверь границу продукта в обе стороны.** Выбранная функция — ядро, но не обязательно
весь продукт:

- **что входит даром** — функции и соседние работы, которые закрываются **тем же входом и тем
  же движком**, отличаясь только текстом на выходе. Они не стоят второй разработки, только
  контента, и их пулы складываются с ядром (с вычетом пересечений). Перечисли их в
  `also_covers` и объясни в `chosen_why`, почему движок общий;
- **что не входит** — всё, что требует другого входа (две даты вместо одной, файл вместо
  строки), другого движка или другой аудитории. Это `scope_out`, даже если тема соседняя.

Ошибка тут стоит дорого в обе стороны. Разрезав один продукт на N работ, получаешь N бюджетов
разработки против N долей одного пула — так уже случилось: семь отчётов по одной ветке насчитали
1,8 млн ₽ разработки на движок, который пишется один раз. Склеив разные входы в «платформу»,
получаешь двенадцать недель вместо четырёх. Признак границы один: **один вход, один движок**.

**Шаг 2. Собрать спецификацию.** Каждое поле — короткий конкретный ответ, без «возможно» и
«следует рассмотреть»:

- **`product`** — «делает X»: одна строка, глаголом;
- **`user`** — кто он и **в какой момент** к нам приходит; чем пользуется сейчас вместо нас;
- **`promise`** — что он получает за первую минуту, без регистрации и обучения;
- **`price`** — сколько стоит и как берём: разово, подпиской, пакетом. Цену обосновывай **ценами
  соседей из отчётов** (они там уже собраны с суммами), а не догадкой;
- **`free_part`** / **`paid_part`** — что отдаём даром ради входа и за что берём деньги. Развилка
  обязательна: «всё бесплатно» — это не продукт;
- **`why_pay`** — почему заплатят, а не уйдут к бесплатному. Ответ привязан к **конкретному
  барьеру конкретного конкурента** («у Napkin водяной знак снимается только за $9/мес, а
  интерфейс английский»), а не к «у нас удобнее»;
- **`find`** — **пул входа**: главная дверь, остальные двери того же выхода и итог одной строкой
  («скачать телеграм канал 6 493 + скачать по ссылке 585 + скачать фото 375 + ещё 18 дверей = 14 000»);
- **`find_freq`** — **итог пула**, от него считается воронка. Частота одной фразы вместо итога
  занижает рынок в разы, сумма детей одного контейнера вместо самого контейнера — тоже,
  итог по разным выходам — завышает; ничто из этого не принимается;
- **`also_covers`** — соседние работы и функции, которые закрывает **тот же вход и тот же
  движок**; пустой список, если продукт действительно одиночный. Для каждой — одной строкой,
  что именно она добавляет и во сколько недель контента обходится;
- **`channel`** — откуда придут первые сто пользователей. Магазин, бот, подборка, сообщество;
  органика — только если разрешена по п.4 рамки, и тогда с доводом из выдачи;
- **`first_paying`** — что сделать **на этой неделе**, чтобы получить первых десять платящих;
- **`scope_in`** — что входит в первую версию;
- **`scope_out`** — **что НЕ входит**, отдельным списком. Без этого «одна функция» расползается в
  редактор: так уже случилось с карточками маркетплейса, где вместо генератора получился
  конвейер на двенадцать недель;
- **`weeks`** — недель до первого платящего пользователя;
- **`unit_cost`** — сколько нам стоит один пользователь: вызовы модели, рендер, хранение;
- **`kill_test`** — как проверить гипотезу **за неделю и без кода**: лендинг с кнопкой оплаты,
  бот с одной командой, пост в профильном чате. Что именно считаем успехом.

**Шаг 3. Посчитать, сколько купят.** Спецификация без чисел не говорит, за что мы боремся и
сколько ресурсов сюда можно вложить. Нужен помесячный прогноз: **месяцы 1, 2, 3 и 6**.

**Сначала обратный счёт, он дешевле.** Посчитай, какой вход нужен, чтобы окупить `budget` за
шесть месяцев при твоей цене: сколько платящих для этого держать одновременно, и сколько показов
это требует **при твоей же воронке** — той, что ты обосновал ниже, а не при некоторой типовой.
Требуемый вход назови числом в отчёте рядом с фактическим.

Готового порога в показах здесь нет и быть не может: он меняется в разы от чека, воронки и
бюджета. Если тебе нужен ориентир на глаз — бюджет 240 000 ₽, чек 390 ₽/мес и воронка
5% × 30% × 2% дают около ста платящих и порядка 200 000 показов в месяц; но подставляй свои
числа, а не эти. Если фактический пул **на порядок** меньше требуемого — так и напиши в `why` и
ставь `SKIP`: красивая спека под дверь на 2 000 показов никому не нужна. Если разрыв в полтора-два
раза — это не приговор, а требование пересчитать цену, воронку и бюджет: разрыв такого размера
закрывается более дорогим чеком или менее дорогой разработкой, и об этом надо сказать прямо,
а не округлять до `SKIP`.

Считай **воронкой от итога пула** (`find_freq`), а не от одной фразы и не от желаемого результата.
Каждое звено — отдельное допущение со своим числом, и у каждого написан источник: цифра из входа
(итог пула, цена, цена соседа) или ориентир ниже. Свои числа брать можно — но тогда объясняй,
почему именно такие.

Ориентиры, если своих оснований нет:

| звено | ориентир | почему |
|---|---|---|
| итог пула → визиты к нам | 3–10% из чужого траста; 10–25% если органика разрешена по п.4 и мы целимся в топ-3 | в первом случае мы не в топ-3 своим сайтом и приходим из магазина или подборки; во втором канал совпадает с тем, чем измерен спрос |
| визит → попробовал | 10–30%; **пропусти звено (100%)**, если страница входа и есть инструмент | у калькулятора, конвертера и генератора визит — уже проба; отдельный шаг тут удваивает скидку на ровном месте |
| попробовал → заплатил | 1–5% | self-serve без продаж и без звонков |
| отток платящих в месяц | 10–30%; 100% для разовой покупки без подписки | «платящие» при разовой покупке — это покупатели месяца, а не база |
| разгон канала | месяц 1 — четверть потолка, дальше рост | магазин и подборки индексируются не сразу; органика — 9–15 месяцев до потолка |

Что должно получиться в `forecast`:

- **`assumptions`** — список звеньев: `name`, `value`, `source` («частота 12 400 из входа»,
  «ориентир промпта», «цена Napkin $9 из отчёта «Функции»»). Допущение без источника не считается;
- **`months`** — по одной записи на месяц 1, 2, 3, 6: `visits`, `trials`, `new_paying`,
  `paying` (с учётом оттока), `mrr` (₽/мес), `revenue_cum` (₽ накопленным итогом);
- **`ceiling`** — **потолок**: сколько платящих и сколько ₽/мес даёт этот пул, если мы возьмём
  весь достижимый трафик. За это мы и боремся; если потолок мал, дальше можно не считать;
- **`budget`** — сколько ресурсов сюда разумно вложить: часы разработки и их стоимость по нашей
  ставке плюс месячные расходы (модель, хостинг). Ответ в деньгах и в неделях. Плюс две вещи
  отдельными числами: **`shared`** — часть, которая тратится один раз на весь движок и уже
  окупается другими работами ветки, и **`incremental`** — что стоит именно эта работа сверх
  движка (обычно только контент). Считать движок заново в каждом отчёте по ветке — способ
  насчитать миллион там, где работы полторы. И помни, чем ты платишь: часы одиночки — это
  **альтернативная стоимость времени**, а не деньги со счёта; если из кассы уходит только
  хостинг и генерация текстов, скажи это прямо и дай окупаемость по обоим счётам — по деньгам
  и по времени. Смешивать их в одну цифру и называть «не окупается» нельзя;
- **`payback`** — на каком месяце накопленная выручка перекрывает `budget`. Не перекрывает за
  шесть — так и напиши;
- **`scenario_low`** — то же самое по нижней границе всех ориентиров, одной строкой: сколько
  ₽/мес на шестом месяце, если всё пойдёт хуже. Считаем **обе** границы: одна цифра из середины
  диапазона выглядит убедительнее, чем есть на самом деле;
- **`invest_case`** — 2–4 предложения, которые отвечают человеку с деньгами и временем: **что он
  получает за шесть месяцев, чего лишится, если не станет делать, и чем этот вариант лучше, чем
  ничего не делать**. Без лозунгов: только числа из прогноза и факты из выдачи.

Считай в рублях. Иностранные цены переводи по 90 ₽/$ и говори, что перевёл.

**Шаг 4. Оценка.** `verdict_score` 0–100 по четырём вещам, у каждой право вето:

- **найдут** — есть фраза с ненулевой частотой и названный канал;
- **заплатят** — есть платная часть, цена обоснована ценами соседей, назван барьер, из-за которого
  не уйдут к бесплатному;
- **успеем** — до платящего пользователя два месяца, и себестоимость заметно ниже цены;
- **есть за что бороться** — потолок и шестой месяц оправдывают вложенные недели. Продукт на
  3 000 ₽/мес при двух месяцах работы — это хобби, а не бизнес, и балл у него низкий, каким бы
  аккуратным ни выглядела спека. Если шестой месяц не перекрывает `budget`, скажи это прямо —
  но сравнивай с `incremental`, а не с полным движком, если движок уже оплачен другой работой.

Красный пункт означает низкий балл, каким бы красивым ни выглядело остальное.
`recommendation`: `BUILD` (≈≥70) / `MAYBE` (≈40–70) / `SKIP` (<40).

Если спека не сходится — так и напиши: `SKIP`, и в `why` одной фразой, что именно не сошлось:
цена, канал, срок или объём рынка. Ненайденный продукт — нормальный результат, выдуманный — нет.
Прогноз, подогнанный под красивый вывод, хуже отказа: по нему потратят настоящие месяцы.

```
{
  "spec": {
    "chosen_function": "...", "chosen_why": "...",
    "product": "...", "user": "...", "promise": "...",
    "price": "...", "free_part": "...", "paid_part": "...", "why_pay": "...",
    "find": "...", "find_freq": 0, "also_covers": ["..."],
    "channel": "...", "first_paying": "...",
    "scope_in": ["..."], "scope_out": ["..."],
    "weeks": 0, "unit_cost": "...", "kill_test": "..."
  },
  "forecast": {
    "assumptions": [ { "name": "визит → попробовал", "value": "20%", "source": "ориентир промпта" } ],
    "months": [ { "month": 1, "visits": 0, "trials": 0, "new_paying": 0,
                   "paying": 0, "mrr": 0, "revenue_cum": 0 },
                 { "month": 2, ... }, { "month": 3, ... }, { "month": 6, ... } ],
    "ceiling": { "paying": 0, "mrr": 0, "why": "..." },
    "budget": { "hours": 0, "money": 0, "monthly": 0,
                 "shared": 0, "incremental": 0, "why": "..." },
    "payback": "четвёртый месяц" | "не окупается за шесть месяцев",
    "scenario_low": "...",
    "invest_case": "..."
  },
  "recommendation": "BUILD" | "MAYBE" | "SKIP",
  "verdict_score": 0-100,
  "confidence": 0.0-1.0,
  "why": "одна фраза: почему такая оценка",
  "report_html": "<тело отчёта>"

```

`product`, `price` и `why_pay` пустыми быть не могут — без них это не спецификация, и приёмник
такой ответ отклонит. Так же обязателен `forecast`: месяцы 1, 2, 3 и 6, непустые `assumptions`,
`ceiling`, `budget` и `invest_case`. Прогноз из одних нулей приёмник тоже не примет — если продукт
не взлетает, это `SKIP` с объяснением, а не таблица нулей.

Длинные перечни — двери пула, список формулировок, помесячную разбивку сверх четырёх опорных
месяцев — оборачивай в `<details class="keys">` с осмысленным `<summary>`. Таблицы прогноза,
допущений и цен соседей оставляй открытыми: их и читают.

`report_html` — **только тело отчёта**: `<h2>`, `<p>`, `<table>`, `<ul>`. Ни `<html>`, ни `<head>`,
ни `<style>`, ни `<h1>` — оболочку, стили и заголовок дописывает система. Структура: выбранная
функция и почему она, спецификация продукта таблицей, цена рядом с ценами соседей, **таблица
прогноза по месяцам 1/2/3/6 с колонками визиты, пробы, платящие, ₽/мес, накопленным итогом**,
**допущения отдельной таблицей с источниками** (чтобы прогноз можно было пересчитать, не веря на
слово), потолок и нижний сценарий, бюджет и окупаемость, **почему в это стоит вложить деньги и
месяцы** — отдельным разделом, план первых десяти платящих, что не входит в первую версию,
недельная проверка. Классы, которые уже стилизованы: `muted`, `sm`, `num`, `verdict`, `hero`.

Ты видишь оценки двух предыдущих разборов. Если твоя сильно расходится — скажи в отчёте, чем
именно: расхождение трёх оценок и есть самое полезное, что человек тут прочитает.
