# needs — дерево потребностей по ветке дерева запросов

На входе — ветка дерева поисковых запросов Яндекс.Вордстата: фразы с частотами и структурой
«кто кого уточняет». Твоя работа — собрать из этих фраз **дерево потребностей**: не список
запросов, а перечень **работ**, которые люди хотят сделать.

**Работа** — то, какой результат человек хочет получить: «оживить фото», «написать текст»,
«сделать видео из моей фотографии». Одну работу выражают десятки разных фраз. Цель — увидеть
работы и то, где внутри работы есть **узкая потребность**, которую мог бы закрыть небольшой
продукт.

Смотри **всю ветку целиком**. Узкая работа с частотой 589 — это шум, если смотреть на неё
отдельно, и заметная щель, если рядом видно, что похожая работа собирает 3 861. Сравнение и есть
смысл задачи.

## Три уровня

1. **Условие** — рамка всей ветки, если она есть. Слова «бесплатно», «без регистрации», «на
   русском», «онлайн», «скачать» — это **не работа**, а требование к продукту и признак
   аудитории. Если вся ветка стоит под таким условием, назови его один раз сверху и больше не
   дроби по нему работы.
2. **Работа** — что человек хочет сделать.
3. **Внутри работы — два вида подгрупп**, и путать их нельзя:
   - **сегмент** (`kind: "segment"`) — другой вход, другая аудитория, другое ограничение.
     Именно здесь обычно и живёт микро-продукт;
   - **раздел** (`kind: "section"`) — **тот же вход и тот же продукт**, отличается только то,
     какую часть ответа человек спрашивает. Позиция карты, тема разбора, глава отчёта, одно поле
     из выдаваемой формы. Раздел не требует второй разработки: движок уже посчитал всё, меняется
     текст на выходе.

## Как решать (по порядку)

1. **Отложи то, что вообще не работа** (см. «Что исключать»). Сначала убери мусор — на
   оставшемся картина видна яснее.
2. **Сгруппируй остальное по результату**, которого хочет человек. Ориентируйся на глагол
   (что делаем) и объект (с чем). Разные слова для одного результата — одна работа: «убрать
   фон» и «удалить фон» это одно; опечатки и перестановки слов — тоже одно.
3. **Внутри каждой работы поищи сегменты**: где вход другой, где аудитория другая, где
   ограничение другое.
4. **На этом остановись.** Не оценивай рынок, конкурентов, возможность продукта, «занятость»,
   щели или вероятность успеха. Это отдельная команда над уже принятой классификацией.

## Различения, на которых легко ошибиться

- **Создать новое ≠ обработать своё.** «Сгенерировать фото по описанию» и «улучшить моё фото» —
  **разные работы**: во втором случае у человека уже есть файл и новый ему не нужен.
- **Вход важнее слов.** «Сделать видео по описанию» и «сделать видео из моего фото» выглядят
  почти одинаково, а это два разных продукта.
- **Слова похожи — работа разная.** «Поменять фон на фото» и «поменять лица на фото» отличаются
  одним словом, но это совершенно разные продукты. Не склеивай по похожести слов; склеивай по
  совпадению результата.
- **Уточнение-модификатор своей работы не образует.** «Убрать фон онлайн» и «убрать фон онлайн
  бесплатно» — одна работа, а «бесплатно» относится к условию.

## Частоты

Частота — широкое соответствие: число родителя **уже включает** его уточнения. Поэтому
**складывать частоты нельзя** — сумма даст кратное завышение. Для работы указывай `top_freq` —
наибольшую частоту среди её фраз, и `phrase_count` — сколько фраз ты в неё отнёс.

Если считаешь количества — считай точно по выданному JSON, а не на глаз, и осторожно с
подстроками: «чат» сидит внутри «ска**чат**ь».

## Вход

Данные приходят одним из двух способов, смотри `params`:

- **есть поле `input_file`** — это путь к файлу, прочитай его;
- **нет** — данные лежат прямо в `params`.

Форма одна и та же:

```
{ "root": "...", "root_freq": 12345, "min_freq": 50, "max_freq": 30000,
  "nodes":      [ { "phrase": "...", "freq": 12345, "children": ["...", "..."] }, ... ],
  "head_nodes": [ { "phrase": "...", "freq": 204741, "children": [...] }, ... ] }
```

`children` — дети из той же ветки (кто уточняет кого). Фраз, которых нет во входе, не выдумывай.
Файл читай целиком: работать по части ветки нельзя, вся суть задачи в сравнении внутри неё.

## Выход

```
{
  "condition": "бесплатно · без регистрации · на русском" | null,
  "works": [
    { "name": "оживить фото",
      "phrases": ["...", "..."],
      "top_freq": 11081,
      "phrase_count": 15,
      "unclear": false,
      "segments": [
        { "name": "через голосовой помощник", "kind": "segment", "phrases": ["..."],
          "why": "..." },
        { "name": "аркан под сердцем", "kind": "section", "phrases": ["..."],
          "why": "тот же вход и тот же расчёт, другой раздел ответа" }
      ],
      "why": "1-2 предложения: почему это одна работа и что про неё видно"
    }
  ],
  "excluded": [
    { "phrase": "...", "why": "brand|catalog|consumption|broken|condition|other",
      "note": "коротко, если есть что добавить" }
  ]
}
```

**Как отдавать ответ:** если у джоба есть **`result_file`** — запиши JSON в этот файл и вызови
`submit_result(job_id)` **без** параметра `result`; обвязка прочитает файл сама. Ответ большой, и
через вызов инструмента он может молча обрезаться по длине, дав валидный JSON без хвоста. Свой
путь не подставляй, пиши ровно в объявленный. Если `result_file` нет — отдавай результат значением.

Перед отправкой сделай второй внутренний просмотр результата: у каждой конкретной работы заново
прочитай 20 самых частотных назначенных фраз. Всё, что требует угадывать результат, перенеси в
существующую `unclear`-работу; всё, что требует другого микро-продукта, вынеси в отдельную
работу. После переносов пересчитай `phrase_count` и `top_freq` по фактическим фразам.

Ответ проверяется на приёме. Если вернулось `accepted: false` — в `problems` перечислено, что
именно не так (какие фразы потеряны, каких нет во входе, где не сходится `phrase_count`):
почини и вызови `submit_result` снова. Пересобирать всё заново не нужно.

Дерево должно быть **осмысленным, а не полным по форме**: лучше десяток честных работ с
понятными границами, чем сорок групп по одному слову.
