# analyze_work — стоит ли делать продукт под РАБОТУ (Opus 1M, xhigh)

Разбираешь **работу** из дерева потребностей, а не отдельную фразу. Работа — это то, какой
результат человек хочет получить; её выражают десятки формулировок, и все они перед тобой.
Отчёт по нише — один, на работу.

Думай глубоко и трезво: шаг дорогой, его запускают вручную по конкретной работе.

## Вход

```
{ "condition": "рамка ветки: бесплатно · без регистрации · на русском" | null,
  "root": "узел дерева запросов, по которому собрана ветка",
  "work": { "name": "...", "top_freq": 11081, "phrase_count": 15,
            "occupied_by": "продукт, если работа похоже занята" | null,
            "gap_candidate": true|false, "unclear": true|false,
            "needs_serp": true|false, "serp_question": "что проверить в выдаче" | null,
            "why": "почему сборка считает это одной работой" },
  "segments": [ { "name": "...", "phrases": ["..."], "gap_candidate": ..., "why": "..." } ],
  "phrases": [ { "phrase": "...", "freq": 11081 }, ... ],   // ВСЕ формулировки работы
  "serps": { "фраза": { "yandex": [ {"rank","url","title","snippet"}, ... ],
                        "google": [ ... ] } } }             // топ-10 по самым частотным
}
```

`condition`, `occupied_by`, `gap_candidate` и `why` — это **гипотезы предыдущего шага**, а не
факты. Выдача у тебя есть; если она их опровергает — так и напиши, это ценнее подтверждения.

## Как считать спрос

- **Частоты не складывай.** Частота Вордстата — широкое соответствие: число более общей фразы
  уже включает свои уточнения. Опирайся на `top_freq` как на порядок величины и отметь, сколько
  формулировок в работе.
- `freq` **завышена в ~3–10 раз** относительно точного спроса.
- На #1 в выдаче кликают ~30%. Реальный захватываемый трафик = реальный спрос × ~0.3.
- Рынок — **Россия, рубли**. Монетизация: реклама/РСЯ, партнёрка (Ozon/WB/Я.Маркет),
  freemium/SaaS, донаты, лидоген.
- Ценность = **спрос ÷ конкуренция × лёгкость реализации**. Крошечный спрос при нулевой
  конкуренции и лёгкой сборке — валиден.

## Что оценить

1. **Занята ли работа.** По выдаче: кто её сегодня закрывает, насколько хорошо, и какой ценой
   для пользователя (регистрация, оплата, качество). Если `occupied_by` подтверждается — скажи
   прямо, что нишу держат, и чем её можно взять (или что нельзя).
2. **Есть ли незакрытая потребность** и в чём именно она: чего в выдаче нет, что люди просят
   формулировками, а получают не то.
3. **Не сидит ли внутри работы более узкий сегмент**, который стоит закрыть отдельным
   микро-продуктом. Смотри `segments` и сами формулировки: узкий вход, своя аудитория, своё
   ограничение. Часто именно там весь смысл — большая работа занята, а её угол свободен.
4. **Реальный захватываемый спрос** (с дефляцией `freq` и поправкой на CTR).
5. **Реализация:** тип продукта (инструмент / лендинг + партнёрка / SaaS / контент), стек,
   ключевые фичи, объём работ (S/M/L плюс оценка в человеко-неделях), риски, монетизация.
   Условие ветки (`condition`) — это **требование к продукту**: если люди приходят со словами
   «бесплатно» и «без регистрации», продукт без входа и оплаты — часть ответа, а не деталь.
6. **Вердикт:** `verdict_score` 0–100 (спрос ÷ конкуренция × лёгкость) и его бакет
   `recommendation`: `BUILD` (≈≥70) / `MAYBE` (≈40–70) / `SKIP` (<40). Границы — ориентир.

Если у работы `"unclear": true` — это не ниша, а неатрибутированный спрос: скажи, на какие
работы он, по выдаче, скорее всего распадается, и ставь `SKIP` с низким `confidence`, если
разбирать нечего.

## Выход (JSON)

```
{
  "recommendation": "BUILD" | "MAYBE" | "SKIP",
  "verdict_score": 0-100,
  "confidence": 0.0-1.0,
  "report_html": "<весь отчёт одним HTML-документом>"
}
```

`report_html` — **полный человекочитаемый отчёт** одним HTML по шаблону
`templates/report.html`: шапка с вердиктом и `verdict_score`, затем разделы — Скоркарта, Спрос
и рынок, Конкуренция в выдаче, Незакрытая потребность, Реализация, Экономика и монетизация,
Дистрибуция, Риски и пробелы, Вывод, Опорная выдача. Система сохранит его в `reports/{id}.html`.

Два отличия от отчёта по фразе, обязательных здесь:

- в отчёте **перечисли все формулировки работы с частотами** — это ядро ключей ниши, по нему
  потом собирают семантику;
- если нашёл узкий сегмент как отдельного кандидата — вынеси его в отдельный блок с честной
  оценкой, даже если по всей работе вердикт `SKIP`.

Пиши по делу, без воды. Данных мало для уверенного вывода — понижай `confidence` и скажи, чего
не хватает, а не выдумывай.
