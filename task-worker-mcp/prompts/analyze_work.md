# analyze_work — можно ли перехватить трафик этого ПРОДУКТА (Opus 1M, xhigh)

Разбираешь **группу дерева продуктов** — один вход, один движок, — а не фразу и не отдельную
работу. В группе может быть одна работа, может быть десяток: их потребности разные, но закрывает
их один продукт, и трафик у них общий. Все формулировки всех работ группы перед тобой.
Отчёт по нише — один, на продукт.

Думай глубоко и трезво: шаг дорогой, его запускают вручную по конкретной работе.

## Вход

```
{ "condition": "рамка ветки: бесплатно · без регистрации · на русском" | null,
  "root": "узел дерева запросов, по которому собрана ветка", "root_freq": 1069301,
  "group": { "id": "micro-3", "level": "micro|medium|macro", "name": "имя продукта",
             "input": "что человек подаёт", "engine": "чем считаем", "output": "что отдаём",
             "money": "за что берём деньги", "pool": 204741, "pool_why": "арифметика пула",
             "core": "что пишем первым", "order": ["что прирастает"], "why": "почему один продукт" },
  "works": [ { "name": "...", "top_freq": 11081, "phrase_count": 15, "unclear": false,
               "score": 0-100 | null, "intent": "product|mixed|information|..." | null,
               "product": "...", "blocker": "...", "why": "...",
               "sections": [ { "name": "...", "kind": "section|segment", "phrase_count": 4 } ] } ],
  "phrases": [ { "phrase": "...", "freq": 11081 }, ... ],   // ВСЕ формулировки работы
  "head": [ { "phrase": "матрица судьбы рассчитать", "freq": 204741,
              "covers": 90, "covers_top_freq": 23677 } ],   // контейнеры над работой
  "serps": { "фраза": { "yandex": [ {"rank","url","title","snippet"}, ... ],
                        "google": [ ... ] } },              // топ-10 по самым частотным
  "context": {                                              // что уже посчитали по этой работе
    "season": { "stats": {"amplitude","peak_months","trough_months","yoy","last","points"},
                "seasonal": true|false, "phase": "пик|спад|дно|рост",
                "phrase": "фраза, по которой снят ряд", "comment": "..." } | null,
    "adjacent": { "keys": {"фраза": частота}, "total_freq": 196196, "ours": 2385,
                  "covered": 80, "comment": "..." } | null,
    "dumps": [ {"work","dir","queries","pages","ok","report_link"} ],   // скачанные страницы
    "previous_verdicts": [ {"verdict","verdict_score","created_at"} ] } }
```

`score`, `intent`, `product` и `blocker` — гипотеза отдельного анализа физической возможности
продукта без конкурентов. Выдача у тебя уже есть; не принимай эту гипотезу за факт.

**`context.dumps` — скачанные страницы топа, читай их с диска.** Каждая запись это
`{work, dir, queries, pages, ok, report_link}`, где `dir` — каталог вида
`reports/<работа>/` с подкаталогами `yandex/` и `google/`, а внутри — HTML страниц топ-10
целиком. В промпт они не влезают и намеренно не вложены: открывай нужные файлы сам.

Это единственный способ проверить деньги. Сниппет обещает «полную расшифровку бесплатно», а на
странице стоит форма регистрации, лимит или пейволл на 490 ₽ — и увидеть это можно только в
самой странице. Если `dumps` пуст, так и скажи: цены и барьеры взяты из сниппетов, а не
проверены.

### `context` — обязателен к учёту

Ветка дерева выросла из одного слова, поэтому сама по себе меряет спрос узко и в один момент
времени. `context` — это поправки к ней, и молчать о них нельзя:

- **`season` есть** → `top_freq` снят в конкретном месяце. Если `phase` — «дно», спрос занижен,
  и вердикт по текущему числу будет неверным: считай по среднему за год (`stats`), а сезон
  разбери отдельно — когда выходить, сколько длится окно. **`season` = null** → так и скажи:
  спрос без поправки на месяц, и это ограничение вывода.
- **`adjacent` есть** → настоящий размер ниши — `total_freq`, а не `ours`; наша ветка это
  `ours/total_freq` от него. Но проверь по формулировкам, какая часть смежного спроса ищет
  **готовый результат**, а не инструмент: адресуемая доля обычно сильно меньше суммы.
  **`adjacent` = null** → измерен спрос только со словом-технологией, ниша может быть кратно
  больше; скажи это прямо.
- **`previous_verdicts` не пуст** → это повторный разбор по новым данным. Скажи, что изменилось
  по сравнению с прошлым вердиктом и почему число другое (или почему то же самое).

## Как считать спрос

- **Частоты не складывай.** Частота Вордстата — широкое соответствие: число более общей фразы
  уже включает свои уточнения. Опирайся на `top_freq` как на порядок величины и отметь, сколько
  формулировок в работе.
- **Потолок работы — в `head`, а не в `phrases`.** Голову ветки классификация не разбирает, и в
  фразах работы её нет: там максимум всегда ниже порога головы. Но именно головной контейнер и
  есть рынок этой двери — «матрица судьбы рассчитать» 204 741 накрывает 90 фраз работы, чей
  собственный максимум 23 677. Назови оба числа: контейнер как потолок, `top_freq` как якорь.
- `freq` **завышена в ~3–10 раз** относительно точного спроса.
- На #1 в выдаче кликают ~30%. Реальный захватываемый трафик = реальный спрос × ~0.3.
- Рынок — **Россия, рубли**. Монетизация: реклама/РСЯ, партнёрка (Ozon/WB/Я.Маркет),
  freemium/SaaS, донаты, лидоген.
- Ценность = **спрос ÷ конкуренция × лёгкость реализации**. Крошечный спрос при нулевой
  конкуренции и лёгкой сборке — валиден.

## Что оценить

1. **Занята ли работа.** По выдаче: кто её сегодня закрывает, насколько хорошо, и какой ценой
   для пользователя (регистрация, оплата, качество). Если в самой выдаче доминирует конкретный
   сервис — скажи об этом прямо; не считай гипотезу продуктового рейтинга доказательством.
2. **Есть ли незакрытая потребность** и в чём именно она: чего в выдаче нет, что люди просят
   формулировками, а получают не то.
3. **Не сидит ли внутри продукта более узкий угол**, который стоит закрыть отдельно. Смотри
   `works[].sections` и сами формулировки: узкий вход, своя аудитория, своё ограничение. Часто
   именно там весь смысл — крупная дверь занята, а её угол свободен.
4. **Реальный захватываемый спрос** (с дефляцией `freq` и поправкой на CTR).
5. **Реализация:** тип продукта (инструмент / лендинг + партнёрка / SaaS / контент), стек,
   ключевые фичи, объём работ (S/M/L плюс оценка в человеко-неделях), риски.
   Условие ветки (`condition`) — это **требование к продукту**: если люди приходят со словами
   «бесплатно» и «без регистрации», продукт без входа и оплаты — часть ответа, а не деталь.
6. **Монетизация — отдельный обязательный ответ, а не строка в списке.** Три поля, каждое
   непустое, иначе приёмник отклонит отчёт:
   - **`money`** — что продаём и **как берём деньги**: разовая покупка, подписка, снятие
     лимита, реклама и партнёрка, CPA, лидоген, B2B. С ценой или ставкой, а не «монетизация
     возможна». «Слабая и конфликтная» — это оценка, а не ответ;
   - **`who_pays`** — кто платит, в какой момент и за что платит **сегодня** тем, кто стоит в
     топе. Если в выдаче никто денег не берёт — так и напиши, это факт, а не пропуск;
   - **`why_pay`** — почему заплатят нам, а не уйдут к бесплатному. Привязано к **барьеру
     конкретного конкурента** («у X полная расшифровка только после регистрации и за 490 ₽»),
     а не к «у нас удобнее».

   **Рекомендуешь контентный актив под трафик — посчитай доход с трафика.** Вывод «сам по себе
   не монетизируется, нужен как источник трафика» без чисел не принимается: назови визиты в
   месяц и что они дают в ₽ по выбранной модели. Иначе рекомендация повисает без экономики —
   так уже вышло на живой ветке, где отчёт предложил справочник на 200 страниц и не сказал,
   чем он зарабатывает.

   **Плюс помесячная прикидка — таблицей, месяцы 1, 2, 3 и 6.** Колонки: визиты, покупки
   (или показы рекламы), ₽ за месяц, ₽ накопленным итогом. Считается от твоей же оценки
   захватываемого трафика с разгоном: органика выходит на потолок за 9–15 месяцев, поэтому
   первый месяц — доли процента от потолка, а не четверть. Это **прикидка порядка**, детальный
   прогноз с воронкой и допущениями делает третий разбор; но отчёт, который не говорит, сколько
   это денег к шестому месяцу, решение принять не помогает. Числа грубые — так и напиши, но
   назови их.
7. **Вердикт:** `verdict_score` 0–100 (спрос ÷ конкуренция × лёгкость) и его бакет
   `recommendation`: `BUILD` (≈≥70) / `MAYBE` (≈40–70) / `SKIP` (<40). Границы — ориентир.
   **Монетизация имеет право вето:** ниша, где не названо, кто и за что платит, не может
   получить `BUILD`, каким бы крупным ни был спрос.

Если все работы группы помечены `"unclear": true` — это не ниша, а неатрибутированный спрос:
скажи, на какие работы он, по выдаче, скорее всего распадается, и ставь `SKIP` с низким
`confidence`, если разбирать нечего.

## Выход (JSON)

```
{
  "money": "что продаём и как берём деньги, с ценой или ставкой",
  "who_pays": "кто платит, в какой момент и кому платит сегодня",
  "why_pay": "почему заплатят нам — барьер конкретного конкурента",
  "recommendation": "BUILD" | "MAYBE" | "SKIP",
  "verdict_score": 0-100,
  "confidence": 0.0-1.0,
  "report_html": "<весь отчёт одним HTML-документом>"
}
```

`report_html` — **только тело отчёта**: `<h2>`, `<p>`, `<table>`, `<ul>`. Ни `<html>`, ни `<head>`,
ни `<style>`, ни `<h1>` — оболочку, стили и заголовок дописывает система. Разделы: Скоркарта, Спрос
и рынок, Конкуренция в выдаче, Незакрытая потребность, Реализация, **Экономика и монетизация**
(что продаём, кому, почему купят у нас, и таблица месяцев 1/2/3/6),
Дистрибуция, Риски и пробелы, Вывод, Опорная выдача. Классы, которые уже стилизованы: `muted`,
`sm`, `num`, `verdict`, `hero`.

Раздел «Спрос и рынок» ведёшь **от поправок**: сначала измеренное число, потом что с ним
делают сезонность и смежные ключи, потом итоговая оценка. Блок «Входные данные» в конец отчёта
дописывает система — сам его не рисуй, но и не противоречь ему: если чего-то во входе не было,
вывод обязан это признавать, а не додумывать.

Два отличия от отчёта по фразе, обязательных здесь:

- в отчёте **перечисли все формулировки продукта с частотами** — это ядро ключей ниши, по нему
  потом собирают семантику. **Оберни этот перечень в `<details class="keys">`** с осмысленным
  `<summary>` вида «Ядро ключей: 372 формулировки»: список нужен целиком, но развёрнутым он
  занимает две трети отчёта и мешает читать вывод. Это же правило — для любой таблицы длиннее
  примерно пятнадцати строк;
- если нашёл узкий сегмент как отдельного кандидата — вынеси его в отдельный блок с честной
  оценкой, даже если по всей работе вердикт `SKIP`.

Пиши по делу, без воды. Данных мало для уверенного вывода — понижай `confidence` и скажи, чего
не хватает, а не выдумывай.
