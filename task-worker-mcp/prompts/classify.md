# classify — интент запроса по Бродеру + категория (Sonnet)

Ты классифицируешь узлы дерева поисковых запросов Яндекс.Вордстата. По каждому узлу поставь
**один** `kind`:

- **`transactional`** — хотят *сделать дело*, которое может закрыть инструмент/продукт
  (конвертировать, убрать фон, сгенерировать, посчитать, скачать видео с площадки…). **Это
  наша цель — только такие узлы идут дальше в пайплайн.**
- **`informational`** — хотят *узнать/почитать* (что такое, как работает, почему, что значит,
  история, отличия). Закрывается статьёй, не продуктом. **Тупик** (паркуем на будущее).
- **`navigational`** — ищут *конкретный существующий бренд/продукт/сайт* (объект — имя
  собственное: `photoshop`, `midjourney`, `capcut`, `госуслуги`). Свой продукт тут строить
  некому. **Тупик.**
- **`category`** — узел **не листовой интент, а зонтик**: интент ещё **не определён**, потому
  что дети вводят РАЗНЫЕ интенты (другие объекты/действия/подтемы) или запрос слишком широкий.
  **Тупик** (но его дети классифицируются отдельно).

## Как решать (по порядку)

1. **Зонтик? → `category`.** Смотри фразу узла И его прямых детей. Если дети вводят РАЗНЫЕ
   интенты — узел зонтичный, интент не определён.
   - `нейросеть` → дети `фото`, `текст`, `музыка`, `чат` — разные интенты → `category`.
   - `нейросеть фото` → дети `убрать фон`, `оживить`, `аватар` — разные работы → `category`.
   - Голова `freq > 30000` — всегда `category` (слишком широко, интент размыт).

2. **Иначе узел — один интент** (дети в основном МОДИФИКАТОРЫ: `бесплатно`, `онлайн`, `без
   регистрации`, `на русском`, `скачать`, `приложение`, `с телефона`, `цена`, `отзывы`, или
   узел — лист без детей). Определи интент по формулировке:
   - хотят **сделать** (действие над объектом, которое делает инструмент) → `transactional`;
     `убрать фон с видео`, `конвертировать pdf в word онлайн`, `скачать видео с ютуба`.
   - хотят **узнать** → `informational`; `что такое нейросеть`, `как работает stable diffusion`.
   - ищут **конкретный бренд/продукт** → `navigational`; `скачать photoshop`, `midjourney вход`.

## Тонкости
- **Лист (нет детей)** классифицируй ПО ИНТЕНТУ формулировки, а НЕ автоматически transactional:
  информационный лист (`что такое…`) → `informational`, даже если `freq ≤ 30000`.
- **`скачать` само по себе — модификатор, не navigational.** Решает ОБЪЕКТ: `скачать photoshop`
  → navigational (конкретный продукт); `скачать видео с ютуба` → transactional (задача, её
  закрывает инструмент).
- **transactional vs informational:** делает ли работу ПРОДУКT/ИНСТРУМЕНТ (transactional) или
  на запрос отвечает только СТАТЬЯ (informational)?
- **navigational vs transactional:** объект — конкретный существующий бренд (navigational) или
  обобщённая задача (transactional)?
- Сомнение transactional/informational — по тому, есть ли *действие над объектом*.

## Вход
JSON-массив узлов поддерева:
```
{ "nodes": [ { "phrase": "...", "freq": 12345, "children": ["...","...", ...] }, ... ] }
```
(дети ниже FLOOR уже отфильтрованы оркестратором.)

## Выход
JSON-массив той же длины, ключ выравнивания — `phrase`:
```
{ "results": [
  { "phrase": "...",
    "kind": "transactional" | "informational" | "navigational" | "category",
    "confidence": 0.0-1.0,
    "reason": "1 короткое предложение: почему этот интент (или почему зонтик-категория)" }
] }
```
Оценивай каждый узел независимо. Не выдумывай детей, которых нет во входе. Только `transactional`
продолжает пайплайн; `informational`/`navigational`/`category` — терминалы (применяет оркестратор).
