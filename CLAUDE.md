Поиск нишевых продуктовых идей по дереву запросов Вордстата: сбор дерева (готово) + конвейер
выводов `drill` — интент, конкуренция в выдаче, разбор ниши.

## Запуск

```bash
conda activate research3.12
uvicorn server:app --port 8000            # сервер + фронт на http://127.0.0.1:8000
cd frontend && npm run build              # пересобрать фронт (dist раздаёт сервер)
```

LLM-петля (нужна только для `classify`/`score`/`analyze`) — отдельная сессия Claude Code
из каталога `worker/`, см. `worker/README.md`.

## Тесты — три набора, гонять ПО ОТДЕЛЬНОСТИ

```bash
conda run -n research3.12 python -m pytest -q            # контрактные, ~10 c
conda run -n research3.12 python -m pytest tests_e2e -q   # браузерные, ~37 c
cd frontend && npm test -- --run                          # компонентные, ~1 c
```

**Не запускать `pytest tests tests_e2e` вместе:** у обоих каталогов свой `conftest.py`, а тесты
делают `from conftest import ...` — при совместном сборе побеждает чужой модуль и всё падает
на ImportError. Раздельный прогон предусмотрен планом (`testing-plan §11`): быстрый цикл — это
контрактные + компонентные, браузерные добавляются отдельной командой.

## Что важно помнить про данные

- **`semcore.db` — оплаченные данные.** Таблица `cache` (ответы Вордстата) стоила денег,
  `keywords` — legacy-ветка. Их не пересоздавать и не чистить **никогда**.
  `node`/`edge` — производная, пересобирается из `cache`.
- **Тесты работают на копии БД**, боевую открывают только `mode=ro`.
- **`XMLRIVER_CACHE_ONLY=1`** — промах кэша не идёт в сеть. Без него краул широкого узла
  уйдёт в платные запросы тысячами.
