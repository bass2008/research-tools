# research-tools

Поиск нишевых продуктовых идей по дереву запросов Вордстата. **Два слоя:**

- **дерево запросов** (факты) — фразы, частоты, выдача; собирается краулом;
- **дерево потребностей** (толкование) — **работы**, которые люди хотят сделать, собранные из фраз
  ветки; по работе делается разбор с отчётом.

Единица вывода — **работа, а не фраза**: одну работу выражают десятки формулировок.

**Три разбора одной работы, воронкой от рынка к продукту** (`design §4.4–4.6`), каждый со своим
вопросом и своим отчётом; они не заменяют друг друга, и расхождение их оценок — сигнал:

| # | Команда | Вопрос | Единица ответа |
|---|---|---|---|
| 1 | «Ниша» (`analyze`) | можно ли перехватить поисковый трафик | работа, `спрос ÷ конкуренция` |
| 2 | «Функции» (`analyze_adv`) | какие функции внутри и за что платят | функция «вход → выход» |
| 3 | «Продукт» (`product`) | что строим, кому, почём, почему и сколько купят | спецификация + прогноз 1/2/3/6 мес |

## Запуск

```bash
./run.sh                                  # сервер + фронт на http://127.0.0.1:8000
cd frontend && npm run build              # пересобрать фронт (dist раздаёт сервер)
```

LLM-петля (нужна для всех операций второго слоя: `needs_build`, три разбора, `needs_season`,
`needs_adjacent`, `stopwords_scan`) — отдельная сессия Claude Code из каталога
`worker/`, см. `worker/README.md`. Без неё эти операции падают по таймауту, а индикатор показывает
«LLM: офлайн».

Лаборатория промптов (прогон сборки на реальных данных без конвейера):

```bash
taskworker needs-job '<фраза>' --max-freq 30000   # собрать вход и завести локальный джоб
taskworker needs-show <job_id>                     # вход, ответ, полнота покрытия
taskworker needs-diff <job_id> --ref needs-neyroset-free   # сверка с эталоном
taskworker needs-diff <job_id> --ref-job <job_id2>          # прогон против прогона
```

## Тесты — три набора, гонять ПО ОТДЕЛЬНОСТИ

```bash
conda run -n research3.12 python -m pytest -q             # контрактные, ~16 c
conda run -n research3.12 python -m pytest tests_e2e -q    # браузерные, ~35 c
cd frontend && npm test -- --run                           # компонентные, ~1 c
```

**Не запускать `pytest tests tests_e2e` вместе:** у обоих каталогов свой `conftest.py`, а тесты
делают `from conftest import ...` — при совместном сборе побеждает чужой модуль и всё падает на
ImportError. Раздельный прогон предусмотрен планом (`testing-plan §2`): быстрый цикл — контрактные
плюс компонентные, браузерные добавляются отдельной командой.

Браузерные гоняют **собранный** фронт: перед прогоном `npm run build`, иначе тест проверяет
предыдущую сборку (фикстура об этом предупреждает).

## Что важно помнить про данные

- **`semcore.db` — оплаченные данные.** Таблица `cache` (ответы Вордстата) стоила денег,
  `keywords` — legacy-ветка. Их не пересоздавать и не чистить **никогда**.
  `node`/`edge` — производная, пересобирается из `cache`.
- **`serp` и `history` — тоже оплачено.** Ключи «фраза + движок» и «фраза», поэтому повторный
  разбор и повторный расчёт сезонности бесплатны.
- **`stopword` — что сознательно не покупаем** (`stop` / `brand` / `unwanted`). Сравнение с
  фразой идёт по основе слова; краул такие узлы пропускает, но из дерева не удаляет.
- **`probe` — что куплено под замер, а не под дерево.** Пулы смежных корней лежат в общем `cache`;
  без пометки пересборка `node` из `cache` втянула бы их уточнения в факты (уже ловили: +9876
  узлов).
- **Новую колонку в `node` добавлять только через `ALTER TABLE`.** Признак «схема новая» — наличие
  колонки `status`; колонка, попавшая в список «новых», заставит пересобрать дерево из кэша и
  затрёт результаты работы LLM (это уже случалось).
- **Второй слой — файлы** в `logs/needs-lab/<id>/` (артефакты работ — `artifacts/<работа>/`) плюс
  отчёты в `reports/`. Он одноразовый: снести и собрать заново можно без последствий, потому что
  фактов он не трогает.
- **Тесты работают на копии БД**, боевую открывают только `mode=ro`. Копия делается через
  `Connection.backup`, а не `cp`: база в WAL, и файловая копия без `-wal` — устаревший снимок.
- **`XMLRIVER_CACHE_ONLY=1`** — промах кэша не идёт в сеть. Без него краул широкого узла уйдёт в
  платные запросы тысячами.
