# Разбор незакоммиченных изменений бэкенда перед релизом

Только чтение и прогон тестов. Никаких правок кода, git (только `status`/`diff`/`log`/`show`),
docker, серверов, выкладки.

Проект: `/home/sergey/Personal/research-tools/project/destiny-matrix`. Последний релиз — коммит
`747ac38e` (08.11.2026). С тех пор в рабочей копии накопились незакоммиченные изменения, их
собираются выпустить. Владельцу нужно знать, что именно изменилось на бэкенде и что тестировать.

## Что разобрать

Все изменения относительно `HEAD`, включая новые неотслеживаемые файлы (`git status --porcelain`):
`api/`, `web/app/api/`, `web/app/_lib/`, `web/lib/`, `web/middleware.ts`, `compose/`, `infra/`,
`spec/`. Пересобранный контент `web/content/*.json` построчно не разбирать — одной строкой: что
поменялось по смыслу (какие наборы, сколько записей).

Читать код, а не имена файлов: каждое утверждение о поведении — по diff и по месту использования
(греп по проекту). Контекст: `docs/mobile-backend.md`, `docs/mobile-plan.md`, `docs/payments.md`,
`docs/release-process.md` (§0.5 — формат «файл → кто использует → что проверить»),
`docs/decisions.md`.

## Что сдать

Файл `out/release-backend/backend-changes.md`, по-русски, коротко, таблицами:

1. **Задевает сайт уже сейчас** — группы изменений. На каждую: что изменилось по поведению (1–2
   строки), файлы, кто использует, риск для нынешних пользователей сайта, **сценарий проверки на
   тестовом контуре** (шаги человека, не «эндпоинт отвечает»), какие автотесты это покрывают и чего
   они не покрывают.
2. **Только для мобильного приложения** (не видно на сайте без настроек) — то же, плюс как
   убедиться, что на проде это выключено (Google Play, мок покупки, вход через Google).
3. **Миграции БД и деплой**: миграции, новые таблицы и поля, переменные окружения, зависимости,
   изменения compose и скриптов выкладки; что проверить на копии боевой базы.
4. **Результаты тестов**: `cd api && /home/sergey/miniconda3/envs/research3.12/bin/python -m pytest -q`
   и отдельно `cd web && npm test -- --run` — числа прошло/упало; упавшие перечислить с причиной
   (не чинить).
5. **Подозрительное**: то, что похоже на незаконченную работу, отладочный код или риск, — с
   указанием файла и строки.

Последнее сообщение — 5–10 строк: главные риски и путь к файлу.
