# FLUX.1-schnell — локальная генерация карт

Генерирует изображения на своей видеокарте, без API и оплат. Модель **FLUX.1-schnell**
выбрана из-за лицензии **Apache 2.0**: результат можно использовать коммерчески.
У FLUX.1-dev лицензия некоммерческая — для продукта она не годится.

## Запуск

```bash
./run.sh
```

Один запуск даёт **4 варианта** одной карты — по одному на каждый сид из `FLUX_SEEDS`.
Файлы: `out/<name>-v1.png … v4.png`. Превью открывается на
**http://127.0.0.1:8899/gen/** (картинки копируются туда автоматически).

## Что где настраивается

Всё в `run.sh`, переменными:

| переменная | смысл |
|---|---|
| `FLUX_NAME` | префикс файлов (`empress` → `empress-v1.png`) |
| `FLUX_PROMPT` | промпт целиком, многострочный |
| `FLUX_W` / `FLUX_H` | размер, для карты 768×1152 (пропорция 2:3) |
| `FLUX_STEPS` | шаги; schnell рассчитан на 1–4, больше не нужно |
| `FLUX_SEEDS` | список сидов через запятую — сколько сидов, столько файлов |
| `FLUX_QUANT` | `nf4` для 8 ГБ VRAM, `bf16` если VRAM 24 ГБ и больше |

`generate.py` параметры не хардкодит — только читает окружение.

## Почему nf4

На 8 ГБ VRAM модель в bf16 не влезает: один трансформер занимает около 12 ГБ.
В режиме `nf4` трансформер и текст-энкодер T5 квантуются в 4 бита (bitsandbytes),
плюс включён `enable_model_cpu_offload()` и нарезка VAE. Пик VRAM печатается в лог.

## Единый стиль для колоды

Двадцать две карты, сгенерированные независимо, получатся из разных вселенных.
Что помогает:

1. одинаковый хвост промпта — стиль, палитра, рамка, формат (он уже вынесен в конце `FLUX_PROMPT`);
2. те же сиды для всех карт — часть стилевых решений повторяется;
3. если этого мало — обучить LoRA на 10–15 отобранных вариантах и подключить её через
   `pipe.load_lora_weights()`.

## Колода на сайте

Карты лежат в `project/destiny-matrix/web/public/img/arcana/` как `gen-NN.webp` в нумерации
матрицы судьбы (1–22, Шут двадцать второй), половинная колода — в `half/` рядом. Отдельного
скрипта сборки нет: заменить карту — это ресайз одного PNG, и делается разово.

```python
from PIL import Image
img = Image.open("out/dev-guided/sun/seed-0035.png").convert("RGB")
for width, sub in ((520, ""), (260, "half")):
    out = f"{DST}/{sub}/gen-19.webp" if sub else f"{DST}/gen-19.webp"
    img.resize((width, round(img.height * width / img.width)), Image.LANCZOS) \
       .save(out, "WEBP", quality=78, method=6)
```

Параметры полной карты проверены: пересборка Дьявола и Звезды из их исходников даёт файл,
совпадающий с репозиторием **байт в байт**. Половинная колода собиралась чем-то другим — её
файлы на 20–25 % тяжелее, чем даёт `quality=78`, и точные параметры неизвестны. Пока их не
восстановили, `half/` для старых карт лучше не пересобирать.

**Чем был `deck.py` и почему его нет.** Он собирал всю колоду разом и для карты, не описанной
в `seeds.json`, молча брал сид по умолчанию — то есть прогон ради одной карты перезаписывал
остальные двадцать одну. Исходники восемнадцати карт нынешней колоды после этого уже не
находятся ни в одном сохранившемся прогоне.

Опознать удалось четыре:

| № | Карта | Исходник |
|---|---|---|
| 15 | Дьявол | `out/clothed/devil/seed-0101.png` |
| 17 | Звезда | `out/clothed/star/seed-0101.png` |
| 19 | Солнце | `out/dev-guided/sun/seed-0035.png` |
| 21 | Мир | `out/images/21-world-v10.png` |

Остальные восемнадцать — утрачены, искать их в `out/` бесполезно. Карта Мира продублирована в
`project/destiny-matrix/infra/landing/img/gen-21.webp`: при замене обновлять обе.
