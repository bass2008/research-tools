# 11. Контролируемое расширение SEO-корпуса

**Приоритет:** P2/P3  
**Релиз:** пострелизная постоянная работа; не входит в единый обязательный релиз  
**Зависимости:** [08 — корректный корпус](08-content-corpus-audit.md),
[10 — защитные gates](10-ci-release-and-monitoring.md)  
**Блокирует:** ничего аварийного; это рост после ремонта  
**Оплата:** работает непрерывно  
**Риск до → после:** низкий; снижается вероятность снова создать тысячи малополезных страниц

## Цель

Расти за счёт подтверждённого спроса и продуктовой пользы, не превращая 22³ возможных троек в
10648 однотипных статей. Разделить полный продуктовый словарь и индексируемый SEO-корпус.

## Сколько страниц действительно нужно

| Сущность | Возможный объём | Решение |
|---|---:|---|
| Упорядоченные хвосты | 26 | продукт покрывает все; SEO — только спрос/уникальный интент |
| Неупорядоченные формы хвостов | 24 | не самостоятельная сущность и не URL-модель |
| Произвольные тройки | 10648 | не создавать плоский SEO-корпус |
| Позиционные occurrences | много | генерировать в отчёте; отдельная статья только по спрос-гейту |
| Арканы | 22 | поддерживать и улучшать по данным |
| Позиции | 37 | индексировать при спросе и полноценном ответе |
| Пары | 231 | ревью/объединение по качеству и спросу |
| Матрицы по датам | 5544 текущих типов | продукт, `noindex, follow`, вне sitemap |

Комбинаторный объём — задача движка интерпретаций, а не редакционного плана из 10 тысяч URL.

## Приоритет новой очереди

### P2-A. Закрыть продуктовые пробелы

- Все 26 хвостов имеют полезный текст в разборе независимо от SEO-частотности.
- Для повторяющихся программ создать общее смысловое ядро плюс позиционные модификаторы.
- Усилить 20 платных разделов там, где пользователь получает слишком короткий ответ.
- Не индексировать внутреннюю комбинацию только потому, что для неё появился текст.

### P2-B. Рост существующих winners

В первую очередь улучшать существующий URL, если он уже получает показы и его интент совпадает:

- низкий CTR при хорошей позиции → title/description experiment;
- показы без кликов/расчётов → первый экран и соответствие интенту;
- расчёты без покупки → продукт/CTA, а не ещё одна SEO-статья;
- два URL делят запрос → merge/canonical strategy.

### P2-C. Новые страницы

Новая indexable-страница допускается, если одновременно:

1. запрос есть в датированном ядре или подтверждён GSC/SERP;
2. сущность существует в утверждённом методе;
3. интент не закрыт существующим URL;
4. можно написать уникальный ответ, а не переставить названия арканов;
5. назначены внутренние ссылки и CTA;
6. есть метрика успеха и срок пересмотра;
7. статья прошла два ревью и CI.

Для `3-13-10` отдельная хвостовая статья имеет более высокий кандидатный приоритет. `21-10-7` и
`6-14-8` обязательны продукту, но индексируются после данных. `9-18-9` может существовать в продукте
без SEO, пока точный порядок не показывает спрос; `9-9-18` имеет подтверждённый числовой спрос, но
интент всё равно проверяется.

## Batch-процесс

Публиковать небольшими партиями, например 5–10 URL:

1. утвердить brief и primary query;
2. написать структурированные данные;
3. предметное ревью формулы/смысла;
4. редакторское ревью уникальности и языка;
5. schema, near-dup, link и route tests;
6. test release и просмотр страниц;
7. prod release;
8. контроль после повторного обхода и решение keep/improve/noindex.

Не публиковать следующую большую партию, если предыдущая дала массовые soft-404, near-dup или не
имеет измерения.

## Контентный шаблон без doorway-страниц

Структурированный движок может собирать персональный ответ из:

- значения каждого аркана;
- значения позиции;
- взаимодействия пары/тройки;
- порядка элементов;
- контекста раздела;
- практического вывода.

Такой ответ живёт в продукте. SEO-URL появляется только поверх полноценной самостоятельной статьи.
Нельзя индексировать все комбинации одного шаблона с заменёнными числами — это doorway/near-dup
риск и плохой пользовательский опыт.

## Поддержка корпуса

- Ежеквартально пересматривать страницы без показов/кликов и каннибализацию.
- Ежегодную страницу следующего года готовить до декабря; старый URL не переиспользовать.
- При изменении метода сначала обновлять контракт, golden-набор и impact report, а затем контент.
- Хранить историю решений keep/edit/noindex.
- Перепроверять SERP для неоднозначных числовых запросов, а не только частотность.

## Чеклист партии

- [ ] Для каждого URL есть primary query и SERP evidence.
- [ ] Сущность существует в утверждённом методе, порядок подтверждён.
- [ ] Существующая страница не закрывает тот же интент.
- [ ] Ответ уникален по смыслу, не только по словам.
- [ ] Платный продукт содержит позиционную ценность без обязательного перехода в статью.
- [ ] Перелинковка и CTA осмысленны.
- [ ] Нет медицинских/финансовых/гарантирующих обещаний.
- [ ] Два ревью пройдены.
- [ ] Все CI-gates зелёные.
- [ ] Назначены критерии и дата следующего решения после повторного обхода.
- [ ] Следующая партия не стартует до ранней оценки текущей.

## Критерий завершения

Это постоянный процесс, а не одноразовый финал. Первая итерация завершена, когда выпущена и
измерена одна небольшая партия, ни одна новая страница не создана из чистой комбинаторики, а
решения о продолжении принимаются по индексации, полезности и конверсии, а не по сумме всех
перестановок чисел.
