# 07. Индексация, canonical, redirects и миграция URL

**Приоритет:** P1  
**Релиз:** единый — часть общего release candidate  
**Зависимости:** [06 — новая семантика](06-semantic-core-reclassification.md)  
**Блокирует:** статус «технически корректное SEO» и массовый контент-аудит  
**Оплата:** работает непрерывно  
**SEO-риск до → после:** средне-высокий → средний; техническая карта чиста, тексты ещё ревьюятся

## Цель

Привести индексируемый корпус к новой таксономии без массовых soft-404, цепочек редиректов,
потери существующих сигналов и каннибализации. Для каждого текущего URL должно быть осознанное
решение, а sitemap обязан содержать только канонические индексируемые страницы.

Все изменения этого плана накапливаются в общем release candidate. Отдельной prod-выкладки после
плана 07 нет: движок, контент, SEO и аналитика выпускаются вместе в плане 10.

## Инвентарь

Baseline текущего sitemap — около 410 URL:

- главная и каталог энциклопедии;
- 22 аркана, 37 позиций, 7 чакр, 231 сочетание;
- `/matrix`;
- хаб и 76 страниц хвостов;
- хаб и 23 страницы «на год»;
- концепт-хабы и служебные публичные страницы.

Отдельные 5544 `/matrix/<slug>` — продуктовый корпус под `noindex, follow`, не SEO-страницы.
Перед изменением пересчитать фактические числа автоматически, не доверять этому описанию как
вечной константе.

## Карта миграции

Создать таблицу для **каждого** существующего публичного URL:

```text
old_url | entity_type | index_now | impressions | clicks | backlinks
decision: keep | redirect | noindex | 404 | 410 | quarantine
new_url | status_code | canonical | sitemap | reason | owner | release
```

Правила:

- `keep` — тот же интент и сущность, canonical на себя;
- `301/308` — только однозначный постоянный successor того же интента;
- `noindex, follow` — полезная человеку страница без права конкурировать в выдаче;
- `404/410` — нет сущности и полезного successor;
- `quarantine` — временный `noindex`, исключение из sitemap и коммерческих CTA;
- не редиректить пачку нерелевантных страниц на хаб/главную.

## Последовательность работ

### 1. Route layer

- Ordered хвосты получают отдельные адреса.
- Настоящие alias редиректят ровно один раз.
- Неизвестные параметры отдают настоящий 404/410 с корректной оболочкой.
- Неизвестные значения динамических параметров получают штатный 404 без поштучного реестра.
- Dynamic/static params не должны блокировать предусмотренный redirect до выполнения page logic.

### 2. Metadata

Для каждого indexable URL проверить:

- уникальные title, description, H1;
- self-canonical на production origin;
- `robots=index,follow`;
- корректный BreadcrumbList и Article, FAQ только при реальном FAQ;
- отсутствие canonical на семантически другую перестановку;
- noindex на личных, платёжных, отчётных и 5544 продуктовых страницах.

### 3. Sitemap и robots

[`web/app/sitemap.ts`](../../../project/destiny-matrix/web/app/sitemap.ts) строится из реестра
публикации, а не просто из наличия JSON-объекта.

- В sitemap только `200 + index + canonical self`.
- `lastModified` отражает реальное значимое изменение, а не время каждой сборки для всех URL.
- noindex/quarantine/redirect/404 отсутствуют.
- Тестовый контур отдаёт пустой sitemap и закрыт целиком.
- Не закрывать спорную страницу в `robots.txt` до того, как бот увидит `noindex`: disallow мешает
  поисковику прочитать директиву деиндексации.

### 4. Фазовая миграция

1. Подготовить в release candidate новые canonical/ordered routes и точные redirects.
2. Удалить noindex URL из sitemap и проверить production-like build.
3. В плане 10 выполнить единственный общий релиз.
4. После prod подать новый sitemap в Вебмастер и Search Console.
5. Наблюдать crawl, coverage, soft-404 и redirect errors.
6. Только после выпадения из индекса принимать финальное решение 410 для бесполезных страниц.

## Автоматический аудит

Обходить production-like build без обращения к реальному продакшену:

- все sitemap URL отвечают 200;
- ровно один H1, последовательная иерархия заголовков;
- canonical единственный, абсолютный и ожидаемый;
- indexability соответствует registry;
- нет redirect loop/chain длиннее одного перехода;
- внутренние ссылки не ведут на redirect, 404, quarantine;
- schema JSON-LD валидно парсится;
- ordered route не меняет смысл;
- продуктовые 5544 URL не попадают в sitemap.

## Мониторинг после релиза

- ежедневно первые 14 дней: индекс, исключённые страницы, soft-404, ошибки sitemap;
- еженедельно 8 недель: клики/показы старых и новых URL, каннибализация, crawl stats;
- логировать попадания на старые URL, чтобы не убирать редирект преждевременно;
- 301 сохранять минимум год, а при внешних ссылках — бессрочно.

- [ ] Нет массового редиректа ошибочных страниц на хаб.

- [ ] Внутренние ссылки обновлены на конечные URL.

## Критерий завершения и статус SEO

План готов, когда sitemap, canonical, robots, статусы и внутренние ссылки в release candidate
однозначно отражают новую сущностную карту. На проде техническое SEO считается исправленным только
после общей выкладки плана 10. Это ещё не означает, что **все тексты** качественны — их release
candidate закрывает план 08.
