# 05. Таксономия хвостов, программ и продуктовая перелинковка

**Приоритет:** P0/P1  
**Релиз:** единый — часть общего release candidate  
**Зависимости:** [03 — горячая перегенерация](03-hot-regeneration.md)  
**Блокирует:** семантическую карту и безопасную миграцию SEO-URL единого релиза  
**Оплата:** работает непрерывно  
**Риск до → после:** средний → низкий продуктовый, высокий SEO-риск остаётся до планов 06–08

## Цель

Сделать так, чтобы продукт, энциклопедия и URL одинаково понимали сущности «кармический хвост»,
«программа», «тройка в конкретной позиции» и «произвольный числовой запрос». Убрать архитектурное
допущение, из-за которого порядок чисел теряется и одна статья выдаётся за несколько разных
последовательностей.

Полные цифры аудита и перечни находятся в
[старом плане хвостов](../article-plans/06-karmic-tails.md). Этот этап реализует только решения,
подтверждённые контрактом метода.

## Проблема в текущем коде

[`web/app/encyclopedia/karmic-tail/[triple]/page.tsx`](../../../project/destiny-matrix/web/app/encyclopedia/karmic-tail/%5Btriple%5D/page.tsx)
генерирует перестановки каждого ключа и постоянным редиректом сводит их к одному URL.
[`web/lib/encyclopedia.ts`](../../../project/destiny-matrix/web/lib/encyclopedia.ts) использует
`tailShape`, то есть неупорядоченную форму. Это корректно только если позиции взаимозаменяемы.
Для утверждаемой модели 26 хвостов они не взаимозаменяемы.

Отдельная проблема — 55 из 76 опубликованных «хвостов» не относятся к проверяемому перечню 26.
Их нельзя автоматически удалить или автоматически назвать программами.

## Целевая модель сущностей

### `KarmicTail`

- `ordered_key`, например `18-9-9`;
- три именованные позиции и их отдельный смысл;
- ссылка на правило и три именованные позиции из контракта;
- подтверждённый список допустимых последовательностей;
- SEO-статус независимо от наличия продуктового толкования.

### `Program`

- ordered numbers;
- `position_key` или перечень позиций, где программа допустима;
- общее ядро смысла и позиционный модификатор;
- не наследует автоматически title/текст хвоста.

### `Occurrence`

- ссылка на сохранённую матрицу;
- `entity_key` и `position_key`;
- ссылка из конкретного раздела отчёта на соответствующее объяснение.

Один текст может иметь общее ядро, но итоговая интерпретация должна включать контекст позиции.
Пользователь не должен сам угадывать, относится ли найденная статья к его строке отчёта.

## Работы

### 1. Реестр 26 хвостов

- Создать machine-readable список всех 26 **упорядоченных** последовательностей.
- Добавить продуктовые тексты для всех отсутствующих последовательностей, включая `21-10-7`,
  `3-13-10`, `6-14-8`, `9-18-9` и `9-9-18`.
- Развести `18-9-9`, `9-18-9`, `9-9-18`: это три записи и три смысла.
- Для SEO индексировать только страницы, прошедшие спрос-гейт; продуктовый текст может существовать
  без индексируемой отдельной статьи.
- Проверить, что исправленный расчёт способен получить каждую последовательность.

### 2. URL и canonical

- Канонический ключ хвоста равен `ordered_key`, а не отсортированному набору.
- Удалить автоматическую генерацию всех шести перестановок и редиректы между семантически разными
  порядками.
- Оставить 301 только для настоящих технических alias: другой разделитель, прежний URL той же
  сущности, однозначная опечатка.
- Не редиректить неизвестную тройку на хаб: это soft-404.
- Не менять уже индексированный URL без записи в карте миграции плана 07.

### 3. Удаление ошибочного корпуса

55 материалов, которые не относятся к достижимым ordered-хвостам метода, удаляются из исходного
корпуса. Поштучный исторический реестр URL не хранится: неизвестное значение динамического
параметра получает штатный 404 благодаря `dynamicParams = false` и `notFound()`. Универсальный
route-тест защищает это поведение без списка конкретных адресов.

### 4. Связь с разбором

- В строке «Задачи прошлых воплощений» показывать точный ordered хвост и ссылку на его объяснение.
- В других разделах ссылаться на программу с параметром/путём позиции, а не на хвост только из-за
  совпавших чисел.
- Рядом со ссылкой дать короткую позиционную интерпретацию; энциклопедия углубляет, а не заменяет
  купленный разбор.
- Для тройки вроде `2-14-5` в «Что даёт внутренний комфорт» не создавать статью «кармический хвост».
  Сначала это occurrence позиции `comfort`; отдельный SEO-URL появляется только при подтверждённом
  интенте.
- Бесплатная и платная версии должны использовать один resolver ссылок.

### 5. Контентная схема

Расширить валидацию [`web/lib/schema.ts`](../../../project/destiny-matrix/web/lib/schema.ts):

- порядок `arcana[]` обязан совпадать с `key`;
- хвост обязан входить в реестр метода;
- программа обязана содержать допустимую позицию;
- indexed-запись требует уникальных title, description, H1 и основной запрос;
- неизвестный тип не может попасть в sitemap.

## Тесты

- route test: `18-9-9`, `9-18-9`, `9-9-18` не редиректят друг в друга;
- schema test: переставленный `arcana[]` отклоняется;
- exhaustive test: ровно 26 последовательностей разрешены как product tail;
- test: все 26 достижимы контрольными датами;
- browser test: ссылка из каждого раздела отчёта ведёт к правильному типу и позиции;
- test: `2-14-5` из comfort не маркируется хвостом;
- sitemap test: quarantine и noindex отсутствуют в sitemap;
- 404/410 test: неизвестный URL не превращается в хаб или чужую статью.

## Критерий завершения

Ни один URL `/karmic-tail/*` не описывает последовательность, которую утверждённый метод не считает хвостом;
перестановки не склеиваются; каждый раздел отчёта ведёт к сущности своего типа и контекста;
неизвестная тройка получает настоящий 404. Коммерческий путь уже проверен планом 04, но создание
счетов не останавливается.
