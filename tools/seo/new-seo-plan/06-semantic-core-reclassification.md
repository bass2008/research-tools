# 06. Переразметка семантического ядра по интенту

**Приоритет:** P1  
**Релиз:** единый — часть общего release candidate  
**Зависимости:** [01 — контракт](01-methodology-contract.md),
[05 — таксономия сущностей](05-tail-taxonomy-and-product-links.md)  
**Блокирует:** корректные landing URL, sitemap-миграцию и контентную очередь  
**Оплата:** работает непрерывно  
**SEO-риск до → после:** критический/высокий → средне-высокий; карта верна, индекс ещё старый

## Цель

Повторно классифицировать все ключи ветки «матрица судьбы» по реальному пользовательскому интенту,
а не по синтаксису запроса. Получить воспроизводимую таблицу «одна фраза → один основной интент →
один landing URL или осознанное отсутствие страницы».

## Исходные факты

- Старый сборщик нашёл 603 фразы с тремя числами, 257 неупорядоченных форм и сложил 199240 показов.
- Только 23 формы и 30466 показов содержат явные слова `хвост`/`кармический`.
- 199240 нельзя называть спросом на кармические хвосты.
- Числа `97/160` описывали пересечение с ошибочным текущим движком, а не «наши/чужие школы».
- Одинаковая тройка может означать хвост, программу в другой позиции, общий разбор сочетания,
  запрос по дате или шум.

## Схема данных

Каждая исходная фраза получает поля:

```text
query
frequency
intent: calculate | meaning | position | program | tail | year | compatibility | brand | noise
context: karmic_tail | comfort | money | love | talent | health | ... | null
ordered_numbers: [a,b,c] | null
unordered_shape: [a,b,c] | null        # только аналитика, не canonical
method_entity: tail:18-6-6 | program:... | position:... | null
landing_url: /... | null
primary_or_supporting: primary | supporting | reject
confidence: automatic | serp_checked | product_verified
evidence: краткое основание/URL SERP-снимка
reviewed_at
```

Исходный запрос и частотность неизменяемы. Нормализованные поля строятся отдельно.

## Процесс

### 1. Детерминированная первичная разметка

- Явные слова `кармический хвост` дают candidate `tail`, но последовательность всё равно
  проверяется по утверждённому контракту.
- Слова позиции (`комфорт`, `отношения`, `деньги`, `визитка`, `центр`) дают candidate `position`.
- Запросы с датой, годом, совместимостью и брендом выделяются до числовых правил.
- Правило «ровно три числа → хвост» удаляется и запрещается regression-тестом.
- Порядок чисел сохраняется; сортировка допустима только для группировки аналитики.

### 2. Ручная SERP-проверка

Обязательна для:

- числовых запросов без явного класса;
- конфликтов нескольких интентов;
- всех неоднозначных числовых запросов;
- запросов, способных создать новую индексируемую страницу;
- кластеров с заметным спросом и низкой уверенностью.

Проверять текущую выдачу Яндекса и Google: тип документов, формулировки title/H1, контекст
сниппетов. Снимок датировать, потому что SERP меняется. Чужой title — доказательство интента, но не
источник истины для формулы.

### 3. Кластеризация без двойного счёта

- Одна фраза входит ровно в один основной кластер.
- Supporting queries можно привязать к той же странице, но не складывать повторно в другой раздел.
- Частотность точного порядка и сумма всех перестановок хранятся раздельно.
- Бренд, мусор и чужая методика не превращаются автоматически в нашу страницу.
- Для каждого итогового числа должна существовать команда/скрипт воспроизведения.

### 4. Назначение landing URL

- Один primary intent — один canonical URL.
- Хаб отвечает на общий вопрос, позиция — на чтение места в карте, хвост — на точный ordered хвост.
- Нет уникального ответа или подтверждённого спроса — `landing_url=null`, а не тонкая статья.
- Нельзя назначать одну страницу двум несовместимым основным интентам.
- Конфликт двух существующих URL фиксируется как cannibalization task для планов 07/08.

## Результаты

- CSV/JSON всех фраз с датой выгрузки и git commit классификатора;
- сводка по взаимоисключающим кластерам;
- список primary landing pages;
- список пробелов в продукте отдельно от SEO-пробелов;
- список каннибализации и ошибочных URL;
- генератор отчёта с контрольными суммами входа/выхода.

## Тесты качества

- сумма частотностей primary-кластеров равна сумме принятого входа без double count;
- ни у одной фразы нет двух primary intents;
- каждый `tail:*` существует в реестре 26 и сохраняет порядок;
- каждый индексируемый landing имеет хотя бы один primary query;
- случайная стратифицированная выборка проверена вторым ревьюером;
- Cohen's kappa/доля согласия ревьюеров зафиксирована; спорные строки уходят в очередь, не в
  автопубликацию;
- старые числа 199240 и 257 воспроизводятся только как сырой baseline, не как итог хвостов.

## Критерий завершения

Любая цифра спроса раскладывается до исходных запросов, у каждой фразы один проверяемый интент, а
числовой синтаксис больше не определяет предметную сущность. SEO ещё не считается исправленным:
поисковики видят старые URL до выполнения плана 07.
