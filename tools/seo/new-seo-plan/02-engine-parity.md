# 02. Исправление движка и паритет Python/TypeScript

**Приоритет:** P0  
**Релиз:** 1 — реализация корректного расчёта  
**Зависимости:** [01 — контракт методики](01-methodology-contract.md)  
**Блокирует:** горячую перегенерацию, отчёты и продуктовые ссылки  
**Оплата:** работает непрерывно  
**Риск до → после:** критический → высокий; код исправлен, контуры ещё содержат старые данные

## Цель

Реализовать утверждённый контракт один раз на уровне спецификации, синхронно применить его в двух
исполнениях и сделать расхождение Python/TypeScript технически невозможным для релиза.

Сейчас формула продублирована в
[`engine/matrix.py`](../../../project/destiny-matrix/engine/matrix.py) и
[`web/lib/matrix.ts`](../../../project/destiny-matrix/web/lib/matrix.ts). Одинаковое название
`fold` не гарантирует одинаковый смысл после следующей правки.

## Целевая архитектура

### Канонический контракт

- `spec/method.json` хранит ключи точек, зависимости и правила редукции.
- Python остаётся эталонным пакетным движком и генератором контрольных результатов.
- TypeScript нужен для мгновенного расчёта в браузере, но обязан проходить тот же набор golden
  vectors.
- Никаких «быстрых» локальных формул внутри компонентов, SEO-шаблонов или PDF.
- Сериализованная карта содержит единый набор продуктовых данных для API, экрана и печати.

Если выразить весь граф декларативно непрактично, допустимы две реализации, но одна спецификация,
одинаковые имена точек и exhaustive parity-тест — обязательны.

## Реализация

### 1. Единый тип результата

- Зафиксировать один набор стабильных машинных ключей всех точек.
- Python и TypeScript возвращают одинаковую структуру без дополнительных служебных полей.
- API, экран и печать используют этот тип, не создавая собственные сокращённые варианты.
- Источник конкретной выкладки определяется существующим git commit/release tag, а не полем в
  каждой матрице.

### 2. Полная замена формул

- Реализовать утверждённую редукцию во всех точках.
- Пересобрать граф позиций строго по документу из плана 01.
- Исправить формулу кармического хвоста и сохранить порядок элементов.
- Проверить секции, чакры, предназначения, линии рода, программы, комфорт и возрастные точки.
- Удалить или закрыть deprecated-функции, которые позволяют посчитать старым способом.

### 3. Паритет двух языков

Сделать отдельную команду проверки:

1. Python рассчитывает JSON для набора дат.
2. TypeScript рассчитывает те же даты.
3. Сравниваются каждая именованная точка, массивы и секции.
4. Diff показывает первый ключ расхождения, а не только `false`.

Проверять:

- все golden-примеры из контракта;
- все валидные даты с 1900 года до текущей даты — пространство достаточно мало для nightly/full
  прогона;
- мужской и женский варианты;
- недопустимые даты и даты будущего;
- все 26 хвостов и сохранение их порядка.

### 4. Единственные точки вызова

Поискать и устранить вычисления вне движка в:

- `web/app`, `web/components`, `web/lib`;
- генераторе [`engine/precompute.py`](../../../project/destiny-matrix/engine/precompute.py);
- API матриц и отчётов;
- страницах печати и SEO-компонентах.

Компоненты должны получать именованные значения результата, а не повторять `a + b` и `fold`.

## Тесты

### Unit/contract

- таблица граничных значений редукции;
- golden-тест каждой точки для подписанных дат;
- property: все результаты находятся в `1…22`;
- property: один вход детерминирован;
- тест порядка хвоста;
- тест `31.03.1993` с утверждённым результатом;
- тест отсутствия старой формулы в публичном API.

### Cross-runtime

- полный Python ↔ TypeScript diff всех дат;
- отдельный тест сериализации: JSON из Python читается TypeScript без потерь;
- CI падает при несовпадении хотя бы одного ключа.

### Browser

- ввод даты на главной, переход из энциклопедии и открытие сохранённой карты показывают одинаковые
  числа;
- повторный расчёт не меняет результат после hydration;
- refresh и разные viewport не влияют на данные.

## Выкатка и откат

- Сначала исправленная формула выкладывается на тестовый контур.
- Сравнить выборку старого и нового результата, приложить diff к релизу.
- Не оставлять скрытый fallback на старую формулу: откат делается возвратом всего релиза, а не
  смешением двух алгоритмов.
- До плана 03 не считать прод исправленным: там ещё могут быть старые тестовые записи и PDF.

## Критерий завершения

Для любого поддерживаемого входа Python, браузер, API и печать получают одинаковую матрицу по
утверждённому контракту. Следом без паузы выполняются перегенерация и горячий релиз плана 03;
создание счетов при этом продолжает работать.
