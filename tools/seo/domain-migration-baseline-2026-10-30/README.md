# Контрольные посадочные Release 1

Срез получен 30.10.2026, период 02.10–29.10.2026 (28 завершённых календарных дней в настройках счётчика). Источник: API Метрики, счётчик 111856670; фильтр `ym:s:lastTrafficSource=='organic' AND ym:s:lastSearchEngineRoot=='yandex'`. Без семплирования (`sampled=false`, `sample_share=1`).

Всего 1254 визита из Яндекса, 116 посадочных. Выбранные 43 страницы дают 1129 визитов — **90.03%**. Это выполненное требование покрытия ≥90%, а не топ-20 всей поисковой органики.

- `control-pages.csv`: соответствие старого/нового адресов, визиты, накопленное покрытие, ожидаемые HTTP-статусы после Release 1.
- `recrawl-old.txt` и `recrawl-new.txt`: отдельные списки для Вебмастера.
- `recrawl-priority.txt`: 85 уникальных адресов; старый и новый рядом, главная без дубля. Применять **только после production-выкладки и проверки ответов**, в пределах фактически доступной квоты интерфейса.
- `metrika-yandex-landings.json`: исходная агрегированная выгрузка, без токенов.

При недоступном API переобхода использовать интерфейс «Индексирование → Переобход страниц». Sitemap отправляется через «Файлы Sitemap», а не в поле URL страниц. Ничего из этих списков автоматически не отправлено.

`tools/seo/recrawl-extra.txt` — прежний отдельный список, не использовать его как список новых URL этого релиза. Текущий контрольный набор подготовлен отдельно, чтобы не потерять старые адреса, которым также нужен переобход.

После релиза считать поисковые визиты пары старый+новый вместе. Не интерпретировать падение только старого URL как потерю трафика. Если релиз переносится на другую дату, обновить срез непосредственно перед выкладкой. Это не закрывает целиком этап 1 плана: актуальность остальных метрик и карт следующих фаз проверяется отдельно.
