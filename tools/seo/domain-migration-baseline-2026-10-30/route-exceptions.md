# Параметризованные URL и исключения для трёх релизов

Это дополнение к `url-map-all-phases.json`, а не новая конфигурация сервера. Release 1 уже проверен; Release 2/3 здесь только спроектированы. `H` — исходный домен, `L` — язык `ru` или `en`. Статус в таблице относится к HTTP GET; POST не превращать в GET редиректом.

| Семейство | Release 1 | Release 2 | Release 3 | Индексация / проверка |
|---|---|---|---|---|
| Русская главная `.ru/` | 200 на прежнем адресе | 301 → `.com/`, там 200 RU | Старый `.ru/` сразу 301 → `.com/ru/`; `.com/` также 301 → `/ru/` | Единственная индексируемая главная RU каждой фазы |
| Английская главная `.com/` | 302 → `.com/en/`, там 200 | Английская главная остаётся `/en/`; корень теперь русская главная 200 | `/en/` без изменений | Не сохранять английский редирект из корня в Release 2 |
| `.ru/ru/` | 302 → `.ru/` | Прямой 301 → `.com/` | Прямой 301 → `.com/ru/` | Не создавать дубль главной |
| Публичные статьи и справочники `/encyclopedia/**`, `/year/**` и публичные разделы | Старый путь 301 → `H/L/path`; конечный 200 для существующей сущности | RU SEO-страницы `.ru/ru/path` и старые `.ru/path` напрямую 301 → `.com/ru/path`; EN остаются `.com/en/path` | Без изменений | Self-canonical, hreflang, sitemap по текущей фазе |
| Перевод публичной страницы на другом домене: `.ru/en/path`, `.com/ru/path` | Язык URL, переключение остаётся на H; canonical на основном SEO-домене языка | .ru-публичные копии напрямую → соответствующий `.com/L/path` | Без изменений | Не применять это правило к приватным страницам и API |
| Исторические `/na-god/:key`, транслитовые разделы, `comfort_south/:n`, `/karmic-compatibility` | По сохранённым 48 правилам → соответствующая сущность и языковой путь; возможна цепочка старого алиаса | Старые алиасы сразу на конечный `.com/L/path`, без цепочки доменов | Без изменений, кроме адреса главной | Не заменять отсутствующую сущность главной/хабом |
| `/contacts`, `/support`, `/terms`, `/privacy`, `/refund` | `H/L/path`, canonical и переводы остаются на текущем H | Публичный переезд только с сохранением корректного продавца и условий для исходных заказов | Без изменения продавца старого заказа | Отдельно сверить юридический профиль .com перед Release 2; сейчас не менять |
| `/login`, `/register`, `/forgot`, `/reset` | Старый GET 302 → `H/L/path`; query кроме `lang` сохранён; конечный 200 | Сохранить старый H для рабочих ссылок и сессий; новые .com-ссылки локализованы | То же | noindex; проверять reset token, next, hash, отсутствие циклов |
| `/account`, `/admin`, `/report`, `/matrices/:id`, `/readings/:id` | GET 302 → `H/L/path`; серверная проверка прав прежняя | Старый H обслуживает текущую сессию/заказы; никакого общего междоменного редиректа этих адресов | То же | noindex, robots; cookie между .ru/.com не переносится |
| `/pay`, `/pay/:offer`, `/pay/done`, `/pay/fail` | GET 302 → `H/L/path`; order/m/r и прочие параметры сохранены | Старые заказы обслуживаются на исходном H, профиль продавца/платежа не подменяется | То же | noindex, robots; возвраты банка и новые письма уже содержат префикс |
| `/print/report`, `/print/pair` и остальные маршруты печати | `H/L/path`; token и id сохранены; без токена доступ не открывается | Сохранить исходный H и внутренние адреса сервиса печати | То же | noindex, robots; не редиректить подписанный API/PDF запрос на другой хост |
| `/encyclopedia/chakras/:slug` (удалённый персональный разбор) | После нормализации 308 напрямую → `H/L/encyclopedia/position/chakras` | Старые ссылки из PDF должны оставаться рабочими; явное правило, не общая переадресация всех приватных маршрутов | То же | Проверено RU/EN; не считать персональную страницу существующей статьёй |
| Персональные `/encyclopedia/years/:sequence?birth=…`, другие вычисляемые статьи | Языковой путь; данные/query сохранены; некорректные входы 404 | Отдельно сохранять контекст; новые ссылки на `.com/L/…` только после проверки конкретного семейства | То же | noindex/robots согласно действующей политике; не включать в sitemap |
| `/api/**`, включая auth, tariff, report/PDF и payment sync | Без языкового префикса и без нового редиректа | Оба старых API-origin продолжают обслуживаться | То же | API не переносится правилом публичного SEO |
| POST `/api/payments/notify`, `/api/payments/notify/:provider` | Исходный путь, тело и подпись; без редиректов | Сохранить .ru и исходные connection/site_origin старых заказов | То же | Callback, возвраты, повторные уведомления не ломаются |
| `_next/static/**`, `_next/image`, `/health`, `/api/health`, `/version/current.txt`, статические файлы | Пути не локализуются | Сохранить работоспособность старого H | То же | Проверять реальные статусы; неизвестный статический файл остаётся 404 |
| `/robots.txt`, `/sitemap.xml` | Без префикса, отдельное содержимое доменов; старые и новые закрытые пути запрещены robots | Обновить по фазе; публичные редиректы доступны роботу, карта содержит только конечные 200 | То же | Не закрывать весь .ru от обхода при переносе |
| Подтверждение владения DNS / существующие verification-файлы | DNS не менялся; существующие маршруты вне языкового редиректа | Сохранить подтверждение обоих доменов; добавить .com в Вебмастер до переключения | Сохранить | Произвольный `google*.html`/`yandex_*.html` не объявляется существующим: неизвестные файлы 404 |
| Неизвестные URL и несуществующие сущности | 404; существующего 410 в этой проверке не обнаружено | Сохранить корректный 404/410, не перенаправлять всё на главную | То же | Нет soft 404 |

## Параметры и методы

- Карта JSON нормализована до пути. Одинаковый путь с разными query обслуживается одним правилом; параметры расчёта, заказа, токена и назначения входа сохраняются. Устаревший `lang` удаляется, язык задаётся префиксом.
- Fragment (`#…`) сервер не получает; переключатель языка сохраняет его в браузере.
- Нормализация пользовательского POST использует 307 и сохраняет метод/тело. API и банковские POST не попадают в правило локализации.
- Статус API/приватного URL зависит от авторизации и параметров (200/401/403/404); нельзя записывать всем им безусловный 200.
- В Release 2/3 нужно убирать цепочки старый путь → старый домен → новый путь: старый публичный адрес должен вести сразу на актуальное назначение. Эти правила сейчас не внедрялись.

Основания: `web/middleware.ts`, `web/lib/publicRouting.ts`, `web/lib/redirects.ts`, `web/lib/contentRoute.ts`, маршруты Next и API, сохранённые sitemap/посадочные, проверки Release 1 и банковские сценарии от 30.10.2026.
