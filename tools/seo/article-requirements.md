# Требования к статье энциклопедии (SEO + смысл и качество)

Спека для написания страниц `arcana-sense.ru`: арканы, позиции, сочетания, концепт-хабы
(программы, карма, хвост), матричные тройки. Годится и для человека, и для LLM.

Главный принцип: **поисковик оценивает не «чем написано», а пользу и уникальность по смыслу.**
LLM — нормальный инструмент. Штрафа «за ИИ» нет. Штраф есть за страницу, которая ничего нового
не добавляет. Поэтому качество здесь — не про красоту слога, а про то, есть ли у страницы
**свой смысл** и **закрывает ли она вопрос человека**.

---

## Часть A. Смысл и качество (главное)

### A1. Уникальность — по смыслу, а не по словам
Разные слова при одинаковом смысле — для Яндекса тот же дубль (фильтр «малополезный контент»
сравнивает смысл, а не буквы). Значит, недостаточно «переписать другими словами». Страница
обязана нести то, чего нет на соседних страницах.

**Тест перед написанием:** «Что эта страница говорит такого, чего НЕТ на страницах её частей?»
Если ответа нет — писать нечего, страницу не делаем (или закрываем в `noindex`).

### A2. Правило целого: пиши про взаимодействие, а не про сумму частей
Самая частая ошибка — «склейка»: страница сочетания/тройки = пересказ куска про аркан A + куска
про аркан B. Это дубль в новых словах: смысл уже лежит на `/arcanum/A` и `/arcanum/B`.

- **Страница аркана** — про сам аркан во всех позициях (её уникальность: все позиции вместе).
- **Страница сочетания/тройки** — про то, что происходит, **когда они стоят вместе**: усиление,
  конфликт, во что складывается, что делать. Ни одного абзаца, который можно дословно перенести
  на страницу одиночного аркана.
- **Концепт-хаб** (программы, кармический хвост) — про сам механизм: как считается, как читается,
  типовые сценарии, частые ошибки. Не список арканов.

### A3. Соответствие интенту (зачем человек пришёл)
Одна страница — один вопрос человека. Определи его точно и ответь на **него**, а не на смежный.

- «6 в матрице судьбы» — человек хочет *значение* числа 6, а не калькулятор. Отвечаем значением.
- «рассчитать матрицу онлайн» — хочет инструмент, а не статью. Такой запрос — на главную, не сюда.
- Ответ на главный вопрос — **в первом экране**, без раскачки и без «немного истории таро».

### A4. Польза = вопрос закрыт на странице
Человек не должен уходить дочитывать к конкуренту. Признаки закрытого вопроса:
- есть прямой ответ, а не «всё индивидуально, запишитесь на консультацию»;
- есть конкретика: примеры, «сильная/слабая сторона», «что с этим делать»;
- есть следующий логичный шаг (соседний аркан, своя карта) — через ссылки, а не тупик.

### A5. Тон и экспертность (тематика — эзотерика, YMYL-смежная)
- Уверенно и конкретно, но без обещаний событий и без медицины/гарантий (см. дисклеймер сайта).
- Не лить воду ради объёма: длина берётся из полноты ответа, а не наоборот (см. C).
- Живой связный текст, а не список ключей. Переспам ключами → фильтр переоптимизации
  (Баден-Баден). Ключ входит естественно.

### A6. Антипаттерны смысла (красные флаги = переписать)
- Абзац дословно применим к другой странице → это чужой смысл, убрать.
- Статья = склейка кусков про части (см. A2).
- «Вода»: общие слова про судьбу/энергии без привязки к конкретной сущности страницы.
- Ответ на вопрос человека появляется ниже середины страницы (или его нет).
- Страница сделана под запрос, которого никто не ищет (см. C1).

## Часть B. SEO на странице (on-page)

### B1. Title
- Точная формулировка запроса в естественном виде, ключ ближе к началу. Для арканов —
  вариант **«N в матрице судьбы»** (топ-формулировка без слова «аркан»), а не только «N аркан».
- До ~60–70 знаков (выдача режет длиннее). Бренд-хвост дописывает шаблон, в ручной title не тащить.
- Уникален на весь сайт.

### B2. H1
- Один на странице, отражает суть и содержит ключ. H1 «Влюблённые» без числа и «матрицы судьбы»
  — слабо; нужно, чтобы H1 бился с запросом человека.
- H1 ≠ title дословно, но об одном.

### B3. Description
- 1–2 предложения, живые, с ключом и с «крючком» (что человек получит). Влияет на кликабельность,
  не на ранг напрямую — но клик влияет на ранг.
- Уникален на каждую страницу (не шаблон с подстановкой числа).

### B4. URL / slug
- Короткий, латиница/цифры, человекочитаемый, стабильный (менять URL после индексации — терять
  позиции). Схему не плодить: тип сущности + идентификатор.

### B5. Структура
- Ответ на главный вопрос — в первом экране.
- Разбивка на H2/H3 по подвопросам (значение, в позициях, плюсы/минусы, сочетания, «что делать»,
  вопрос-ответ). Заголовки — осмысленные, с подтемами (это тоже сбор хвоста).
- Абзацы короткие, списки где уместно, таблицы для «позиция → значение».

### B6. Ключи и хвост
- Один главный интент на страницу + его синонимы/словоформы (LSI) естественно по тексту.
- Подзаголовки закрывают близкие хвосты («что значит», «в центре», «в отношениях», «плюсы и минусы»).
- Никакого повторения ключа ради плотности.

### B7. Внутренняя перелинковка (обязательна, в обе стороны)
- Тупиков быть не должно: с каждой страницы — ссылки на соседние арканы, позиции, сочетания и на
  свой расчёт. Обратные ссылки тоже (аркан ↔ позиция ↔ сочетание).
- Из статьи — заметный вход в расчёт (конвертация инфо-трафика в лид). Предпочтительно **встроенный
  мини-калькулятор** (`CalcPromo`), а не только ссылка: без входа в расчёт инфо-трафик уходит без
  действия. Он обязателен на всех инфо-шаблонах (арканы, чакры, сочетания, позиции), не только на арканах.

### B8. Разметка Schema.org
- `Article` (headline, description, inLanguage, image, mainEntityOfPage).
- `BreadcrumbList` под хлебные крошки.
- `FAQPage` — если есть блок вопрос-ответ (даёт расширенный сниппет).

### B9. Медиа
- У картинок осмысленный `alt` с сутью (не «изображение»). Латиницы на артах карт быть не должно.
- Изображения не должны ронять LCP первого экрана.

### B10. Индексация
- `canonical` на себя.
- Нет спроса или нечего сказать уникального (A1) → `noindex, follow`: страница живёт и передаёт
  ссылочный вес, но в поиск не лезет и не тянет домен вниз.

## Часть C. Когда вообще писать и сколько

### C1. Спрос-гейт (до написания)
Полноценную статью пишем только под запрос, у которого есть спрос (частота в ядре
`logs/needs-lab/матрица-судьбы-dd5dcc98/params.json`). Нет спроса → шаблон + `noindex`, время не
тратим. Особый случай — **матричные тройки**: сперва проверить, ищут ли их вообще и в какой форме
(арканы / дата / кармический хвост), и лишь совпавшие с реальным спросом достойны статьи.

### C2. Объём — по полноте ответа, не по норме
Ориентиры (нижняя граница «не тонко», не самоцель):
- Аркан / крупная позиция / концепт-хаб: полный разбор, обычно от ~3–5 тыс. знаков.
- Сочетание / тройка со спросом: столько, чтобы раскрыть именно взаимодействие, без воды.
- Меньше — только если вопрос узкий и честно закрывается коротко.

## Часть D. Формат сдачи и куда писать

### D1. Файл
Готовую статью писать в **`tools/seo/out/article-<тройка>.md`** — по одному файлу на страницу
(например `tools/seo/out/article-18-9-9.md`). Имя = идентификатор страницы из плана.

### D2. Формат файла — как в `result-article-1-1-2.md`
Готовая markdown-страница со всеми блоками, в таком порядке:
- **Шапка:** целевой URL / canonical, хлебные крошки.
- **Мета списком:** Title, H1, Description.
- `---`
- **Тело статьи:** H2/H3 по подвопросам; внутренние ссылки прямо в тексте markdown-ссылками
  `[текст](/путь)` (на арканы, позиции, соседние тройки, расчёт).
- **Вопросы и ответы** (2–4 Q&A).
- **CTA на расчёт** + блок **«Куда дальше»** (перелинковка).
- **Блок Schema.org** — ```json``` с `@graph`: `Article` + `BreadcrumbList` + `FAQPage`.

Файл самодостаточен: это готовая к вёрстке страница, а не черновик.

## Чеклист «готово к публикации»
- [ ] Есть спрос на запрос страницы (C1).
- [ ] Определён один интент, ответ на него — в первом экране (A3).
- [ ] Ни одного абзаца, переносимого дословно на другую страницу (A2, A6).
- [ ] Страница говорит то, чего нет на страницах её частей (A1).
- [ ] Title содержит точную формулировку запроса, ≤ ~70 знаков, уникален (B1).
- [ ] H1 бьётся с запросом (B2); description живой и уникальный (B3).
- [ ] Структура H2/H3 по подвопросам, таблицы/списки где нужно (B5).
- [ ] Ключ входит естественно, без переспама (A5, B6).
- [ ] Перелинковка в обе стороны, тупиков нет, есть CTA на расчёт (B7).
- [ ] Schema: Article + BreadcrumbList (+ FAQPage при Q&A) (B8).
- [ ] `alt` у картинок, canonical на себя (B9, B10).
- [ ] Нет медицины, гарантий и обещаний событий (A5).
- [ ] Записано в `tools/seo/out/article-<тройка>.md` в формате `result-article-1-1-2.md` (D1, D2).
