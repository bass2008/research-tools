# Бесплатный калькулятор матрицы на GitHub Pages: итоговый план

06.11.2026. План для обсуждения и последующей отдельной команды на реализацию.
Пример структуры — [план материальной кармы](metarial-karma-plan.md); его задачи сюда не переносятся.
Репозиторий, сайт, новые события аналитики и публикация этим документом не создаются.

## 1. Что делаем, зачем и как это работает

**Одна отдельная публичная репа `destiny-matrix-calculator` и одна русская страница
обычного бесплатного калькулятора личной матрицы на GitHub Pages.** Название рабочее;
доступность имени проверяется при реализации. Первая версия: дата рождения → полная
схема → таблица семи чакр и итоговое энергополе → краткий разбор → ссылки продолжения.

**Зачем:** проверить дополнительный вход из поиска по калькуляторным запросам, где
основной сайт слабо виден. По «матрица судьбы рассчитать» оба наших домена отсутствовали
среди 10 документов свежего замера. Конкуренция высокая; преимущество нового сайта
заранее не доказано.

**Как работает путь посетителя:**

1. В репе лежат только публичные файлы инструмента. GitHub Pages отдаёт их как обычный
   сайт по адресу `https://<аккаунт>.github.io/destiny-matrix-calculator/`.
2. Поисковик может проиндексировать страницу и показывать её по подходящим запросам.
   Для этого на ней есть доступные без ввода даты объяснение, пример и сам калькулятор.
3. Человек вводит дату. Расчёт выполняется в браузере; схема и бесплатный ответ появляются
   сразу, без регистрации и перехода на основной сайт.
4. Из результата можно открыть соответствующие подробные статьи Arcana Sense или
   основной калькулятор. Это обычные добровольные переходы по ссылкам.
5. Оцениваем, появились ли поисковые посетители и переходы в Arcana Sense с этой страницы.
   Если страница не ранжируется или посетители не переходят, канал не дал ожидаемого эффекта.

Дополнительный трафик возникает только при поисковой видимости и интересе к продолжению.
Наличие репозитория и ссылки на основной домен само по себе не обещает роста позиций.
Ссылочный эффект отдельно не измерен и в обоснование результата не закладывается.

**Основные запросы:** «матрица судьбы рассчитать» и «матрица судьбы рассчитать бесплатно».
У второго есть историческая частота 41 304, но его свежая выдача отдельно не проверена;
положение по первой фразе ему не приписывается. «Матрица судьбы с энергополем» —
дополнительная проверяемая формулировка: функция соответствует запросу, его частота
в кэше не установлена. Все три относятся к одной странице.

Хвост и денежная линия входят в результат общей матрицы. Отдельные инструменты и
страницы под эти темы в первую версию не входят. Наличие спроса на объяснение хвоста
не является доказательством спроса на отдельный калькулятор хвоста.

У [страницы из скриншота](https://olmeksky.github.io/matrix_fate2/matr.html) действительно
задан `<title>Заголовок страницы семантической верстки</title>`. Это объясняет заголовок,
но не её позицию. Наш эксперимент проверит конкретную страницу и канал; он не отделит
влияние домена GitHub от содержимого, интерфейса и истории сайта.

### Что уже приносит посетителей основному сайту

За 09.10–05.11 из Яндекса: энергополе — **216 визитов**, визитка — **111**,
годовой раздел — **613** на 22 нормализованных посадочных. Старые URL и новые `/ru/…`

У хаба личных хвостов — **31 визит**, у конкретных личных хвостов — ещё **46**.
Поэтому риск перетягивания существующей аудитории хвостов не нулевой. Общий калькулятор
показывает тройку по дате; числовые запросы к готовым статьям остаются на основном сайте.

У калькулятора `/compatibility` в полной выгрузке входов нет строк; это наблюдение
данного периода и фильтра, а не доказательство отсутствия функции. При этом статьи
про совместимость получили **54 визита**: 41 у аркана 15 и 13 у хвоста пары 9–6–15.
У денежного хаба и предназначения строк входов нет, но три числовые страницы денег
в сумме дали **5 визитов**. Нельзя объявлять весь раздел слабым только по его общей странице.

## 4. Состав первой версии

Рабочий title: **«Матрица судьбы — бесплатный расчёт с чакрами и энергополем»**.
H1: **«Рассчитать матрицу судьбы по дате рождения»**. Одна русская индексируемая страница.
Перед формой честно обозначить объём: полная схема и краткие бесплатные пояснения.

| Элемент | Что получает человек |
|---|---|
| Форма | Ввод даты рождения, проверка существования даты, кнопка расчёта |
| Полная личная матрица | Обычная схема с числами, линиями и понятными подписями по текущему методу Arcana Sense |
| Чакры и энергополе | Семь строк «физика / энергия / эмоции» и итоговая тройка энергополя под таблицей. Энергополе не изображается отдельной точкой звезды |
| Краткий разбор | Объяснение центра E и портрета личности A именно для полученных арканов; роль позиции и короткий содержательный текст |
| Хвост и линии | Полученная тройка M–N–D, денежная линия L–R2–R и линия отношений M–R1–R с подписями |
| Продолжение | Ссылка из хвоста на статью своей тройки, из энергополя на его объяснение, из основных показателей на подходящие статьи; отдельная ссылка на основной расчёт |

Бесплатный ответ целиком доступен без покупки, регистрации, email или обязательного перехода.
Заявленный краткий разбор не заменяется общим текстом «узнайте больше на нашем сайте».
При этом полный разбор всех сфер бесплатно не обещается.

До расчёта видны объяснение метода, пример готовой матрицы, состав бесплатного результата
и короткие ответы о вводе даты и расположении энергополя. Полные статьи и числовые
посадочные остаются в энциклопедии основного сайта.

Расчёт берётся из [действующего движка](../../project/destiny-matrix/web/lib/matrix.ts).
На основном сайте уже работают полная матрица, чакры, краткий ответ и каталог хвостов.
Этот проект даёт им отдельный публичный вход; наличие нового домена не доказывает,
что он эффективнее улучшения основного сайта.

Для центра и визитки нужны короткие тексты для всех достижимых результатов соответствующей
позиции. Использовать выбранные публичные пояснения и проверить их в контексте позиции;
не выгружать платный корпус. Отдельные 26 новых толкований хвоста первой версии не нужны:
она показывает числа и ведёт к существующей статье своей тройки.

Ориентир активной работы — **4–6 рабочих дней** при переиспользовании проверенного расчёта
и выбранных публичных материалов. Это оценка, без ожидания индексации и изменений основного сервиса.

## 5. Границы первой версии и дальнейшее развитие

Первый выпуск ограничен одной личной матрицей по одной дате. Совместимость, прогноз
года и месяца, детский разбор и новые методы расчёта в него не входят. На GitHub не
создаётся каталог статей или сеть репозиториев под близкие формулировки.

Хвост, деньги, отношения и энергополе представлены внутри результата общей матрицы.
Это не отдельные страницы, конкурирующие с энциклопедией. Запросы «что означает»,
«расшифровка тройки» и конкретные числовые сочетания сохраняются за основными статьями.

Совместимость — возможное расширение после проверки первой версии: две даты, схема пары
и несколько содержательных бесплатных пояснений. Историческая частота запроса расчёта —
11 573, но выдача конкурентная. Предварительный объём такого отдельного расширения —
5–8 рабочих дней; решение зависит от результата первого инструмента.

Годовой раздел уже даёт трафик; учитывается [отдельный план месяца](month-arcana-plan.md).
Материальная карма рассматривается в [своём плане](metarial-karma-plan.md), её будущий URL
при проверке возвращал 404 и не годится как готовое продолжение. Произвольные денежные
коды, ХВД и чакроанализ другой школы не добавляются под похожие поисковые слова.

## 6. Отдельная репа и публикация

Предлагается **новый репозиторий с чистой историей**, содержащий только публичный инструмент:
минимальный расчёт, представление результата, выбранные бесплатные пояснения и документацию.
Основной репозиторий не становится исходником опубликованного сайта и не указывается в его ссылках.

Формулы выделяются из действующего расчёта, а не переписываются по конкурирующим страницам.
Текущий `matrix.ts` связан со словарями приложения: копирование одного файла без разбора
зависимостей недостаточно. Выделение ограничить новым инструментом; архитектуру основного
проекта ради этого не перестраивать.

Расчёт работает в браузере. В публичную репу не попадают API, платежи, админка, серверные
настройки, пользовательские данные, секреты и история основного проекта. Дата не передаётся
в ссылку на Arcana Sense. Изображения и тексты публикуются только из выбранного разрешённого
набора, без автоматического экспорта всего контента.

Связь «инструмент → Arcana Sense» будет публичной намеренно. Это не обещание анонимности
владельца: по общему аккаунту или другим публичным признакам можно найти другие репозитории.
Отдельная репа решает задачу ограничения опубликованного кода и прямой ссылки на основную реализацию.

Минимальные требования к поисковому представлению:

- собственные title и description с честным объёмом бесплатного ответа;
- объяснение и пример в исходном HTML; для понимания страницы не требуется отправлять форму;
- один основной адрес инструмента и canonical на него;
- отсутствие индексируемых URL с персональными датами и копий страницы под синонимы;
- обычные доступные ссылки на конкретные материалы основного сайта;
- самостоятельный текст и сценарий; полные статьи остаются в энциклопедии Arcana Sense.

Canonical внешнего самостоятельного инструмента **не направляется на Arcana Sense**:
такое указание описывало бы другую страницу как основную копию. Ссылка на основной сайт
и canonical решают разные задачи.

GitHub Pages рассматривается как площадка эксперимента, без обещания особого поискового веса.
Его [условия](https://docs.github.com/en/site-policy/github-terms/github-terms-for-additional-products-and-features#pages)
ограничивают сайты, основная задача которых — содействие коммерческим сделкам или коммерческий SaaS.
Самостоятельный бесплатный инструмент с дополнительной ссылкой представляется обоснованным
форматом; это оценка, а не одобрение GitHub. Наличие оплаты только на другом домене само по
себе не даёт исключения. При необходимости инструмент можно разместить на другом статическом
хостинге; утверждать одинаковый SEO-эффект площадок нельзя.

## 7. Ссылки на .ru и .com во время переезда

**Две одинаковые ссылки на русскую страницу обоих доменов не нужны.** У каждого действия
один целевой адрес, соответствующий текущему основному адресу и языку материала.

Живая проверка 06.11 установила:

- `https://arcana-sense.ru/ru/compatibility` отдаёт 200 и canonical на себя;
- `https://arcana-sense.com/ru/compatibility` отдаёт 200, но canonical указывает на `.ru/ru/compatibility`;
- для статьи денег действует та же схема;
- `https://arcana-sense.com/` сейчас перенаправляет на английскую `/en/`;
- `.com/en/compatibility` имеет собственный английский canonical.

Поэтому доступность русского зеркала на `.com` ещё не означает, что его нужно использовать
как основной адрес. Источник: [проверка HTTP и canonical](../../project/destiny-matrix/reports/github-calculator-plan-2026-11-06/evidence/live-routes.json)
и действующий [план переезда](domain-migration.md).

| Этап на момент публикации инструмента | Ссылка на русскую статью хвоста | Ссылка на объяснение энергополя | Ссылка на русскую главную |
|---|---|---|---|
| Сейчас, Release 1 | `https://arcana-sense.ru/ru/encyclopedia/karmic-tail/{тройка}` | `https://arcana-sense.ru/ru/encyclopedia/chakra/energy-field` | `https://arcana-sense.ru/` |
| После Release 2 и проверки новых основных адресов | `https://arcana-sense.com/ru/encyclopedia/karmic-tail/{тройка}` | `https://arcana-sense.com/ru/encyclopedia/chakra/energy-field` | `https://arcana-sense.com/` |
| После Release 3 | Тот же `.com/ru/…` | Тот же `.com/ru/encyclopedia/chakra/energy-field` | `https://arcana-sense.com/ru/` |

`{тройка}` — фактически полученная последовательность из существующего реестра, а не
произвольные три числа. Если эксперимент будет опубликован уже после переноса, сразу
ставить новый адрес; создавать промежуточные ссылки на `.ru` не требуется.

Когда переключение выполнено, **заменить ссылки**, а не удалить продолжение разбора:
в интерфейсе, описании репозитория и README. Адреса продолжения хранить в одном небольшом
списке новой репы. Перед заменой проверить конечный 200, язык, соответствующий материал и
canonical; нового механизма редиректов на основном сайте этот эксперимент не требует.

Старый `.ru` сохраняется с HTTPS и редиректами согласно уже принятому плану. Сохранённые
закладки и чужие ссылки продолжат вести на соответствующие новые страницы. Яндекс описывает
учёт внешних ссылок старого сайта после признания нового главным; Google рекомендует
обновлять внешние ссылки после переезда и сохранять редиректы длительно, обычно не менее года.
[Яндекс](https://yandex.ru/support/webmaster/ru/yandex-indexing/moving-site),
[Google](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes).

Оба домена можно показывать одновременно, **если ссылки ведут на разные языковые версии**
и так подписаны. Например, русский материал на `.ru/ru/…` и English на `.com/en/…`.
Для первого русского пилота английская версия не обязательна; её спрос здесь не исследован.

## 8. Проверка эффекта и ограничения прогноза

Для старта нужны один инструмент, неизменяемый список целевых запросов и сохранённый срез
основных страниц. Свежая выдача этого исследования — исходная точка, а не постоянный мониторинг.

После отдельного решения о публикации смотреть:

1. Появилась ли внешняя страница в поиске и по каким запросам получает показы и клики.
2. Сколько посетителей приходит с неё в Arcana Sense по уже доступным отчётам источников.
3. Как меняются основные страницы того же кластера: рост внешней страницы может частично
   заменять собственные входы, а не добавлять их.
4. Были ли переезд домена, заметные изменения содержимого или сезонности в сравниваемом периоде.

Новые события, счётчики, UTM-схема, dashboard и настройка атрибуции этим планом не внедряются.
Если существующих данных не хватит для оценки переходов, недостающий замер согласуется
отдельно. Покупки учитываются только при надёжной связи с источником, без предположений.

Первую оценку можно делать после появления индексации; для решения о дальнейшем развитии
предлагаются два последовательных сопоставимых 28-дневных окна. Это организационный ориентир,
а не обещание, что поисковику хватит месяца. При малом числе показов вывод остаётся неопределённым.

Формула сценария для одного и того же 28-дневного периода:

`дополнительные переходы в основной сайт = D × V × CTR × R − C`, где:

- `D` — поисковый спрос на выбранный непересекающийся набор запросов;
- `V` — доля этого спроса, при которой инструмент показывается;
- `CTR` — доля кликов по инструменту среди его показов;
- `R` — доля его поисковых посетителей, переходящих в основной сайт;
- `C` — переходы в основной сайт, которые эксперимент вытеснил.

Актуальные `D`, `V`, `CTR`, `R` и `C` для нового инструмента пока неизвестны. Для понимания
масштаба — **условный расчёт на каждые 1 000 запросов за 28 дней**, не прогноз выбранной темы:

| Сценарий | V | CTR | R | Поисковые визиты в инструмент | Переходы в основной сайт до вычета C |
|---|---:|---:|---:|---:|---:|
| Не вошёл в выдачу | 0% | — | — | 0 | 0 |
| Ограниченная видимость | 20% | 5% | 10% | 10 | 1 |
| Заметная видимость | 50% | 10% | 20% | 50 | 10 |
| Сильный результат | 80% | 20% | 25% | 160 | 40 |

У общей матрицы историческая частота велика, но неизвестно, какую долю сможет получить
новая страница. 204 741 и 41 304 пересекаются: их нельзя складывать или подставлять
в формулу как гарантированную аудиторию. Сценарии выше показывают механику переходов,
а не прогноз посещаемости первого запуска.

Отрицательный чистый результат возможен, если `C` больше полученных переходов. Нулевой
результат возможен при отсутствии индексации, низкой позиции или отсутствии интереса к продолжению.
Рост во время доменного переезда сам по себе не докажет эффект эксперимента.

## 9. Последовательность реализации и критерии готовности

| Шаг | Конкретный результат | Ориентир |
|---|---|---:|
| Подготовить отдельный проект | Чистая репа `destiny-matrix-calculator`, только нужные публичные файлы, выбранный способ публикации Pages | ½ дня |
| Перенести расчёт | Схема, семь чакр и итоговое энергополе совпадают с действующим движком на контрольных датах | ½–1 день |
| Собрать страницу и краткий разбор | Ввод даты, читаемый результат на телефоне, объяснения центра и визитки, пример и ссылки продолжения | 2–3 дня |
| Проверить публикационный комплект | Точность расчёта, состав публичных файлов, ссылки, title, description, canonical, доступный исходный HTML | ½–1 день |
| Опубликовать после команды на реализацию и запуск | Рабочая страница на `github.io`, README с примером и ссылками на инструмент и Arcana Sense | До ½ дня |
| Оценить результат | Индексация, поисковая видимость и переходы в основной сайт; решение о продолжении | По двум сопоставимым 28-дневным окнам после индексации |

Планирование завершено; выбор между калькулятором хвоста и обычной матрицей больше
не является открытым пунктом. Предлагаемый первый выпуск — **обычная личная матрица**.
Текущая задача создаёт план; реализация и публикация в неё не входят.

Перед публикацией проверить:

- точки, линии, семь чакр и итоговая тройка совпадают с текущим движком;
- для всех допустимых результатов центра и визитки показаны подходящие короткие пояснения;
- порядок хвоста M–N–D сохранён, ссылка открывает статью именно этой тройки;
- пример доступен до ввода даты, новая дата обновляет все части результата;
- схема и таблица читаются на телефоне, ошибки даты объясняются понятно;
- бесплатный объём соответствует обещанию, полный результат схемы не скрыт переходом;
- ссылки ведут на соответствующие материалы текущего основного домена и языка;
- в файлах и истории репы нет основной серверной реализации, секретов и лишних корпусов;
- страница полезна посетителю, который не перейдёт в Arcana Sense.

Если инструмент проиндексирован, но не получает значимых показов или переходов,
сначала оценить его результат и затраты. Создание новых репозиториев не является
автоматическим следующим шагом.
