# Архитектурные рекомендации

| Архитектурная проблема | Какие дефекты породила | Остаточный риск | Рекомендация |
|---|---|---|---|
| Матрица определяется то по `sessionStorage`, то по `?m=`, то по первой записи кабинета | №7, 11, 13; частично №8 | Высокий | Сделать сохранённую матрицу всегда адресуемой по обязательному ID. Запретить неявный выбор «первой» матрицы для оплаты и открытия отчёта |
| Доступ представлен несколькими признаками: `paid`, `unlimited`, `row.access`, `unlocked`, `scopes` | №10, 13, 18, 19 | Высокий | Ввести единую модель доступа к конкретной матрице и централизованно вычислять CTA, цену и текст |
| Загрузка, ошибка и пустой список кодируются через `null` и `[]` | №20; потенциально новые ошибки оплаты | Средний | Использовать явное состояние `loading / ready / empty / error`, не превращать сетевую ошибку в пустой список |
| Форматирование одной сущности разбросано между списком, кнопкой и чеком | №8, частично №17 | Средний | Использовать один форматтер названия матрицы и одну структуру метаданных поля |
| Один и тот же контент выбирается разными ветками | №16 | Средний | Оставить единственный resolver текста позиции; убрать специальную ветку `chakras` из сборщика отчёта |
| Админская сводка собирается несколькими независимыми запросами | №14 | Высокий | Возвращать пользователей, платежи и итоговые суммы одним `/admin/overview` и одной транзакцией |
| У задания печати нет аренды или срока действия состояния `running` | №15 | Средний | Хранить `lease_until` и периодически завершать просроченные задачи, а не только чинить их при чтении |
| Каркас страницы и размеры липкой шапки дублируются | Вёрстка №3–5 | Средний | Создать общий `SiteChrome`/`ReportShell`; высоту шапки передавать через одну CSS-переменную или измерять |
| Локальные ошибки без серьёзной архитектурной причины | Вёрстка №6, баги №9, 12, 17, SEO | Низкий | Достаточно сделанных локальных исправлений и регрессионных тестов |
