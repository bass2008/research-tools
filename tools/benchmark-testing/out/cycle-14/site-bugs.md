# Цикл 14 · Реальные баги сайта

Цикл 14 · 2026-09-02 · ступень 1 (локальный стенд, мок-оплата) · пользовательский режим · **только поиск, без исправлений**.

**Preflight по §3 пройден до запуска агентов.** Стенд собран из текущих исходников (образ
`arcana/web:dev` 19:33, Next 16.3.4), провайдер оплаты — `mock`. В чистом браузерном контексте
главная гидратируется (поле даты принимает ввод), неуспешных `/_next/static/*` нет, аварийного
экрана нет, `/api/health` → `{ok: true, db: true}`. Полный gate на этом же состоянии — зелёный:
279 браузерных сценариев, 364 юнита, 6 065 проверок корпуса, `npm audit` 0.

**Состав прогона:** 12 маршрутов поиска волнами по пять агентов, затем три независимых
опровергателя. Заявлено 15 находок, опровергатели подтвердили 14, одну признали ожидаемым
поведением. Каждую находку из числа значимых я перепроверил своим прогоном — ниже в отчётах числа
мои, а не пересказ агента.

**Приоритет** ставится по одному правилу: высокий — деньги, потерянный доступ, тупик для
посетителя или неверные данные на оплаченной странице; средний — видно на обычном пути, но
результат человек получает; низкий — редкий путь или экран только для администратора.

Security в этом цикле не рассматривается вообще — это отдельный режим и отдельный отчёт.

## Подтверждённые дефекты

### 1. Одна дата рождения продаётся дважды — переключатель пола делает второй товар за 250 ₽

**Приоритет: высокий.**

| | |
|---|---|
| Что видит человек | Купил разбор 17 октября 1987 с телефона. Вечером открыл ноутбук, посчитал ту же дату, нажал «Купить» — экран оплаты ничем не отличается от первого раза, кнопка «Оплатить 250 ₽ · 17 октября 1987», ни слова о поле. Платёж проходит. В кабинете «Куплено 2 даты навсегда», две одинаковые карточки и два платежа по 250 ₽ |
| Когда возникает | Есть: когда положение переключателя пола отличается от того, при котором покупали (по умолчанию активна «женская»). Нет: при совпавшем поле — сервер отвечает 409 и пишет «Эта дата уже открыта — второй раз платить не нужно» |
| Почему не находили раньше | Инвариант проверяли внутри одного браузера, где после покупки кнопка покупки не показывается вовсе. Второе устройство или чистый контекст в проверку не входили |
| Корень (проверено мной по коду) | `api/app/routers/payments.py:33-36`: существующая матрица ищется по паре `birth` **и** `sex`, поэтому другой пол создаёт новую запись, а проверка 409 (`unlocked_matrix`) смотрит уже на неё |

**Почему это нужно исправить.** Продукт продаёт дату: тариф называется «Полный разбор одной даты»,
экран оплаты пишет «Все 20 разделов разбора по одной дате рождения», оферта — то же. Пол при этом
не меняет в разборе ни одного числа: тексты двух покупок совпали до знака, различие ровно в одной
строке из 258 — подпись «женская карта» / «мужская карта». Человек платит вторые 250 ₽ за тот же
текст, и заметить это до списания нечем. Это прямой повод для возврата и для претензии.

**Рекомендация.** Искать существующую матрицу и проверять оплаченность по дате, а не по паре
«дата + пол» — ровно так, как уже сделано на экране результата после цикла 13. Пол остаётся
свойством записи (подпись «мужская/женская карта»), но не частью ключа товара. Отдельно стоит
показать на экране оплаты, что именно уже открыто, если дата совпала.

### 2. Ссылка «Открыть разбор … для этой матрицы» ведёт на разбор чужой матрицы

**Приоритет: высокий.**

| | |
|---|---|
| Что видит человек | В оплаченном разборе «Программы» внизу блок «Те же точки в разделе „Ваш идеальный формат отдыха“» со ссылкой «для этой матрицы». Клик — и открывается разбор **другой** даты: для 07.03.1988 отчёт даёт `/encyclopedia/rest/8-9` («Сила, Отшельник»), а ссылка ведёт на `/encyclopedia/rest/5-9` («Иерофант, Отшельник») |
| Когда возникает | Есть: на всех 54 слагах раздела «Программы» — по моему перебору поставочных 5 544 матриц неверный адрес получают **4 979 (89,8 %)**. Нет: у пар `money40 → resources` и `realisation → purpose`, где слаг цели выводится из исходного (0 из 5 544) |
| Почему не находили раньше | Блок добавлен в итерации 4 и закрыт проверкой на текст, а не на адрес: инварианта «ссылка ведёт на разбор той же матрицы» не существовало |
| Корень | `web/lib/sectionReadings.ts` (`sharedInteraction`): адрес строится как `sectionReadingHref(shared.section, matrix)`, а `matrix` восстановлена из слага «Программ». Слаг `loops` (D–E–духовное) не определяет слаг `rest` (эмоции свадхистханы + центр), и `sectionReadingMatrix` возвращает первую подходящую матрицу |

**Почему это нужно исправить.** Это платный раздел, и ссылка подписана «для этой матрицы». Человек
уходит читать про себя, а читает чужой разбор — и никакого признака подмены на странице нет: та же
вёрстка, те же заголовки, другие арканы. Хуже того, разбор соседнего раздела он потом может принять
за свой.

**Рекомендация.** Либо передавать в ссылку исходную матрицу целиком (как это уже делает `years`
через `?birth=`), либо показывать блок только там, где целевой слаг однозначно выводится из
исходного — то есть у `money40 → resources` и `realisation → purpose`, а у `loops → rest` заменить
ссылку на текст без адреса. Первое лучше: смысл блока в том, чтобы увести на свой второй разбор.

### 3. Со страницы 404 нельзя уйти по ссылке

**Приоритет: высокий.**

| | |
|---|---|
| Что видит человек | На «Такой страницы нет» жмёт «Главная и расчёт». Адрес меняется на `/`, заголовок вкладки — на заголовок главной, а на экране по-прежнему «Такой страницы нет», формы расчёта нет. Выйти можно только перезагрузкой или кнопкой «назад» |
| Когда возникает | Есть: с любого несовпавшего адреса и по любой ссылке 404 — проверено мной на `/nosuchpage` и `/encyclopedia/arcanum/99`, оба раза после клика `#d` отсутствует. Нет: на обычных страницах переходы работают |
| Почему не находили раньше | Тесты 404 проверяют статус, заголовок и наличие текста, но ни один не кликает ссылку с этой страницы |
| Корень | `app/global-not-found.tsx` собирает **собственный** документ с своим `<html>` — это и было решением против пустого 404 в итерации 3. Клиентский роутер в таком документе не совпадает с деревом маршрутов, поэтому `<Link>` меняет историю, но не отрисовывает целевую страницу |

**Почему это нужно исправить.** 404 — это точка, куда попадают по устаревшим ссылкам из поиска и
мессенджеров. Сейчас там тупик: три ссылки «Главная и расчёт», «Энциклопедия», «Мой разбор» не
работают. Обещание «тупиков на сайте быть не должно», написанное на самой странице, не выполняется.

**Рекомендация.** Проще всего — сделать эти три ссылки обычными `<a href>` без клиентской
навигации: полная перезагрузка на 404 ничего не стоит и гарантированно уводит. Если хочется
сохранить клиентские переходы, придётся отказаться от собственного документа, а это вернёт пустое
тело 404 — то есть решение обратное тому, что принято в итерации 3.

### 4. Подпись даты на экране оплаты получает пометку пола, когда различать нечего

**Приоритет: низкий.** Тот же корень, что у дефекта 1.

Переименованная в кабинете матрица («Сестра Аня») на `/pay?m=…` печатается как «Сестра Аня (ж)» —
в единственном пункте списка, в подсказке и на кнопке. Пометка нужна, только когда в списке есть
две одинаковые даты разного пола; здесь пункт один. Чинится вместе с ключом товара: если пол
перестанет быть частью товара, различать будет нечего.

### 5. Пульс админки считает одну печать дважды

**Приоритет: низкий** (экран только для администратора).

При единственной задаче печати строка состояния показывает «1 печатается, 1 в очереди»: `/api/admin/pulse`
отдаёт `print.active=1` и `print.waiting=1` одновременно, хотя running-строка одна (id 257). Держится
6,4 с — весь срок печати. Числа админки должны сходиться сами с собой, иначе по ним нельзя судить о
загрузке.

### 6. «Смотрят» молча обрезано до пяти страниц

**Приоритет: низкий** (экран только для администратора).

В заголовке «1 человек · 8 вкладок сейчас», в разбивке ниже — пять адресов, сумма вкладок 5. Три
вкладки пропали без пометки «и ещё 3». Либо показать остаток, либо назвать список «пять самых
частых».

## Отсеянное

| Находка | Почему не дефект |
|---|---|
| Двойные клики, повторные отправки, обновление посреди операции, две вкладки | Маршрут «дубли и повторные отправки» находок не дал: кнопки блокируются, повтор второй сущности не создаёт |
| Приватность: остатки чужих данных после выхода, индексация служебных экранов | Маршрут «приватность» находок не дал; `noindex` подтверждён и метатегом, и заголовком `X-Robots-Tag` |
| Печать PDF: повторная печать, обновление во время печати, печать неоплаченного | Маршрут «печать» дефектов поведения не дал (замечание к содержимому PDF — в отчёте по текстам) |
| Калькулятор и навигация: назад/вперёд, обновление, две вкладки, подмена даты | Маршрут находок не дал |
