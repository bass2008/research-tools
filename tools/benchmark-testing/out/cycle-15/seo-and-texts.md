## Подтверждённые дефекты

### 1. ОТОЗВАНО. «Вместо цены отдаётся заглушка „уточняется"»

**Находка снята мной 3 сентября: это загрузка, а не дефект.**

На месте цены стоит заглушка, пока идёт запрос за прайсом. Через 1,3 с она сменяется на «250 ₽»,
кнопка покупки всё это время ведёт на оплату. Никакого расхождения между тем, что показывает
страница, и тем, что происходит, нет — см. §5, «Незагруженное — не сломанное».

Что я подал как улики и почему они таковыми не были:

| Довод | Чего он не доказывает |
|---|---|
| 352 адреса из 356 содержат «уточняется» | сколько страниц находятся в состоянии загрузки — не мера поломки |
| цена появляется на 1332 мс | длительность загрузки не делает загрузку отказом |
| «поисковик проиндексирует „уточняется" вместо цены» | статьи не объявляют себя товаром: в их разметке `Article`, `BreadcrumbList`, `FAQPage`, слова `"price"` нет вовсе. Цена объявлена там, где объявлен товар, — `Product` с `"price": "250.00"` на главной |
| «ломается воронка из поиска» | предположение о поведении человека, не проверенное ничем |

Остаётся возможное улучшение, не дефект: **читать прайс на сервере и на этих страницах** — механизм
есть, им пользуются главная и оферта. Это уберёт секундную заглушку и даст цену клиенту без
JavaScript. Делать или нет — вопрос владельцу.

### 2. Меню справочника на 16 разделах подсвечивает «22 аркана», а крошка над ним — «Разделы отчёта»

**Приоритет: средний.**

| | |
|---|---|
| Что видно | На персональном разборе, например `/encyclopedia/money/10-5-22-3`, хлебные крошки говорят «Главная › Энциклопедия › Разделы отчёта › Деньги», а подсвеченный пункт бокового меню — «22 аркана». Меню показывает не тот раздел, в котором человек стоит |
| Мой замер | Прошёл по одному живому адресу каждого раздела: расходятся **13 из 16** проверенных; совпадают только `character`, `comfort`, `profession`. Ещё три раздела (`years`, `chakras`, `body_resource`) попадают под тот же корень — итого **16 разделов**. Адресов под ними: `years` 5 544, `chakras` 5 544, `family_gifts` 4 463, `parents_children` 4 429, `money` 1 766, `relations` 1 685, `ancestry` 886, `body_resource` 363, `karma40` 332, `soul_tasks` 239, `rest` 215, `money40` 95, `resources` 95, `realisation` 86, `loops` 54, `purpose` 42 — **25 838** |
| Корень (проверено мной по коду) | `web/lib/encyclopediaNavigation.ts:65` знает только три раздела списком: `["character", "comfort", "profession"]`. Остальные не разрешаются ни списком, ни сегментом, функция возвращает `null`, и `web/components/enc/EncFrame.tsx:61` берёт запасной вариант `sections[0]` — первый пункт меню, то есть «22 аркана» |

**Почему это нужно исправить.** Меню — единственный указатель «где я» на странице без списка;
подсветка спорит с крошками и с заголовком на одном экране. Три раздела из шестнадцати работают
верно ровно потому, что их вписали руками — то есть следующий добавленный раздел сломается так же.

**Рекомендация.** Не держать список разделов в двух местах: выводить раздел из того же перечня
персональных ключей, по которому построены маршруты (`PersonalSectionKey`), а не из строкового
массива. Сторож на соответствие «подсвеченный пункт = третья крошка» по одному адресу каждого
раздела — тот же приём, что уже сторожит список маршрутов.

### 3. Несуществующий адрес персонального разбора отдаёт HTML с заголовком и карточкой главной

**Приоритет: средний.**

| | |
|---|---|
| Мой замер | `GET /encyclopedia/money/1-1-1` → HTTP **404**, и в отданном HTML: `<title>` — «Матрица судьбы — расчёт по дате рождения с расшифровкой» (заголовок **главной**), `og:title` — «Arcana Sense», ни одного `<h1>`. Директива `noindex` на месте. В браузере после гидратации заголовок становится верным — «Страница не найдена — Arcana Sense» |
| Отчего так | Маршрут объявлен `force-dynamic`, метатеги приходят потоком после тела; до этого в документе стоит значение по умолчанию из корневого макета |

**Почему это нужно исправить.** Пустое тело до гидратации — принятое решение (цена отсечения
25 тысяч адресов разбиралась дважды), а вот заголовок и карточка главной — нет. Битой ссылкой
делятся: мессенджер и соцсеть читают именно этот HTML и показывают карточку главной страницы, то
есть обещают рабочий адрес там, где его нет.

**Рекомендация.** Отдавать метатеги «страница не найдена» синхронно — не потоком: на этом
маршруте `generateMetadata` уже умеет возвращать `NOT_FOUND_META`, нужно только чтобы значение
попадало в первый кусок документа. Сторож: в отданном HTML такого адреса `og:title` не равен
`og:title` главной.

### 4. Одиннадцать страниц точек обещают, что позиция открывается только полным разбором

**Приоритет: средний.**

| | |
|---|---|
| Что написано | «Карта по дате рождения строится бесплатно и без регистрации. Позицию «Духовная мужская линия рода — точка F» **открывает полный разбор**» — `web/app/encyclopedia/position/[key]/page.tsx:222-224` |
| Что на самом деле | Бесплатный расчёт без регистрации выводит блок «Все позиции карты» со всеми точками — аркан и строка «как читается». Мой замер: из 11 страниц, где стоит платное обещание, **11 из 11** названий встречаются в бесплатном результате (9 совпали дословно, «внутренняя левая точка» и «вход денежной линии» — с поправкой на тире в подписи расчёта): «Кармическая задача», «Духовная мужская линия рода», «Духовная женская линия рода», «Материальная мужская линия рода», «Материальная женская линия рода», «Внутренняя левая точка», «Вход денежной линии», «Духовное предназначение», «Планетарное предназначение», «Личное предназначение», «Социальное предназначение» |
| Корень | `isFree` (строка 63) выводится из доступности **раздела** отчёта, а страница описывает **точку**. Точка видна в бесплатной карте, раздел — нет; признак взяли не тот |

**Почему это нужно исправить.** Обещание работает против продажи: человек пришёл из поиска
по запросу про конкретную точку, и первая же строка призыва говорит, что смотреть придётся за
деньги, — хотя эту точку он получит бесплатно за один шаг. Плюс это просто неверный текст на
одиннадцати индексируемых страницах.

**Рекомендация.** Считать признак от того, что реально показывает бесплатный расчёт: если аркан
точки есть в бесплатной карте — обещать бесплатный результат, а полный разбор предлагать за
толкованием. Сторож: для каждой страницы точки формулировка призыва должна совпадать с тем, есть
ли её название в бесплатном результате.

### 6. Плашка «секрет обрезан» стоит у незаданной переменной

**Приоритет: низкий.** Повтор дефекта 4 цикла 14, не исправлялся.
`web/components/admin/AdminSettings.tsx:32` вешает плашку по признаку `row.sensitive`, то есть по
типу переменной, а не по наличию значения: у пустой переменной администратор видит «секрет
обрезан» и думает, что значение задано и просто скрыто.

**Рекомендация.** Показывать плашку только когда значение непустое; для пустой писать «не задано».
