# Браузерные сценарии

Ходят по сайту так, как ходит человек: клики, ввод, переходы. Подмены состояния и прямых
запросов к api здесь нет — только то, что доступно из браузера.

Общий локальный стенд и языковые сценарии описаны в
[runtime-localization.md](../docs/runtime-localization.md). Команды из корня проекта:

```sh
docker compose -f compose/docker-compose.localized.yml up --build -d
E2E_URL=http://127.0.0.1:3000 E2E_API_CONTAINER=arcana-localized-api-1 \
  /home/sergey/miniconda3/envs/research3.12/bin/python -m pytest e2e/test_runtime_localization.py -q
```

Обычные русскоязычные сценарии на этом стенде используют `E2E_URL=http://localhost:3000`;
сценарии переключения — международный профиль `127.0.0.1:3000`.
Набор проверок выбирается по задаче; полный прогон — по
[release-process.md](../docs/release-process.md).

Remote-fixtures распознают `.ru` и `.com` по точному hostname URL; оба тестовых домена
используют общий удалённый API-контейнер. Похожая строка в query/path не превращает локальный
стенд в удалённый. `E2E_REMOTE_API` позволяет указать имя текущего контейнера.

`PAYMENT_PROVIDER=mock` в обычном локальном запуске задаёт mock в RU-профиле;
в `docker-compose.localized.yml` это уже явно настроено. COM не принимает оплату.
`test_payment_regions.py` проверяет запрет, переключение сообщения и общие купленные права.
Старые проверки многоязычной формы пропускаются, если у проверяемого профиля нет провайдеров;
они применимы к специально настроенному локальному профилю с оплатой.
`MAIL_TO_LOG=1` держит письма в логе api — оттуда сценарий восстановления пароля берёт ссылку.

Прогон идёт на общей базе стенда и ничего не чистит: у каждого теста своя случайная почта, поэтому
повторные запуски не мешают друг другу.
