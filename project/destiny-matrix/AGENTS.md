# Обязательная архитектура контента

## Все статьи находятся только в энциклопедии

Любая страница, основной ценностью которой является толкование, разбор или другой
полноценный читаемый материал, обязана иметь URL внутри `/encyclopedia/`.

Это правило распространяется в том числе на:

- общие SEO-статьи;
- статьи по разделам отчёта;
- персональные разборы комбинаций и троек арканов;
- индексируемые и закрытые от индексации статьи;
- материалы, собранные комбинаторно из канонических текстовых блоков.

Маршруты `/matrix/` предназначены только для калькулятора, результата расчёта,
схемы матрицы и короткой навигации. Полноценный текст статьи внутри `/matrix/`
размещать нельзя. Результат расчёта должен вести в соответствующий материал внутри
`/encyclopedia/`, а статья может ссылаться обратно на матрицу и калькулятор.

Хлебные крошки статьи также обязаны проходить через энциклопедию:

`Главная → Энциклопедия → … → Статья`.

`noindex` не является исключением: персональная статья может быть закрыта от индексации,
но всё равно должна находиться в `/encyclopedia/`.

Перед завершением любой задачи с новым контентным маршрутом обязательно проверить:

- URL статьи начинается с `/encyclopedia/`;
- переход из калькулятора ведёт в `/encyclopedia/`, а не в `/matrix/`;
- хлебные крошки включают «Энциклопедия»;
- `/matrix/` не содержит полноформатную статью.

Отступать от этого правила можно только по отдельной прямой команде пользователя.

## Новые функции повторяют существующие паттерны проекта

При реализации новой функции необходимо сначала найти и повторить ближайший существующий
паттерн проекта: структуру страницы, маршрут, хлебные крошки, тип перехода, компонент,
цвет, размер и визуальный приоритет элемента.

Если в проекте уже есть аналогичный сценарий, нельзя без прямой просьбы пользователя:

- изобретать для нового сценария отдельный дизайн;
- менять обычную текстовую ссылку на акцентную кнопку;
- добавлять новый цвет, вариант CTA или уровень визуального приоритета;
- создавать другую навигационную модель для сущности того же типа;
- делать новый компонент вместо переиспользования существующего паттерна.

Пример обязательного применения: переход из раздела отчёта в персональную статью должен
выглядеть и работать так же, как существующий переход из кармического хвоста в энциклопедию.
Если у аналога используется обычная ссылка внизу раздела, новый переход тоже должен быть
обычной ссылкой, а не жёлтой или иной акцентной кнопкой.

Если существующий паттерн кажется неудачным и есть идея сделать лучше, это отдельное
предложение, а не часть реализации. До изменения необходимо сообщить пользователю:

- какой текущий паттерн предлагается нарушить;
- что именно предлагается вместо него;
- зачем это нужно и какая ожидается польза;
- какие страницы и компоненты будут затронуты;
- какие возможны побочные эффекты.

Реализовывать такое отклонение можно только после явного согласования пользователя.
Без согласования повторяется существующий паттерн проекта.
