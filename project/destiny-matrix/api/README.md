# api — бэкенд «матрицы судьбы»

FastAPI + SQLAlchemy 2 на SQLite. Расчёт не дублируется: `app/report.py` импортирует
`engine.matrix.calculate` и `engine.sections.build` из корня продукта.

## Запуск

```bash
./run.sh                 # схема + uvicorn на 127.0.0.1:8010
./run.sh 8011            # другой порт
```

`run.sh` использует conda-окружение `research3.12` (переопределяется `CONDA_ENV`).
Документация схемы — `http://127.0.0.1:8010/api/docs`, OpenAPI — `/api/openapi.json`.

## Схема без миграций

```bash
python -m app.schema ensure   # создать недостающее и наполнить справочник тарифов
python -m app.schema reset    # снести всё и создать заново
```

Миграций на этапе разработки нет намеренно: таблицы можно ронять. **В день первой живой
продажи миграции надо вернуть** — `reset` уносит платежи вместе с таблицами. Полное описание
таблиц и правил доступа — `docs/schema.md`.

## Тесты

```bash
conda run -n research3.12 python -m pytest -q
```

Идут на sqlite в памяти, сеть и внешняя БД не нужны.

## Конфиг (переменные окружения, `.env.example`)

| переменная | по умолчанию | смысл |
|---|---|---|
| `DATABASE_URL` | `sqlite+pysqlite:///api/var/api.db` | других СУБД в планах нет, см. ниже |
| `JWT_SECRET` | dev-заглушка | при `APP_ENV=prod` дефолт и ключ короче 32 байт запрещены |
| `JWT_TTL_DAYS` | `30` | срок токена по контракту |
| `MOCK_PAYMENTS` | `1` | `0` — `/api/payments/mock` отвечает 503 |
| `ENCYCLOPEDIA_DIR` | `../web/content/encyclopedia` | откуда читается контент энциклопедии |
| `CORS_ORIGINS` | пусто | список через запятую; пусто = кросс-домена нет (см. ниже) |
| `MATRICES_HARD_CAP` | `2000` | предохранитель от спама, а не тариф |
| `APP_ENV` | `dev` | `prod` включает проверки конфига |

Postgres из планов вычеркнут: нагрузка на одну виртуалку, а SQLite в WAL держит и запись, и
чтение. Обязательные настройки соединения (`foreign_keys`, `journal_mode`, `busy_timeout`)
включены в `models.py` — без первой не работают каскады.

## Доступ считают права, а не поле тарифа

Справочник тарифов лежит в таблице `tariffs` (цена в копейках, меняется `UPDATE`-ом без
пересборки фронта). Оплата пишет `payments` со снимком тарифа в `tariff_body` и выдаёт запись в
`entitlements`. Что открыто — решает `app/access.py` по действующим правам:

- `single` — один разбор по одной дате; право привязано к матрице через `matrix_id`;
- `matrix` — хранить и открывать матрицы в кабинете; без него кабинет держит одну;
- `all` — любое число дат.

**Разовое право находит дату не сразу.** Дата рождения в платёжный запрос не входит (так
обещано в оферте), поэтому право приходит с `matrix_id IS NULL` и привязывается один раз: на
оплате — к последней сохранённой матрице, если она есть, иначе к первой, которую сохранят после
оплаты (`access.bind_single`). Привязка происходит только на записи; чтение разбора прав не
меняет.

Следствия, которые видно в ответах: `GET /auth/me` отдаёт `access.scopes`, `can_store`,
`unlimited`, `until` и `matrices_used` — поля `tariff` и `matrices_limit` больше нет; открыт ли
разбор конкретной матрицы, говорит `unlocked` в `GET /matrices/{id}`.

## Решения, которые контракт не фиксировал

- **Бесплатно два раздела** — `character` и `comfort`. Остальные восемнадцать открывает любой
  платный тариф: тарифов, дающих часть разделов, больше нет.
- **`unlocked`** — `true`, когда открыт полный разбор этой матрицы.
- **Мок-оплата накапливает права**, а не заменяет их: месячный доступ поверх разового не
  отменяет разовый, у пользователя просто два действующих права.
- **`/leads` идемпотентен по почте**: повторная отправка не плодит строк, пустой `source`
  дозаполняется первым непустым.
- **Энциклопедия**: если в `ENCYCLOPEDIA_DIR` ещё нет файлов генератора, эндпоинты отдают
  каркас по контракту с флагом `"stub": true`. Форматы, которые читаются:
  `arcanum/{n}.json`, `arcana/{n}.json`, `arcana.json` (объект по номерам, `{"arcana": [...]}`
  или список), `index.json`.

## CORS — когда его вообще включать

По умолчанию `CORS_ORIGINS` пусто, и мидлварь CORS не подключается вовсе. На принятой
раскладке деплоя браузер к этому API напрямую не обращается: страницы отдаёт node-сервер
Next.js, а его BFF ходит в api серверным запросом со своей же машины — там политики одного
источника нет и заголовки `Access-Control-*` ни на что не влияют. Разрешать localhost «на
всякий случай» значит держать для чужих страниц открытую дверь к эндпоинтам с `Authorization`.

Заполнять список стоит только в служебных случаях:

- отдельный админский или мониторинговый фронт на другом домене;
- мобильное приложение или сторонний интегратор, ходящий из браузера;
- временная отладка, когда фронт запущен не на том же origin, что API.

Формат — список через запятую, схему и порт указывать целиком:
`CORS_ORIGINS=https://admin.example.ru,http://localhost:5173`. Запросы идут с
`allow_credentials=True`, поэтому `*` не поддерживается принципиально — только точные origin.

## Про дату рождения

Дата приходит только в теле `POST /api/matrix/calc` и `POST /api/matrices`. Её нет ни в одном
пути, ни в query-параметре, ни в теле `/payments/mock` и `/leads` — это проверяется тестом
`tests/test_privacy.py` по OpenAPI. В логах uvicorn остаются только методы и пути, тело не
пишется.

## Долг, который нужно закрыть до продакшна

- **Настоящий приём платежей.** `POST /api/payments/mock` всегда отвечает «оплачено» и для
  автосозданного аккаунта отдаёт токен. На проде гасить `MOCK_PAYMENTS=0` и заменять
  эндпоинт на провайдера с чеком по 54-ФЗ.
- **Автопродление подписки.** Токен способа оплаты не сохраняется, планировщика списаний нет,
  экрана согласия и отмены тоже — поэтому срочный тариф продлевается только вручную.
- **Миграции.** Пока схема создаётся из моделей; до первой продажи нужен инструмент, который
  меняет таблицы, не теряя платежи.
- **Уведомления об окончании доступа.** Срок проверяется на запрос, фоновой задачи нет: письмо
  «доступ кончается» никто не отправляет.
- **Восстановление пароля.** Автосозданному при оплате аккаунту пароль показывается один раз;
  сброса по почте нет.
- `passlib` 1.7.4 несовместим с `bcrypt` 5.x (падает при загрузке бэкенда), поэтому в
  `requirements.txt` стоит `bcrypt>=4.0,<4.1`. Пароли хешируются схемой `bcrypt_sha256`:
  у неё нет ни лимита 72 байта, ни молчаливого обрезания длинного пароля.
- Целочисленные id матриц видны в URL кабинета; если понадобятся неугадываемые ссылки, нужен
  отдельный публичный uuid.
