# compose — весь продукт двумя контейнерами

Раскладка та же, что на боевой машине (`docs/api-contract.md`, «Раскладка деплоя»): браузер
ходит только во фронт, а фронт своим BFF — в API по внутренней сети. Порт API открыт наружу
только на `127.0.0.1` и только для отладки.

```bash
cp .env.example .env      # по желанию: порты, домен, секреты
scripts/run.sh            # собрать изменившееся и поднять
```

Скрипты без параметров, один скрипт — одно действие:

| скрипт | что делает |
|---|---|
| `scripts/run.sh` | собрать изменившееся и поднять — повседневный запуск |
| `scripts/full-build.sh` | пересобрать всё с нуля и поднять |
| `scripts/prod.sh` | раскладка боевой машины: nginx впереди, node и api спрятаны |
| `scripts/down.sh` | погасить (база в томе остаётся) |
| `scripts/run-python.sh` | без докера: uvicorn напрямую и собранный фронт на node |
| `scripts/release.sh` | задеплоить последнюю версию на прод |

| адрес | что |
|---|---|
| http://127.0.0.1:3000 | сайт |
| http://127.0.0.1:8010/api/health | API напрямую |
| http://127.0.0.1:3000/admin | админка, `snborodaenko@mail.ru` / `123` |

## Какой скрипт когда

| | `scripts/run.sh` | `scripts/full-build.sh` |
|---|---|---|
| что делает | пересобирает только изменившиеся слои и поднимает | игнорирует кеш слоёв: заново ставит зависимости и печатает страницы |
| правок нет | **2 с** | ~67 с |
| поправили `.tsx` / `.ts` / python | **~52 с** | ~67 с |
| поменяли `package-lock.json` | ~65 с (переустановка зависимостей) | ~67 с |

Замеры на этой машине, а не оценка. `run.sh`: третий запуск подряд без правок — 2 с, после
правки одного компонента — 52 с, из них `next build` 29 с и экспорт слоёв 19 с.
`full-build.sh` целиком — 67 с, по шагам: `pip install` 39 с, `npm ci` 12,5 с,
`next build` 30 с (шаги идут параллельно, поэтому сумма больше итога).

**`./run.sh` — повседневный путь.** Правите код, запускаете, смотрите. Docker сам понимает, что
изменилось: слой с `npm ci` переиспользуется, пока не тронут `package-lock.json`.

**`./full-build.sh` нужен в четырёх случаях:**

1. **Первый запуск на новой машине** — кеша слоёв ещё нет вовсе.
2. **Перед релизом** — проверить, что образ собирается с нуля и воспроизводимо: `--no-cache
   --pull` подтягивает свежие базовые образы `node:22-alpine` и `python:3.12-slim` и ставит
   зависимости заново. Если сборка проходит только на вашем кеше, на сервере она сломается.
3. **Обновились базовые образы или зависимости** — заплатки безопасности в node и python
   приезжают именно через `--pull`, кеш слоёв о них не знает.
4. **Образ ведёт себя странно** — в сборке остался мусор от прошлых слоёв, `.next` собрался
   наполовину, тесты зелёные, а в контейнере старый код. Полная пересборка отвечает на вопрос
   «дело в кеше или в коде».

Логи — `docker compose logs -f`. Снести том с базой (данные пропадут) — `docker compose down -v`.

## Две раскладки

**`./run.sh`** — dev: node смотрит наружу на 3000, api на 8010 для отладки. Быстро и удобно
дебажить.

**`./prod.sh`** — то, что будет на машине: nginx единственная точка входа на `HTTP_PORT`
(по умолчанию 8080), node и FastAPI наружу не смотрят вовсе, `_next/static` nginx отдаёт с
диска с `Cache-Control: immutable`, а не проксирует в node. Правила взяты из
`infra/terraform/server/cloud-init.yaml.tftpl` — того же файла, что настраивает боевую машину.

Отличий от машины два, оба осознанные: TLS там терминирует сам nginx по сертификату certbot
(локально всё по http, поэтому `SESSION_COOKIE_SECURE=0`), и `_next/static` дополнительно
уезжает в Object Storage — за это отвечает `ASSET_PREFIX`.

## Нужно ли выносить фронт в S3

Нет, и это записанное решение (`docs/api-contract.md`, «Раскладка деплоя — решено»). Object
Storage не выполняет код: он не поставит httpOnly-куку, без которой нет сессии, и не решит,
кому печатать платные разделы. Предрендеренная страница отчёта содержала бы тексты всех
платных разделов в исходнике — их было бы видно, не заплатив.

В бакет уезжает только то, что и правда статично: `_next/static` и картинки из `public`
(`infra/terraform/site/deploy.sh`). Подключается это одной переменной — `ASSET_PREFIX`
(в сборку уходит как `NEXT_ASSET_PREFIX`): браузер берёт чанки с бакета или CDN, HTML
по-прежнему печатает node. Пусто — чанки отдаёт nginx с диска, и это рабочий вариант:
вся статика весит 1,4 МБ.

## Релиз на прод

```bash
scripts/release.sh
```

Скрипт делает четыре вещи: собирает образы, помечает их коротким хешем коммита, отправляет в
Yandex Container Registry и на машине выполняет `docker compose pull` с перезапуском службы.
Сборки на машине нет вовсе — 2 vCPU с гарантией 5 % печатали бы 5 854 страницы десятки минут.

Адрес машины и реестр скрипт спрашивает у `yc`, а не у terraform: ключи к state ему не нужны.
Версия сборки уезжает в образ, поэтому после релиза её видно снаружи:

```bash
curl http://<ip>/version/current.txt     # commit, branch, время сборки
```

Та же тройка показана первой панелью в админке — совпадение с `git log` означает, что на машине
именно то, что вы собрали.

## Что где лежит

```
compose/
  docker-compose.yml    два сервиса, том под базу, healthcheck и порядок запуска
  api.Dockerfile        FastAPI + engine + content энциклопедии; контекст — корень продукта
  web.Dockerfile        сборка Next.js и standalone-сервер; контекст — web/
  compose.prod.yml      надстройка: nginx впереди, порты node и api закрыты
  nginx.conf            те же правила, что в cloud-init боевой машины
  compose.server.yml    раскладка на машине: образы из реестра, сборки нет
  scripts/
    run.sh              собрать изменившееся и поднять
    full-build.sh       полная пересборка с нуля
    prod.sh             запуск в раскладке боевой машины
    down.sh             погасить
    run-python.sh       запуск без докера (uvicorn + node)
    release.sh          релиз на прод: сборка, реестр, перезапуск на машине
  .env.example          порты, домен, секреты
```

База — SQLite в томе `arcana_api-var`: контейнер пересоздаётся, платежи и матрицы остаются.
Схема создаётся при старте (`python -m app.schema ensure`), справочник тарифов и админ
наполняются сидом — на пустом томе сайт поднимается сам, без ручных шагов.

## Две вещи, которые ломаются молча

**`SESSION_COOKIE_SECURE`.** Кука сессии с флагом `secure` по http не ставится вовсе, и вход
перестаёт работать без единой ошибки в логах. Локально флаг выключен (`0`), на домене с TLS
обязательно поставить `1`.

**`--no-cache` не чистит кеш Next.** Кеш-маунт `.next/cache` живёт отдельно от слоёв, поэтому
даже полная пересборка переиспользует его — отсюда 30 с на генерацию вместо холодных двух-трёх
минут. Обычно это то, что нужно; если требуется честно холодная сборка (например, подозрение на
битый кеш), сначала `docker builder prune --filter type=exec.cachemount`.

**`SITE_URL` попадает в сборку.** Адрес уходит в canonical, sitemap и OG-разметку на этапе
`next build`, а не при запуске: сменили домен — нужна пересборка фронта, перезапуск не поможет.
