# compose — весь продукт двумя контейнерами

Раскладка та же, что на боевой машине (`docs/api-contract.md`, «Раскладка деплоя»): браузер
ходит только во фронт, а фронт своим BFF — в API по внутренней сети. Порт API открыт наружу
только на `127.0.0.1` и только для отладки.

```bash
cp .env.example .env      # по желанию: порты, домен, секреты
scripts/run.sh            # собрать изменившееся и поднять
```

Скрипты без параметров, один скрипт — одно действие:

| скрипт | что делает |
|---|---|
| `scripts/run.sh` | собрать изменившееся и поднять — повседневный запуск |
| `scripts/full-build.sh` | пересобрать всё с нуля и поднять |
| `scripts/down.sh` | погасить (база в томе остаётся) |
| `scripts/run-python.sh` | без докера: uvicorn напрямую и собранный фронт на node |
| `scripts/release-prod.sh` | задеплоить последнюю версию на прод |
| `scripts/release-test.sh` | задеплоить текущее дерево на `test.arcana-sense.ru` |
| `scripts/backup.sh` | копия боевой базы в Object Storage |
| `scripts/release-snapshot.sh` | read-only агрегаты prod-БД до/после релиза |
| `scripts/rollback-prod.sh` | dry-run/откат на tag перед последним prod-релизом |
| `scripts/cleanup-local-db.sh` | снести локальную базу и засеять заново |
| `scripts/run-tests.sh` | все тесты подряд: api, компонентные, браузерные, приёмка |
| `scripts/assert-release-candidate.sh` | запрещает deploy dirty/непроверенного commit |

| адрес | что |
|---|---|
| http://127.0.0.1:3000 | сайт |
| http://127.0.0.1:8010/api/health | API напрямую |
| http://127.0.0.1:3000/admin | админка, `snborodaenko@mail.ru` / `123` |

## Какой скрипт когда

| | `scripts/run.sh` | `scripts/full-build.sh` |
|---|---|---|
| что делает | пересобирает только изменившиеся слои и поднимает | игнорирует кеш слоёв: заново ставит зависимости и печатает страницы |
| правок нет | **2 с** | ~67 с |
| поправили `.tsx` / `.ts` / python | **~52 с** | ~67 с |
| поменяли `package-lock.json` | ~65 с (переустановка зависимостей) | ~67 с |

Замеры на этой машине, а не оценка. `run.sh`: третий запуск подряд без правок — 2 с, после
правки одного компонента — 52 с, из них `next build` 29 с и экспорт слоёв 19 с.
`full-build.sh` целиком — 67 с, по шагам: `pip install` 39 с, `npm ci` 12,5 с,
`next build` 30 с (шаги идут параллельно, поэтому сумма больше итога).

**`./run.sh` — повседневный путь.** Правите код, запускаете, смотрите. Docker сам понимает, что
изменилось: слой с `npm ci` переиспользуется, пока не тронут `package-lock.json`.

**`./full-build.sh` нужен в четырёх случаях:**

1. **Первый запуск на новой машине** — кеша слоёв ещё нет вовсе.
2. **Перед релизом** — проверить, что образ собирается с нуля и воспроизводимо: `--no-cache
   --pull` подтягивает свежие базовые образы `node:22-alpine` и `python:3.12-slim` и ставит
   зависимости заново. Если сборка проходит только на вашем кеше, на сервере она сломается.
3. **Обновились базовые образы или зависимости** — заплатки безопасности в node и python
   приезжают именно через `--pull`, кеш слоёв о них не знает.
4. **Образ ведёт себя странно** — в сборке остался мусор от прошлых слоёв, `.next` собрался
   наполовину, тесты зелёные, а в контейнере старый код. Полная пересборка отвечает на вопрос
   «дело в кеше или в коде».

Логи — `docker compose logs -f`. Снести том с базой (данные пропадут) — `docker compose down -v`.

## Один файл на все раскладки

Состав продукта описан один раз — в `docker-compose.yml`: три сервиса, образы из реестра,
healthcheck, том с базой, выкладка `_next/static` в каталог, откуда её раздаёт nginx машины.
**Этот файл едет на сервер как есть** (`release-prod.sh` кладёт его в `/srv/arcana/docker-compose.yml`).

Локально рядом лежит `docker-compose.override.yml` — compose подхватывает его сам, без флагов, и
добавляет то, чего на сервере быть не должно: сборку из исходников, порты 3000 и 8010 наружу,
dev-значения секретов, `SESSION_COOKIE_SECURE=0` (по http кука с `secure` не ставится). Серверные
части, которые локально мешают, он снимает через `!override`: каталог статики хоста и команду
копирования.

На машине override отсутствует, поэтому dev-надстройка туда физически не может приехать.

Обязательность секретов проверяет не compose, а сам api (`settings.check`): в проде без явного
`JWT_SECRET` и без своего `BROWSER_SECRET` он откажется стартовать. Если бы это проверял compose
через `${VAR:?}`, локальный запуск стал бы невозможен без `.env` — интерполяция базы происходит
до применения override.

Отличий локальной раскладки от боевой два, оба осознанные: там впереди системный nginx с TLS от
certbot (его настраивает `infra/terraform/server/cloud-init.yaml.tftpl`, не compose), и `_next/static`
может дополнительно уезжать в Object Storage.

## Нужно ли выносить фронт в S3

Нет, и это записанное решение (`docs/api-contract.md`, «Раскладка деплоя — решено»). Object
Storage не выполняет код: он не поставит httpOnly-куку, без которой нет сессии, и не решит,
кому печатать платные разделы. Предрендеренная страница отчёта содержала бы тексты всех
платных разделов в исходнике — их было бы видно, не заплатив.

В бакет уезжает только то, что и правда статично: `_next/static` и картинки из `public`
(`infra/terraform/site/deploy.sh`). Подключается это одной переменной — `ASSET_PREFIX`
(в сборку уходит как `NEXT_ASSET_PREFIX`): браузер берёт чанки с бакета или CDN, HTML
по-прежнему печатает node. Пусто — чанки отдаёт nginx с диска, и это рабочий вариант:
вся статика весит 1,4 МБ.

## Релиз на прод

```bash
scripts/release-prod.sh
```

До команды обязателен единый локальный `scripts/run-tests.sh`, clean commit и успешная выкладка
этого же commit через `release-test.sh`. Guard сверяет commit с
`reports/unified/release-manifest.json` и `tested-commit.txt`; dirty tree не релизится.

Скрипт собирает и отправляет образы, снимает read-only диагностический снимок и проверенный backup
prod-БД, сохраняет прежний tag в `/srv/arcana/.env.previous.tag`, затем выполняет `docker compose
pull` с перезапуском службы и снимает второй диагностический снимок.
Сборки на машине нет вовсе — 2 vCPU с гарантией 5 % печатали бы 5 854 страницы десятки минут.

Адрес машины и реестр скрипт спрашивает у `yc`, а не у terraform: ключи к state ему не нужны.
Версия сборки уезжает в образ, поэтому после релиза её видно снаружи:

```bash
curl http://<ip>/version/current.txt     # commit, branch, время сборки
```

Та же тройка показана первой панелью в админке — совпадение с `git log` означает, что на машине
именно то, что вы собрали.

## Печать PDF

Три контейнера, а не два: `browser` — это Chromium с сорокастрочной обёрткой (`browser/server.mjs`),
который берёт URL и возвращает PDF. Отдельно он живёт потому, что повышенные права и 300 МБ памяти
на печать нужны только ему, наших исходников и секретов он не видит, а зависший браузер лечится
перезапуском одного сервиса, не роняя сайт.

Как идёт печать:

1. кнопка «Сохранить как PDF» → `POST /api/reports/pdf` (запрос синхронный, ждёт результат);
2. api проверяет, что разбор оплачен, и заводит запись в очереди (`report_jobs`, статус `running`);
3. api выдаёт одноразовый пропуск на одну матрицу (живёт две минуты) и просит `browser` напечатать
   `http://web:3000/print/report?m=…&t=…` — кука владельца браузеру не достаётся;
4. готовый файл уходит в бакет отчётов, задача получает `done`, наружу возвращается ссылка с
   подписью на час;
5. второе нажатие ничего не печатает: api находит готовый файл и отдаёт ссылку на него.

Очередь видна только админу — `/admin`, блок «Очередь отчётов»: кто печатал, сколько заняло,
что упало. Для пользователя очереди нет: он видит заблокированную кнопку с бегущей полосой.

Переменные (`.env`): `BROWSER_SECRET`, `S3_REPORTS_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`.
Без них печать отвечает `503`, всё остальное работает как обычно.

**Файл печатается одним листом**, без разбиения на A4: разбор — это лента, и страницы в нём
только мешали (панель «Главные точки» оставалась заголовком на одной странице и картами на
другой). Предел формата PDF — 200 дюймов на сторону, а разбор длиннее, поэтому лист сжимается
ровно настолько, чтобы уложиться (около 0,87 — текст остаётся текстом, вектор не теряет
качества). Вернуть А4 можно переменной `SINGLE_PAGE=0` у сервиса печати; правила разрывов для
этого режима живут в `globals.css` на классе `.printmode`.

Замеры на этой машине (контейнер, лимит 512 МБ): разбор с 22 картами — 6,7 с и 3,5 МБ одним
листом 837×14400 pt. Память браузера в простое 35 МБ, при печати 260 МБ, CPU в простое — ноль.
Вес сбит вчетверо тем, что для печати отдаётся половинный набор карт (`public/img/arcana/half/`,
260×390) и выключены тени: они печатались серыми масками 2342×3595 на каждую панель.

Две ловушки, на которые ушло время. `page.evaluate` с ожиданием `onload` всех картинок висел до
`protocolTimeout`: React меняет `src` при гидратации, и у прерванных запросов `complete` навсегда
остаётся `false` — теперь ожидание короткое и необязательное, а карты в файл всё равно попадают
(проверено: 80 изображений в PDF). И чужие домены в печати отрезаны: аналитика не должна ни
задерживать файл, ни попадать в него.

## Досверка платежей

Уведомление провайдера может не дойти: сеть, перезапуск, закрытая вкладка. Тогда исход подтянет
опрос — та же обработка, только инициатива наша:

```bash
docker compose exec -T api python -m app.sweep     # на машине это делает cron каждые 5 минут
```

Берутся платежи без исхода за последние сутки, у которых статус не терминальный. **Если таких нет,
задача не создаётся** — иначе очередь заросла бы пустыми прогонами по двенадцать в час. Прогон
виден админу («Досверка платежей»): когда, сколько заявок опрошено, что изменилось и построчный
журнал по каждой заявке — почта, прежний статус, новый.

Расписание ставится из `infra/terraform/server/cloud-init.yaml.tftpl` в `/etc/cron.d/arcana-sweep`,
лог — `/var/log/arcana-sweep.log`.

На стенде уведомление можно послать себе самому — банк до `127.0.0.1` не дотянется:

```bash
docker compose exec -T api python -m app.selfnotify <payment_id> CONFIRMED
```

Подпись считается тем же кодом, который её проверяет, поэтому путь уведомления проверяется
целиком, без публичного адреса.

## Копии базы

```bash
scripts/backup.sh
```

Единственное, что нельзя восстановить своими руками, — база прода: пользователи, платежи и права.
Образы пересобираются, секреты перевыпускаются, VM и зона описаны в terraform.

Копия снимается через `sqlite3 .backup` внутри контейнера (база в WAL, файловая копия без `-wal` —
устаревший снимок), проверяется `integrity_check` на этой машине и только потом уходит в
`s3://db-backups-hjb4rfs/destiny-matrix/api-ГГГГММДД-ЧЧММ.db.gz`. У бакета включены версии; копия
живёт 90 дней, неактуальная версия — 30.

Вернуть копию на машину:

```bash
yc storage s3api list-objects --bucket db-backups-hjb4rfs --prefix destiny-matrix/
yc storage s3api get-object --bucket db-backups-hjb4rfs --key destiny-matrix/api-… api.db.gz
gunzip api.db.gz
scp api.db ubuntu@84.201.157.100:/tmp/
ssh ubuntu@84.201.157.100 "sudo systemctl stop arcana \
  && sudo docker run --rm -v arcana_api-var:/var -v /tmp:/in alpine sh -c 'rm -f /var/api.db-wal /var/api.db-shm && cp /in/api.db /var/api.db' \
  && sudo systemctl start arcana"
```

## Что где лежит

```
compose/
  docker-compose.yml    состав продукта: три сервиса, том под базу, healthcheck, порядок запуска
  docker-compose.override.yml  локальная надстройка: сборка из исходников, порты, dev-секреты
  api.Dockerfile        FastAPI + engine + content энциклопедии; контекст — корень продукта
  web.Dockerfile        сборка Next.js и standalone-сервер; контекст — web/
  browser.Dockerfile    Chromium для печати PDF; контекст — compose/
  browser/server.mjs    сервис печати: URL → PDF, горячий браузер, один поток
  scripts/
    run.sh              собрать изменившееся и поднять
    full-build.sh       полная пересборка с нуля
    down.sh             погасить
    run-python.sh       запуск без докера (uvicorn + node)
    cleanup-local-db.sh снести локальную базу и завести заново (админ + тарифы)
    run-tests.sh        все тесты: api, фронт, браузерные сценарии, приёмка
    release-manifest.py hashes метода/контента/SEO, commit и число sitemap URL
    assert-release-candidate.sh clean-tree и same-commit gate test/prod
    release-prod.sh     релиз на прод: сборка, реестр, перезапуск на машине
    release-test.sh     то же для test.arcana-sense.ru: свои образы, своя база, тестовый банк
    backup.sh           копия боевой базы в бакет db-backups-hjb4rfs
  .env.example          порты, домен, секреты
```

База — SQLite в томе `arcana_api-var`: контейнер пересоздаётся, платежи и матрицы остаются.
Схема создаётся при старте (`python -m app.schema ensure`), справочник тарифов и админ
наполняются сидом — на пустом томе сайт поднимается сам, без ручных шагов.

## Две вещи, которые ломаются молча

**`SESSION_COOKIE_SECURE`.** Кука сессии с флагом `secure` по http не ставится вовсе, и вход
перестаёт работать без единой ошибки в логах. Локально флаг выключен (`0`), на домене с TLS
обязательно поставить `1`.

**`--no-cache` не чистит кеш Next.** Кеш-маунт `.next/cache` живёт отдельно от слоёв, поэтому
даже полная пересборка переиспользует его — отсюда 30 с на генерацию вместо холодных двух-трёх
минут. Обычно это то, что нужно; если требуется честно холодная сборка (например, подозрение на
битый кеш), сначала `docker builder prune --filter type=exec.cachemount`.

**`SITE_URL` попадает в сборку.** Адрес уходит в canonical, sitemap и OG-разметку на этапе
`next build`, а не при запуске: сменили домен — нужна пересборка фронта, перезапуск не поможет.

## Два контура на одной машине

| | прод | тест |
|---|---|---|
| адрес | `arcana-sense.ru` | `test.arcana-sense.ru` |
| файл | `docker-compose.yml` | `docker-compose.test.yml` (проект `arcana-test`) |
| выкладка | `scripts/release-prod.sh` | `scripts/release-test.sh` |
| тег образов | `<commit>` | `test-<commit>` |
| терминал банка | боевой, деньги настоящие | тестовый, игрушечные карты |
| секреты на машине | `/srv/arcana/.env` | `/srv/arcana/.env.test` |
| база | том `api-var` | том `test-api-var` |
| порт для nginx | `127.0.0.1:3000` | `127.0.0.1:3100` |
| статика для nginx | `/srv/arcana/static` | `/srv/arcana/static-test` |
| счётчик Метрики | вшит при сборке | не собирается вовсе |
| прогрев печати | включён, 3 места | выключен, 1 место |

Печать одна на машину: браузерный контейнер держит до 350 МБ, второй такой в 2 ГБ памяти не влезает.
Тестовый контур ходит в тот же `browser` через внешнюю сеть `arcana-print`, а предел одновременных
печатей живёт внутри самого браузерного сервиса (`PRINT_SLOTS`), потому что контуров к нему два.

**Имена сервисов уникальны на всю машину** (`test-api`, `test-web`) — это не косметика. Compose
добавляет алиас по имени сервиса в каждую сеть, куда подключает контейнер; пока тестовый сервис
назывался `web`, имя в общей сети стало неоднозначным, и браузер прода печатал страницу тестового
контура — вместо разбора в файл уходил 404.
