# Контракт: имена, пути, схемы

Зафиксировано до начала работы. Части системы делаются параллельно и сходятся только по этому
файлу: если он расходится с кодом, прав этот файл.

## Раскладка репозитория

```
project/destiny-matrix/  весь продукт живёт здесь, корень репозитория — про конвейер ниш
  engine/                движок расчёта: matrix.py, sections.py, precompute.py, tests/
  api/                   FastAPI + SQLAlchemy, SQLite, схема без миграций (app/schema.py)
  web/                   Next.js 15, App Router, RSC + SSG, TypeScript
  web/content/           сгенерированный контент энциклопедии (JSON, читается на сборке)
  content/               источник контента: генератор и данные (Python)
  infra/                 terraform и деплой
  docs/                  контракт, схема базы, планы
  legacy/                рукописный лендинг и страницы выбора сидов
```

Генератор колоды (FLUX.1-schnell, 16 ГБ весов) лежит вне продукта — `tools/generators`: он ничего
не импортирует из продукта и пишет готовые карты прямо в `web/public/img/arcana`.

## Тарифы

| id | название | цена | доступ | срок |
|---|---|---|---|---|
| `single` | Полный разбор одной даты | 100 ₽ | одна дата, к которой привязано право | бессрочно |
| `month` | Три месяца без ограничений | 240 ₽ | любое число дат, кабинет | 90 дней |

Справочник тарифов лежит в базе (`tariffs`), цена в копейках. Меняется `UPDATE`-ом без пересборки.
Базового тарифа нет: любой платный открывает все 20 разделов. Бесплатно и без регистрации
доступны 2 раздела: `character` и `comfort` — остальное продукт.

Доступ определяют права (`entitlements`), а не поле у пользователя — см. `docs/schema.md`.
Виды: `single` (один разбор по своей матрице), `matrix` (хранение в кабинете), `all` (любые даты).

## API — префикс `/api`, JSON, UTF-8

| метод | путь | тело / параметры | ответ |
|---|---|---|---|
| POST | `/auth/register` | `{email, password}` | `{token, user}` |
| POST | `/auth/login` | `{email, password}` | `{token, user}` |
| GET | `/auth/me` | — | `{user, access: {scopes, rights}, matrices_used, matrices_limit, can_store, unlimited, until}` |
| POST | `/payments/mock` | `{tariff: "single"\|"month", email, matrix_id?, birth?, sex?}` | `{ok: true, payment_id, tariff, entitlement, matrix_id, user, autoregistered, token, requires_login?}` |
| GET | `/matrices` | — | `{items: [{id, birth, sex, created_at, title, access, access_until}]}` |
| POST | `/matrices` | `{birth, sex, title?}` | карточка матрицы: `{id, birth, sex, title, created_at, access, access_until, unlocked}` |
| GET | `/matrices/{id}` | — | та же карточка (`unlocked` — открыт ли платный разбор этой даты) |
| PATCH | `/matrices/{id}` | `{title}` | строка списка; пустое имя возвращает подпись по умолчанию (дату) |
| GET | `/payments` | — | `{items: [{id, amount, tariff, matrix_id, external_id, created_at, paid_at, refunded_at}]}` |
| GET | `/admin/users` | — | `{items: [{id, email, created_at, is_admin, matrices, payments, spent, scopes, owned, until, rights}]}` |
| GET | `/admin/users/{id}` | — | `{user, matrices, payments, rights}` |
| GET | `/admin/payments` | — | все платежи с почтой плательщика |
| POST | `/leads` | `{email, source?}` | `{ok: true}` |
| GET | `/health` | — | `{ok: true, db: bool}` |

Авторизация — заголовок `Authorization: Bearer <token>`, JWT, срок 30 дней.
Ошибки: `{detail: "текст"}` с кодами 400 (валидация), 401 (нет токена), 402 (слоты хранения
кончились), 404, 422 (схема).

### Карточка матрицы

```json
{
  "id": 12,
  "birth": "1987-06-14",
  "sex": "m",
  "title": "Матрица 14 июня 1987",
  "created_at": "2026-08-29T14:00:00+03:00",
  "access": "forever",
  "access_until": null,
  "unlocked": true
}
```

Разделов разбора здесь нет намеренно: их считает фронт на портированном движке.

Ключевое правило: **дата рождения не уходит в аналитику и не попадает в URL платежа.**
На странице обещано «дата не покидает браузер», поэтому расчёт для анонимного посетителя
идёт в браузере на том же движке, портированном в TypeScript. Сервер разбор не собирает
вовсе — ни для гостя, ни для оплатившего: он хранит даты и права, а разделы печатает фронт
(в том числе страницу печати, из которой делается PDF). Так состав разделов живёт в одном
месте, а не в двух.

## Энциклопедия

Энциклопедия целиком статическая: страницы печатаются на сборке из `web/content/*.json`,
сервис в этом не участвует и своих эндпоинтов под неё не имеет.

```
/encyclopedia                       корень: три раздела
/encyclopedia/arcanum/{1..22}       аркан: значение, в позициях, сочетания, ссылки
/encyclopedia/position/{key}        позиция матрицы (20 ключей разделов + 17 позиций)
/encyclopedia/combination/{a}-{b}   сочетание двух арканов, a < b — 231 страница
/encyclopedia/chakra/{key}          7 чакр
```

Итого статических страниц энциклопедии: 22 + 37 + 231 + 7 + 1 = 298.

Запись аркана в `web/content/arcana.json`:

```json
{ "n": 14, "slug": "temperance", "title": "Умеренность", "roman": "XIV",
  "matrix_number": 14, "short": "одна фраза для отчёта",
  "keywords": ["умеренность", "мера", "…"],
  "meaning": "3–5 абзацев",
  "in_positions": { "character": "как читается в характере", "money": "…" },
  "plus": ["…"], "minus": ["…"],
  "combinations": [{ "with": 3, "href": "/encyclopedia/combination/3-14", "short": "…" }],
  "seo": { "title": "…", "description": "…", "queries": ["14 аркан", "…"] } }
```

Перелинковка обязательна: из каждой позиции отчёта — ссылка на аркан; из аркана — на все его
сочетания и на позиции, где он встречается; из сочетания — на оба аркана. Тупиков быть не должно.

## Админка

Признак админа — почта из `ADMIN_EMAILS` (по умолчанию `snborodaenko@mail.ru`), а не колонка в
`users`: схема без миграций, и новое поле заставило бы пересоздавать таблицу вместе с платежами.
`python -m app.schema ensure` создаёт этого пользователя, если его нет, с паролем из
`ADMIN_PASSWORD` — поэтому после чистки базы админ существует всегда. Ветка `/admin/*` только
читает; посторонним отвечает 404, а не 403: существование админских адресов знать незачем.
`GET /auth/me` отдаёт `is_admin` — по нему фронт показывает ссылку, но доступ решает апстрим.

## Мок-оплаты

`POST /api/payments/mock` всегда отвечает успехом. Если пользователя с такой почтой нет —
создаётся автоматически (пароль генерируется, возвращается токен), поле `autoregistered: true`.
Сайт этой ветки не использует: форма оплаты спрашивает пароль рядом с почтой и регистрирует
аккаунт до платежа, поэтому автосоздание остаётся только для прямых запросов к api.

**Токен выдаётся только вместе с автосозданием аккаунта.** Для известной почты приходит
`token: null` и `requires_login: true` — тариф начисляется владельцу, но доступ он получает
только своим паролем. Иначе достаточно знать чужую почту, чтобы «оплатить» и прочитать
чужие матрицы вместе с датами рождения.
Настоящий провайдер подключается позже за тем же интерфейсом; в ответе всегда есть
`payment_id`, чтобы фронт не переписывать.


## Раскладка деплоя — решено

Фронт работает **node-сервером Next.js (standalone) на той же машине, что FastAPI**, а не
статикой в бакете. Замер: node со всеми 5 856 предрендеренными страницами занимает 95 МБ,
статика `_next` весит 1,4 МБ — виртуалка остаётся лёгкой.

Причина отказа от статического экспорта:

- BFF обязан обрабатывать запрос, чтобы поставить httpOnly-куку; Object Storage кода не
  выполняет и `Set-Cookie` по телу запроса сформировать не может;
- предрендеренная страница отчёта содержит тексты всех платных разделов — их видно в
  исходнике, не заплатив. Пока страницу печатает сборка, иначе быть не может: она не знает,
  кто её откроет.

Следствия, обязательные к исполнению:

1. `output: "export"` не используется. `SITE_EXPORT` и всё, что от него зависит, удаляется.
2. `trailingSlash` не нужен: node отдаёт и `/path`, и `/path/`. Плоские `<a href>` перестают
   быть проблемой.
3. `deploy.sh` собирает standalone-артефакт и перезапускает службу, а не заливает каталог в
   бакет. В бакет и CDN уезжает только `_next/static` и картинки.
4. Платные разделы рендерятся **на запрос** (`dynamic = "force-dynamic"` для `/report` и
   `/matrices/[id]`), их тексты не попадают в предрендеренный HTML. На запрос печатаются и
   страницы, где цена — предмет договора: `/`, `/pay/[tariff]`, `/oferta` (прайс живёт в базе).
   Энциклопедия и 5 544 матрицы остаются статическими, SSG сохраняется; цену в их прозе
   заменяет живой клиентский провайдер через BFF `GET /api/tariffs`.
5. Сессия — только httpOnly-кука `destiny_session`, выставляемая BFF. Ни один тест и ни один
   компонент не имеет права читать токен из JavaScript.
6. `GET /auth/me` описывает доступ правами, а не тарифом: `access.scopes`, `can_store`,
   `unlimited`, `until`, `matrices_used`, `matrices_limit`. Поля `tariff` больше нет — фронт,
   который его читал, показывал оплатившему «не оплачен» и шесть разделов. `matrices_limit`
   считается по правам (`null` — без ограничения), а не берётся из тарифа.
7. Открыт ли разбор конкретной матрицы, решает апстрим (`unlocked` в `GET /matrices/{id}`).
   Фронт этот вывод только печатает: правила прав в двух местах разошлись бы. Кабинету нужен не
   только факт, но и вид доступа, поэтому строки списка несут `access`: `forever` — куплена
   бессрочным правом, `subscription` (+`access_until`) — открыта, пока действует срочное,
   `locked` — закрыта и предлагается к выкупу.
8. Список тарифов BFF не знает: он проверяет форму кода, существование — апстрим по базе.
   Захардкоженный список в BFF уже ломал оплату — новые тарифы отбивались как «неизвестный».

## Браузерных тестов в наборе нет

Selenium выпилен целиком: набор проверял устаревшие тарифы и оставлял за собой профили Chrome.
Проверка собранного сайта — `npm run check`: она сама поднимает сервер и читает страницы,
которые печатаются на запрос.
