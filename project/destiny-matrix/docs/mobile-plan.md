# Мобильное приложение: следующий этап

План будущего Android-приложения на React Native + Expo. Обновлён 08.11.2026 по текущему коду:
мобильная реализация не начата, каталога `mobile/` нет. Документ описывает оставшуюся работу и не
является разрешением начать её.

Языки, домены, API и PDF описаны в [runtime-localization.md](runtime-localization.md), продукты и
цены — в [payments.md](payments.md), индивидуальные разборы — в
[individual-reading.md](individual-reading.md).

## Готовность

Большой рефакторинг перед стартом не нужен: расчёт и словари уже переносимы, API уже выдаёт
Bearer-токен. Нужны четыре небольшие доработки сервера до мобильного кода и пятая — провайдер
Google Play — параллельно с приложением. Со стороны владельца — аккаунт разработчика на ОАЭ.

| Область | Состояние на 08.11.2026 | Что нужно до мобильного кода |
|---|---|---|
| расчёт и словари | переносимы, без Node и Next (замер ниже) | тест-сторож границы общего слоя |
| авторизация | API принимает `Authorization: Bearer`; BFF берёт токен только из cookie | токен из заголовка `X-Arcana-Session` в BFF и выдача токена приложению |
| платные тексты | собираются в Next из корпуса; часть уже отдаётся JSON | JSON бесплатной части разбора и статей энциклопедии |
| аккаунт | вход, регистрация, сброс, смена пароля и почты, уведомления есть | удаление аккаунта через 30 дней: в API его нет |
| оплата | Т-Банк только у профиля `.ru`; у `.com` провайдеров нет | схема по регионам решена; аккаунт разработчика на ОАЭ и провайдер `google_play` — параллельно |
| адрес сервера | `.ru` и `.com`; переезд на `.com` идёт ([domain-migration.md](../../../tools/seo/domain-migration.md)) | решено: приложение ходит в `.com`; адрес — конфигурация сборки |
| окружение | `~/Android` на месте: JDK 17.0.20.1, SDK 35/36, Maestro | сверить версии с выбранным Expo SDK |

## Общий TypeScript-слой

Общий код остаётся в `web/lib` и подключается в Metro из того же репозитория, без копирования в
`mobile/` и без переноса в отдельный пакет. Переносить каталог стоит, только если сторож границы
начнёт мешать.

Замер 08.11.2026: `matrix`, `yearMatrix`, `yearLinks`, `pair/engine`, `pairLinks`,
`individualLinks`, `matrixMap`, `i18n/format`, `contentReader` собираются `rolldown --platform
neutral` в один файл 517 КБ без внешних импортов. Это проверка сборщиком, а не Metro/Hermes.
Из новых API JS используется только `toLocaleString`.

| Переносимо | Только для веба |
|---|---|
| расчёт даты, года, месяца, пары: `matrix.ts`, `yearMatrix.ts`, `pair/engine.ts`, `pair/spheres.ts` | чтение корпуса через `node:fs`: `content.ts`, `pair/corpus.ts` и всё, что их импортирует — `sections.ts`, `sectionReadings.ts`, `positionArcanum.ts`, `related.ts`, `character.ts`, `combinationReading.ts`, `roleContent.ts`, `individualCardLinks.ts`, `sitemapEntries.ts` |
| модели виджетов связей: `individualLinks.ts`, `pairLinks.ts`, `yearLinks.ts` | Next: `i18n/request.ts`, `siteProfile.server.ts`, `tariffs.server.ts`, хуки на `next/navigation` |
| словари `i18n/dict/*`, `i18n/format.ts`, `plural.ts`, `contentReader.ts` (`ContentSource`) | браузер: `api.ts` и `errors.ts` (`@sentry/browser`, DOM), `storage.ts`, `analytics.ts`, `metrikaClient.ts`, `netwatch.ts` |
| цены и заказ: `individualPricing.ts`, `individualOrder.ts`, `tariffs.ts` | схемы и вёрстка: `components/**` (DOM SVG и CSS) |

- `matrix.ts` тянет все словари через `i18n/index.ts` (41 файл). Для приложения это лишний, но не
  платный объём; дробить не нужно, пока размер бандла не станет проблемой.
- `chakraReadings.ts`, `encyclopedia.ts`, `materialKarma.ts`, `individualExamples.ts` статически
  импортируют корпуса от 1,2 до 9,5 МБ, в том числе платный `chakra-personal.json`. В приложение
  они попадать не должны.
- `settings/public.ts` читает `process.env.NEXT_PUBLIC_*` с запасными значениями: в Metro
  переменные пусты, расчёт работает на значениях по умолчанию.

**Сторож границы.** Vitest-тест собирает входной файл общего слоя с `platform: neutral` и падает
на импорте `next/*`, `node:*`, `react-dom`, `@sentry/*` или JSON из `web/content/`. Без него
очередная правка сайта молча утащит `fs` или платный корпус в мобильный бандл.

## Сеть и авторизация

Приложение ходит в BFF сайта (`https://<домен>/api/...`), а не в FastAPI: API не публикуется в
интернет, а BFF добавляет язык, `X-Arcana-Site-Origin` и проверку прав к платным текстам.

| Что есть | Где |
|---|---|
| JWT на 30 дней, гаснет при смене пароля (отпечаток пароля и `auth_version`) | `api/app/security.py`, `api/app/deps.py` |
| BFF читает токен из cookie в одном месте | `sessionToken()` в `web/app/api/_lib/upstream.ts:35` |
| вход и регистрация прячут токен в httpOnly-cookie, наружу — только `authenticated` | `forward(..., { capture: true })` там же |
| ошибки `detail` на языке запроса и `messages` с переводами | `api/app/http_errors.py` |

Нужно:

1. `sessionToken()` берёт токен из заголовка `X-Arcana-Session`, если cookie нет. Все маршруты BFF
   и `web/app/_lib/access.ts` получают токен через неё, поэтому правка одна. Не `Authorization`:
   тестовый контур закрыт Basic Auth, а он занимает тот же заголовок. Свой заголовок одинаков во
   всех окружениях; к FastAPI BFF по-прежнему передаёт `Authorization: Bearer`.
2. Отдельный маршрут входа для приложения возвращает токен в теле, веб-вход не меняется.
   Хранить токен в защищённом хранилище устройства. Заголовок «я мобильное приложение» доверия
   не даёт и не нужен: токен выдаётся за верные почту и пароль.
3. Выход на устройстве — удаление токена; «выйти везде» уже есть через смену пароля.

**Домен приложения — `.com`** с первого выпуска, независимо от сроков Release 2 переезда домена:
production — `https://arcana-sense.com`, test — `https://test.arcana-sense.com`. Адрес — значение
конфигурации сборки, а не константа, и не меняется при смене языка.

- База, аккаунт и права общие: купленное на `.ru` открывается в приложении.
- Т-Банка у профиля `.com` нет, но приложению он и не нужен: в России покупают на сайте, за рубежом
  — через Google Play. Подключение `google_play` добавляется в `payments` профиля `.com`.
- Письма сброса пароля и подтверждения почты ведут на домен запроса, то есть на `.com`; там же
  `/.well-known/assetlinks.json` для App Links.
- Документы приложения — международный юридический профиль `.com`.

Для Android-эмулятора хост доступен как `10.0.2.2`; это имя с портом нужно явно добавить в
`hosts` локального профиля `SITE_PROFILES`. Открывать все hosts не нужно.

## Контент

Корпус не помещается в приложение целиком и содержит платные тексты: `content/ru` 22 МБ,
`content/en` 15 МБ, `content/pair-chakras` 41 МБ, `content/matrices.json` 11,6 МБ.
Тексты отдаёт сервер, приложение кэширует публичное.

| Данные | JSON уже есть |
|---|---|
| полный разбор оплаченной даты | `GET /api/sections?m=<id>` |
| закрытые разделы без текстов (превью) | `GET /api/sections?preview=locked&slug=` |
| пара: превью, оплаченные сферы, сохранённый разбор | `/api/pair/preview`, `/api/pair/units`, `/api/pair/reading-units` |
| значения арканов года | `/api/year-meanings` |
| индивидуальные разборы: список, статья, PDF | `/api/individual-readings`, `…/[id]/open`, `…/[id]/pdf` |
| сохранённые даты и пары, уведомления, тарифы | `/api/matrices`, `/api/readings`, `/api/notifications`, `/api/tariffs` |

Нет JSON:

- **бесплатная часть личного разбора.** Сейчас её рисует сервер на `/report`, а
  `/api/sections?slug=` без оплаты отвечает только подписчику;
- **статьи энциклопедии.** Около 50 маршрутов `/encyclopedia/**` рисуются сервером, JSON-ручки
  нет. Нужна одна ручка по адресу страницы сайта: `/api/content?path=/encyclopedia/arcanum/5`.
  Тогда ссылка из письма, «поделиться» или поисковика ведёт приложение к тексту по тому же пути, и
  отдельной карты маршрутов для приложения нет.

Страница сайта и ручка приложения берут статью из одной функции `article(path)`: страница рисует из
неё HTML, ручка отдаёт результат как есть, без своей логики. Сломается сборка статьи — сломается и
сайт. Отдельно приложение может сломаться только в тонкой обёртке ручки, и её сторожат тесты.

**Тесты ручки** (Vitest, вызов `GET(new Request(...))` напрямую, как в
`app/api/pair/units/route.test.ts`):

- по всем адресам энциклопедии из sitemap на обоих языках: ответ 200, текст не пустой;
- по тем же адресам ответ совпадает с `article(path)`, который рисует страница;
- неизвестный адрес — 404; закрытая статья без входа приходит без платного текста;
- то же для бесплатной части личного разбора.

Тип ответа приложение берёт из того же `web/lib`: переименованное на сервере поле роняет `tsc`
при сборке приложения. Отрисовку полученного текста на экране проверяют тесты компонентов
приложения и Maestro.

Не превращать синхронный доменный слой в асинхронный ради сети: загрузка статьи и выбор из уже
загруженных данных — разные операции.

**Без сети:** публичные статьи и купленные разборы доступны после первого открытия, PDF — после
скачивания. Когда сеть появляется, приложение перепроверяет права: потерянный доступ (возврат
денег, конец подписки) убирает купленное из кэша.

## Оплата и магазины

Сейчас на сайте: разовые `single` и `pair`, подписка `month` на 3 месяца, индивидуальный разбор по
составу заказа. Провайдер выбирает профиль домена, не язык: `.ru` — Т-Банк, `.com` — нет.
Международные платежи на сайте планируются через Робокассу; пока её нет, иностранец не может
заплатить нигде. Google Play в приложении — первый способ оплаты для него.

### Схема по регионам

Регион — страна аккаунта Google Play, её отдаёт библиотека оплаты (`getBillingConfig`). Не IP и
не язык: язык по-прежнему не выбирает способ оплаты.

| Страна аккаунта Google Play | В приложении | Где платят |
|---|---|---|
| Россия, Беларусь | только уже купленное; кнопок и ссылок «купить на сайте» нет | на сайте, любым способом сайта |
| остальные | покупка через Google Play Billing | в приложении |

- Для России исключение есть: с 02.08.2022 требование платить через Google Play Billing «не
  применяется к разработчикам приложений, принимающих платежи от пользователей в России»
  ([Google](https://support.google.com/googleplay/android-developer/answer/11950272?hl=en)). Значит,
  российскому аккаунту приложение может продавать своей оплатой — Т-Банком через страницу банка с
  возвратом по deep link (чек `/api/payments/receipt` уже есть). Решение — в «Вопросах к
  владельцу»; до него в таблице выше осталась схема «только купленное».
- Вне России правило в силе: цифровые товары — только через Google Play Billing, ссылок на
  внешнюю оплату нет.
- Покупка из любого источника открывает права в нашей базе: аккаунт и права общие для сайта и
  приложения.

### Что нужно для Google Play Billing

С 26.12.2024 Google бессрочно остановил продажи для разработчиков со счётом выплат в российском
банке: платные покупки и подписки не проходят, можно публиковать только бесплатное
([Google](https://support.google.com/googleplay/android-developer/answer/15685001?hl=en)).
ОАЭ в списке стран регистрации продавца, выплаты в USD или EUR
([Google](https://support.google.com/googleplay/android-developer/answer/9306917?hl=en)).

| Что | Кто |
|---|---|
| новый Gmail только под разработку; личный аккаунт разработчика (взнос $25 один раз; паспорт и карта на имя владельца, [Google](https://support.google.com/googleplay/android-developer/answer/6112435?hl=en)); платёжный профиль продавца на ОАЭ как физлицо, выплаты на счёт Mashreq. Страну платёжного профиля Google не меняет — регистрироваться сразу на ОАЭ, существующий нидерландский профиль не использовать | владелец |
| продавец в приложении для иностранцев — этот человек или компания, а не российское ИП: своя оферта и политика конфиденциальности приложения | владелец; тексты — мы |
| товары в консоли Google и цены в валютах (таблица ниже) | владелец в консоли; состав — мы |
| тестировщики лицензий и закрытый тест: покупки без списания денег | владелец в консоли |
| библиотека оплаты в приложении; выбор экрана по стране аккаунта | код |
| провайдер `google_play` на сервере | код |

**Продавец — ОАЭ.** Счёт выплат Google должен быть в стране платёжного профиля
([Google](https://support.google.com/googleplay/android-developer/answer/7161426?hl=en)), адрес
профиля — реальное место жительства. Из стран, где владелец живёт и имеет счёт, подходит только ОАЭ.

- Google торговую лицензию не требует: для покупателя продавец — сам Google (договор разработчика
  с 05.02.2024), от личного аккаунта он ждёт паспорт и банковский счёт.
- Закон ОАЭ требует разрешения на самостоятельный доход, но торговая лицензия компании не нужна —
  хватает разрешения фрилансера: Dubai e-Trader 1 070 AED в год или фриланс-лицензия DMCC
  («software developer»). Подходящий вид деятельности уточнить в DMCC или департаменте экономики
  Дубая.
- Разрешение оформить при доходе от ~$100–250 в месяц после комиссии Google (оно стоит около $290 в
  год) или раньше, если банк спросит о происхождении денег. Корпоративный налог начинается с
  1 млн AED выручки и здесь не важен.

**Провайдер `google_play`** — пятая серверная доработка:

1. Заказ создаётся на сервере до оплаты, как сейчас с Т-Банком: покупка открывает именно эту дату,
   пару или индивидуальный заказ.
2. Сервер проверяет покупку через Google Play Developer API с ключом сервисного аккаунта.
3. Выдаёт права и подтверждает покупку в Google; неподтверждённую в течение 3 дней Google
   возвращает сам.
4. Уведомления Google (RTDN через Pub/Sub): возврат снимает права; продление подписки продлевает
   доступ на следующие 3 месяца; отмена оставляет доступ до конца оплаченного срока; окончание
   закрывает его.

Комиссия Google — 15 % на первый миллион долларов в год в программе для малых разработчиков.
НДС покупателей из ЕС Google начисляет и платит сам, удерживая его из выплат
([Google](https://support.google.com/googleplay/android-developer/answer/138000?hl=en-GB)). В консоли
включить «Default price includes tax»: тогда покупатель в ЕС видит ровно €5 и €8, а НДС
вычитается из них; без галочки Google добавит налог сверху.

### Товары

Базовая валюта — евро; покупатель платит в своей валюте, Google пересчитывает от базовой цены.
Можно ли получать выплаты в ОАЭ в евро (на счёт Mashreq в EUR), видно при создании профиля
продавца; если Google платит в долларах, банк конвертирует.

| На сайте | В Google Play | Цена |
|---|---|---|
| `single` — 390 ₽ навсегда | разовая покупка | €5 |
| `pair` — 390 ₽ навсегда | разовая покупка | €5 |
| `month` — 590 ₽, 3 месяца без автопродления | подписка на 3 месяца **с автопродлением** | €8 за 3 месяца |
| индивидуальный разбор | фаза 2: 10 товаров по числу разборов (ниже) | отдельное решение |

Подписка в приложении продлевается автоматически, на сайте — нет. Отсюда:

- условия продления показываются до покупки, отмена — в Google Play, не у нас;
- кабинет на сайте и в приложении показывает подписку из Google иначе: «продлится автоматически,
  управлять — в Google Play» вместо «закроется через 90 дней»;
- права те же, что у `month`: все разборы обоих продуктов, хранение без лимита.

Индивидуальный разбор — цифровой товар, за рубежом он продаётся через Google так же, как
остальные. В фазе 1 его в приложении нет: ни статьи, ни заказа, ни товаров.

**Конструктор и товары (фаза 2).** В приложении в заказе не больше 5 разборов любых видов (на сайте — до 10
каждого вида). Составов получается 55, но цена зависит только от числа разборов, поэтому товаров
Google 10. Состав хранит наш заказ на сервере, Google списывает сумму за количество. Любой заказ —
одна покупка: одно окно оплаты, одно списание.

| Разборов | Товар «обычный»: уже куплено 0–2 | Товар «постоянный»: уже куплено 3 и больше |
|---|---|---|
| 1 | 1 990 ₽ | 1 190 ₽ |
| 2 | 2 990 ₽ | 2 380 ₽ |
| 3 | 3 590 ₽ | 3 570 ₽ |
| 4 | 4 780 ₽ | 4 760 ₽ |
| 5 | 5 970 ₽ | 5 950 ₽ |

- Цены те же, что на сайте: `quote()` в `web/lib/individualPricing.ts` и `price()` в
  `api/app/individual_orders.py`. Лестница считается заново в каждом заказе; скидка постоянного —
  после трёх оплаченных разборов всего (`bought()` в `api/app/individual_orders.py:64`).
- Какой из двух товаров показать, решает сервер по `bought` из `/api/individual-orders/terms`.
- Рубли в таблице — уровни сайта. Цены в евро для фазы 2 — отдельное решение.
- Товары и цены в валютах создаются скриптом через API Google, не руками в консоли.
- Тест: цены 10 товаров совпадают с `quote()` для 1–5 разборов при `bought` 0 и 3; при изменении
  таблицы `prices` тест показывает, какие товары переоценить.

**Возвраты.** В Google человек сам возвращает деньги в первые 48 часов, позже — через разработчика
([Google](https://support.google.com/googleplay/answer/15574908?hl=en)); автор к этому
времени мог начать писать. Уведомление о возврате снимает заказ, работа может пропасть — деловой
риск, а не блокер. На сайте возвраты по нашей оферте.

Возврат из банка без cookie на сайте уже решён: `/api/payments/receipt` показывает исход по номеру
заказа. Тот же механизм годится для возврата в приложение по deep link.

Google Play требует удаление аккаунта из приложения и по веб-ссылке, если в приложении можно
зарегистрироваться. В API удаления нет — схема ниже.

### Удаление аккаунта: через 30 дней

Google Play требует путь удаления в приложении и рабочую веб-ссылку, где удаление запрашивают без
приложения; запрос выполнить «в разумно короткий срок». Часть данных можно хранить по законным
причинам — безопасность, защита от мошенничества, требования закона, — если это сказано в политике
конфиденциальности ([Google](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en)).
Отсрочку Google прямо не упоминает; 30 дней совпадают со сроком уничтожения данных после отзыва
согласия по ч. 5 ст. 21 152-ФЗ, где хранение допускается, если его требует договор или закон —
это и есть платёжные записи.

1. «Удалить аккаунт» в приложении и на сайте ставит `users.deletion_requested_at` и увеличивает
   `auth_version`: все сессии на всех устройствах гаснут сразу. На почту уходит письмо «аккаунт
   будет удалён ДД.ММ».
2. Вход в течение 30 дней показывает «аккаунт будет удалён ДД.ММ — восстановить?»; восстановление
   снимает отметку.
3. Через 30 дней шаг ежедневной чистки (`api/app/sweep.py`) удаляет аккаунт.

| Данные | Что делаем |
|---|---|
| почта, пароль, даты рождения, сохранённые даты и пары, индивидуальные разборы, PDF | удаляем |
| платежи и чеки | обезличиваем: остаются сумма, дата, тариф и номер заказа, без почты и дат рождения — платёжные записи нужны для учёта |

Строку `users` не удалять: платежи и покупки привязаны к ней каскадом (`cascade="all,
delete-orphan"` и `ondelete="CASCADE"` в `api/app/models.py`) и исчезли бы вместе с ней. Вместо
этого обезличить саму строку — почта `deleted-<id>@invalid`, пароль сброшен — и удалить сохранённые
даты, пары и индивидуальные разборы.

Работа: поле в `users` через аддитивное обновление схемы, ручка, письмо, экран восстановления и шаг
чистки.

## Каркас приложения

Предварительная структура, ещё не создана:

```text
mobile/
  app/                 экраны и маршрутизация
  components/          React Native-компоненты, схема матрицы на react-native-svg
  native/              защищённое хранилище, deep links, будущий биллинг
  flows/               сценарии Maestro
  assets/
  app.config.ts
  eas.json
  metro.config.js      watchFolders → ../web/lib
  package.json
```

Сайт и приложение используют одни технические ключи, расчёт и словари, но свои компоненты.
Схемы матрицы, пары и года (`Octagram`, `LinksMap`, `GoldScheme`) — DOM SVG с CSS; в приложении
их нужно нарисовать заново, геометрию (`yearGeometry.ts`, `routes.ts`) можно вынести в общий слой.

Deep links: пути уже с языком (`/ru/…`, `/en/…`), поэтому ссылка из письма или после оплаты
однозначно задаёт язык. Для App Links нужен `/.well-known/assetlinks.json` на `.com`.

## Порядок работ

**Фаза 1** — все экраны из таблицы выше, кроме индивидуальных разборов: в кабинете нет вкладки
индивидуальных разборов, в приложении нет их заказа и товаров Google для них.
**Фаза 2** — индивидуальные разборы нативной статьёй со схемами, вкладка в кабинете, конструктор
заказа до 5 разборов и 10 товаров Google.

Логика переиспользуется, интерфейс пишется заново. Объём веба без админки и SEO-лендингов: фаза 1
— около 14,5 тыс. строк (энциклопедия 4,8 тыс., матрица и разбор 3,2 тыс., кабинет 2,3 тыс., оплата
2,0 тыс., совместимость 1,0 тыс., общие элементы 1,2 тыс.), фаза 2 — ещё 1,5 тыс. Самое тяжёлое
в фазе 1 — схемы на react-native-svg, около 25 видов статей энциклопедии и оплата Google Play.

0. **Подготовка сервера и веба** (до `mobile/`): `X-Arcana-Session` в BFF и мобильный вход; JSON бесплатной
   части разбора и статей энциклопедии через общую `article(path)` с тестами ручки по всем адресам
   sitemap; удаление аккаунта через 30 дней с обезличиванием платежей; сторож границы общего слоя.
   Проверки — Vitest и `api/tests`. Параллельно владелец заводит новый Gmail и личный аккаунт
   разработчика с профилем продавца на ОАЭ.
1. Каркас, калькулятор и карта на Android-эмуляторе: числа совпадают с вебом на обоих языках.
   Адрес API — `.com` из конфигурации сборки.
2. Энциклопедия, прогноз года, совместимость: доставка статей, кэш, отсутствие сети.
3. Вход, кабинет без вкладки индивидуальных разборов, PDF; российская схема «купленное на сайте».
4. Провайдер `google_play` и экраны покупки `single`, `pair`, `month` для зарубежных аккаунтов.
5. Закрытый тест фазы 1 — обязательное условие публикации, правила в разделе «Закрытый тест».
   Разработку не блокирует; к выпуску добавляет минимум три недели: 14 дней теста и проверка
   Google, обычно до 7 дней.
6. Публикация сначала с российской схемой «купленное на сайте»; покупки Google Play включаются,
   когда магазин их проверит. Публикация — отдельное согласование.
7. Фаза 2: индивидуальные разборы — статья, вкладка в кабинете, конструктор и 10 товаров Google.

Для RN-компонентов — `jest-expo` и `@testing-library/react-native`, для сценариев — Maestro, для
визуальной проверки — снимки через `adb`. На каждом экране: загрузка, ошибка API, нет сети,
истёкшая сессия, нет платного доступа, оба языка. Снимки показывают обрезанный текст и вёрстку,
но не заменяют проверку поведения. Локальный стенд — мок-оплата и `MAIL_TO_LOG=1`; выкладка веба
по-прежнему по [release-process.md](release-process.md).

### Закрытый тест

Личный аккаунт разработчика, созданный после 13.11.2023, не может опубликовать приложение для всех,
пока не проведёт закрытый тест ([Google](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)):

- на момент заявки на публикацию в тесте не меньше 12 тестировщиков, и каждый состоит в нём
  непрерывно последние 14 дней; вышедший раньше не засчитывается, новому человеку 14 дней
  отсчитываются заново;
- до этого публикация для всех и предрегистрация закрыты;
- Google смотрит на активность: слабое использование — причина отказа и повторного круга; в заявке
  спрашивают, как шёл тест, какие были отзывы и что исправили.

Тестировщики — живые люди с Android и Gmail: друзья, родные, активные пользователи сайта,
сообщества взаимного тестирования. Зовём 14–15 человек с запасом. Минимум от каждого:

1. записаться по приглашению и установить приложение;
2. не выходить из теста и не удалять приложение все 14 дней;
3. открывать его несколько раз за две недели: посчитать матрицу, почитать статью;
4. по возможности оставить пару отзывов.

Владелец собирает адреса Gmail к концу разработки фазы 1.

## Вопросы к владельцу

- **Покупки для российских аккаунтов в приложении.** Google разрешает в России своей оплатой
  (раздел «Схема по регионам»). Варианты: продавать Т-Банком через страницу банка или оставить
  «только купленное». Если продавать — подключение `tbank` разрешается и профилю `.com`, а покупка
  идёт по российской оферте ИП, не по международной.
