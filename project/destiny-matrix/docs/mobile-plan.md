# Мобильное приложение: следующий этап

План будущего Android-приложения на React Native + Expo. Обновлён 26.09.2026:
предварительная локализация веба выполнена, мобильная реализация не начата.
Настоящий документ описывает оставшуюся работу и не является разрешением начать её.

Текущая архитектура, языки, домены, API и PDF описаны только в
[runtime-localization.md](runtime-localization.md). Здесь нет отдельной схемы локализации.

## Что уже подготовлено

| Прежняя задача | Текущее состояние |
|---|---|
| язык во время работы приложения | явный `forLocale(locale, site?)`, серверный контекст и клиентский `LocaleProvider` |
| оба корпуса в одной сборке | доступны RU и EN, без выбора одного корпуса алиасом сборки |
| язык отдельно от аккаунта и сервера | общий frontend/API/БД; язык не меняет покупки и адрес API |
| чтение контента отдельно от файловой системы | `ContentSource` и `contentReader.ts`; Node-адаптер в `content.ts` |
| язык серверных ответов и писем | `Accept-Language`, `ContextVar`, сохранение языка фоновой операции |
| язык PDF | `ReportJob.locale`, отдельный кэш и `lang` в URL печати |

Это подготовка, а не готовый SDK для React Native. В `web/lib` остаются веб-зависимости,
относительные URL BFF и импорты серверного корпуса; переносить каталог целиком нельзя.
Глобальную изменяемую переменную языка и переключение API по RU/EN не вводить.

## Оставшаяся подготовка

### Общий TypeScript-слой

Выделить расчёт, технические ключи, форматирование, словари и переносимую часть чтения контента.
Сохранить одну реализацию, без копирования файлов в `mobile/`.
Существующий расчёт уже сверяется с Python через `web/lib/matrix.parity.test.ts`.

Перед подключением к Metro проверить зависимости выбранных модулей: `next/*`, `node:fs`,
`process.cwd()`, серверные адаптеры и DOM не должны попасть в мобильный код.
Общий пакет и его границы выбрать на этом этапе, проверив реальный граф импортов.
Платные тексты не включать в открытый бандл приложения.

Для начального экрана нужны небольшие каталоги арканов, позиций, чакр и точек.
Способ доставки полных статей и их кэш — отдельный адаптер. Не превращать весь синхронный
доменный слой в асинхронный только ради сетевой доставки: загрузка и выбор из уже загруженных
данных — разные операции.

### Сетевой контракт и авторизация

Веб сейчас получает httpOnly-cookie через BFF; публичного мобильного механизма входа ещё нет.
До экранов аккаунта нужно выбрать и реализовать поддерживаемый транспорт: endpoint входа,
выдачу/проверку токена, выход и истечение сессии. Мобильный токен хранить в защищённом хранилище.
Не считать произвольный заголовок «я мобильное приложение» доказательством доверия к клиенту.

Адрес API задаётся окружением `dev/test/production` и не меняется при смене языка.
Ошибки используют существующий контракт `detail`/`messages`.
Смена языка должна сохранять сессию, введённые данные, расчёт и состояние навигации;
перемонтирование всего приложения не является обязательным способом перевода.

Для локального Android-эмулятора хост доступен как `10.0.2.2`.
При обращении к веб-BFF это имя с нужным портом необходимо явно разрешить в `SITE_PROFILES`:
текущий allowlist не принимает произвольный Host. Открывать все hosts для этого не нужно.

### Контент, оплата и ссылки

Публичная энциклопедия может кэшироваться на устройстве. Для платного разбора сохраняется
проверка прав общим API. Определить срок и версионирование кэша, поведение без сети,
доступ к ранее полученному PDF и инвалидирование прав.

Мобильный биллинг и зарубежный эквайринг — отдельные решения.
Нельзя наследовать старое предположение «EN бесплатно, RU платно» или выбирать платёжного
провайдера по языку. Подключение магазинов и способы оплаты согласуются перед мобильной
реализацией с проверкой действующих требований соответствующего магазина.
Исследование зарубежного эквайринга — [foreign-acquiring.md](foreign-acquiring.md).

Возврат из браузера после оплаты, восстановления пароля и deep links должен вести к нужному
экрану и сохранять язык. Перед переиспользованием веб-платежей закрыть описанную в основной
статье проблему возврата между `.ru` и `.com`.

## Каркас приложения

Предварительная структура, ещё не создана:

```text
mobile/
  app/                 экраны и маршрутизация
  components/          React Native-компоненты
  native/              защищённое хранилище, deep links, будущий биллинг
  flows/               сценарии Maestro
  assets/
  app.config.ts
  eas.json
  metro.config.js
  package.json
```

Общий слой подключается из того же репозитория. Сайт и приложение используют одни технические
ключи и числовой расчёт, но собственные компоненты отображения. Профили сборок различаются
окружением и, при необходимости, магазином; отдельные RU/EN-базы им не нужны.

## Экраны и проверяемые сценарии

| Экран | Основа на сайте | Ключевая проверка |
|---|---|---|
| калькулятор и карта | `/matrix`, `/matrix/[slug]` | ввод → карта, совпадение чисел с вебом |
| персональный раздел | `/encyclopedia/` — разборы разделов | переход из карты, бесплатный/закрытый/доступный вид |
| прогноз | `/year`, `/year/[key]` | выбор года и переход из карты |
| энциклопедия | `/encyclopedia` | категории и достижимость материалов |
| арканы, чакры, позиции | соответствующие ветки энциклопедии | список → карточка → назад; отсутствующий ключ |
| пересечения и сочетания | позиции × арканы, пары, кармические хвосты | нормализация ключа, ссылки из карты |
| поиск по энциклопедии | отдельный будущий экран | пустой запрос, результаты, отсутствие результатов |
| вход, регистрация, восстановление | `/login`, `/register`, `/forgot`, `/reset` | ошибочные данные, письмо, истечение сессии |
| мои карты | `/matrices`, `/matrices/[id]` | пустой список, сохранение, удаление, лимит |
| аккаунт и покупки | `/account` | права, история, выход |
| покупка и результат | `/pay`, `/pay/done`, `/pay/fail` | мок-оплата, отказ и корректный возврат |
| отчёт и PDF | `/report` | ожидание, получение файла, язык и кэш |
| поддержка | `/support`, `/contacts` | отправка обращения |
| документы | `/privacy`, `/terms`, `/refund` | доступность и правильный профиль |
| настройки | новый мобильный экран | язык, выход, сценарий удаления аккаунта |

Админка остаётся в вебе. Печатная страница, sitemap, robots и SEO-метаданные в мобильный
интерфейс не переносятся; содержимое полезных читателю статей остаётся доступным.

## Проверки и последовательность

1. Общий слой и транспорт: чередование языков, расчёт, авторизация, ошибки, права.
2. Каркас, калькулятор и карта: рабочий поток на Android-эмуляторе.
3. Энциклопедия и поиск: доставка статей, кэш и отсутствие сети.
4. Аккаунт, покупки и PDF: сквозные сценарии с мок-провайдером.
5. Профили магазинов и сборка: отдельное согласование публикации.

Проверки общего слоя остаются в существующем наборе Vitest.
Для RN-компонентов планируются `jest-expo` и `@testing-library/react-native`,
для сценариев — Maestro, для визуальной проверки — снимки через `adb`.
Инструменты и версии уточняются при старте мобильного этапа.

На каждом подходящем экране проверить загрузку, ошибку API, отсутствие сети, истёкшую сессию,
отсутствие платного доступа и оба языка. Экран считается принятым после проверки состояний,
сценария открытия обычным путём и просмотра снимков на обоих языках. Снимки помогают увидеть
обрезанный текст и вёрстку, но не заменяют проверку поведения.

Локальные сценарии используют общий стенд из основной статьи: мок-платежи и `MAIL_TO_LOG=1`.
Проверки и публикация веба остаются в [release-process.md](release-process.md).
Длительные прогоны не повторяются без изменения проверяемого кода.

## Окружение разработки: исторический замер

На 20.09.2026 были проверены Temurin 17.0.20.1 в `~/Android/jdk17`, SDK platforms/build-tools
35 и 36, platform-tools 37.0.1, AVD `pixel` (Pixel 7, Android 15, KVM) и Maestro 2.10.0.
Окружение — `~/Android/env.sh`. Эти версии не являются текущими требованиями будущего Expo:
совместимые Node/JDK/SDK нужно сверить перед созданием проекта.
В том замере Maestro сохранял снимки в `~/.maestro/tests/<дата>/<поток>/takeScreenshot/`.

## Открытые решения

- Граница общего пакета и мобильный транспорт авторизации.
- Объём офлайн-кэша и правила доступа к сохранённым материалам.
- Магазины, биллинг, идентификаторы пакетов, название и иконка.
- Deep links для оплаты, писем и ссылок на материалы.
- Нужны ли push-уведомления и обновления JS/ассетов вне выпуска нативной сборки.
- Состав первого Android-релиза; iOS остаётся следующим отдельным этапом.
