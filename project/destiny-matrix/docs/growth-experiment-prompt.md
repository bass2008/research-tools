# Свободное время агента: Arcana Sense

Промпт для прогона, в котором агенту дают несколько часов свободного времени и просят потратить
их с пользой для владельца. Здесь нет плана: есть цель, контекст, примеры направлений и границы.
Составлен 11.10.2026; числа о текущем состоянии агент перепроверяет сам.

Заполни параметры в начале блока и передай агенту весь блок, либо дай ссылку на этот файл.

Агенты: нет. Всё делаешь сам, без Agent и Workflow.
Каталог прогона: /home/sergey/Personal/research-tools/reports/free-run/<дата>-<номер>/

ЭТО ТВОЁ СВОБОДНОЕ ВРЕМЯ

Следующие шесть часов — твои. Задачи и плана от владельца нет, есть просьба: потрать это время
так, чтобы ему было от этого польза. Что именно делать, решаешь ты. Можно глубоко копать одну
мысль, можно попробовать разное, можно придумать то, о чём владелец не подумал.

Цель у владельца простая — заработать денег легальным путём. У него есть проект Arcana Sense, и
проект почти ничего не приносит. Почему, до конца непонятно: то ли конкуренция, то ли что-то,
чего мы не видим.

Одно условие для любой идеи: делать её будут агенты, а не человек. Владелец готов подписать
договор, пройти проверку личности, подключить платёжную систему. Монтировать ролики, звонить
или вести соцсети руками он не будет.

КУДА МОЖНО СМОТРЕТЬ

Владелец видит четыре направления. Это не план и не обязательный список, а примеры того, что
ему было бы полезно. Возьми одно, несколько или своё.

- Текущий продукт, без трат. Вордстат по нише куплен целиком. Может быть, сайту чего-то не
  хватает, но это не измерено. Например, могут найтись:
  - ключи со спросом, под которые нет статьи;
  - страницы, которые целятся не в тот запрос;
  - расчёты, которые есть у конкурентов, а у нас нет;
  - места, где люди уходят, не дойдя до оплаты;
  - баги, на которые натыкаются посетители.
  Есть ли что-то из этого на самом деле, покажут ошибки, логи, Метрика, Вебмастер и Google.
  Исправлять найденное можно, но только через pull request (см. «Границы»).
- Эксперименты с тем же продуктом, на небольшие деньги. Тот же калькулятор матрицы и
  совместимости: докупить немного выдачи или ключей, чтобы проверить мысль о том, что
  мешает продавать.
- Новые отчёты и калькуляторы. Проект строился, чтобы выпускать их дёшево. Но прошлые замеры
  говорят, что выдача забита. Владельца волнует, стоит ли вообще: два месяца работы ради 500 ₽ в
  месяц не стоят даже хостинга.
- Что-то совсем другое. Если эзотерика занята, может, рядом есть то, что агенты могут делать
  сами и что принесёт деньги.
- Своё. Придумал пятое направление — отлично. Если оно выходит за границы ниже, сначала спроси.

ГРАНИЦЫ

Внутри них делай что считаешь нужным, не спрашивая. Не уверен, можно ли, — спроси заранее.
Хочешь выйти за них — спроси владельца: что и зачем. Пока ответа нет, занимайся другим.

- Код и тексты меняй только через pull request на GitHub — так владелец контролирует продукт.
  Чинить баги, дописывать статьи, делать прототипы можно. Всё идёт в одну ветку прогона, а
  владелец смотрит PR и решает, мёржить или нет. Сам не мёржишь.
- Прод: только смотреть. Ни выкладок, ни перезапусков, ни записи в боевую БД. Тест тоже не
  трогать: на нём приёмка совместимости.
- Наружу ничего не уходит: публикации, письма, регистрации аккаунтов, переобход. Готовое
  описываешь в отчёте одним шагом для владельца.
- Деньги — только XMLRiver, до 100 ₽ за прогон без спроса. Баланс:
    curl "http://xmlriver.com/api/get_balance/?user=$XMLRIVER_USER&key=$XMLRIVER_KEY"
  (ключи — .env в корне research-tools). Остальные траты — предложением с ценой.
- Купленное хранится в semcore.db. Платные таблицы (cache, serp, history, suggest) не
  чистить. Замеры помечать wscore.mark_probe — правила в docs/semcore.md. Запускать всё это
  из основного дерева: wscore открывает базу рядом со своим файлом, а из копии он создаст пустую
  базу и заново купит купленное.
- Рабочее дерево владельца (/home/sergey/Personal/research-tools) не трогать: там ветка
  feature/products и незакоммиченный релиз совместимости. Его код смотри там, только читая.
  Свою ветку прогона отведи от main в отдельной копии:
    cd /home/sergey/Personal/research-tools
    git fetch origin
    git worktree add -b free-run/<дата>-<номер> ../arcana-free-run origin/main
- Коммитить и пушить можно только в эту ветку:
    git push -u origin free-run/<дата>-<номер>
  Сообщение коммита — одна строка. Без amend и force-push.
- Pull request — из ветки прогона в main, один на прогон. В описании по каждой правке:
  - что было не так, с доказательством: что видит посетитель, как воспроизвести, число;
  - что изменено и зачем;
  - чем проверено.
- PR открывается через gh pr create. Если gh нет или он не вошёл в GitHub, спроси владельца. Пока
  ждёшь ответа, запушь ветку, положи текст PR в run.md и дай ссылку:
  https://github.com/bass2008/research-tools/compare/main...free-run/<дата>-<номер>?expand=1
- Hawk — без удалений. Секреты и почты пользователей — не в отчёты.

ТВОЯ ПАПКА

Папка /home/sergey/Personal/research-tools/reports/free-run/ лежит вне git.

- <дата>-<номер>/run.md — для владельца, ведётся с первой минуты:
  - что задумал и почему;
  - что проверяешь;
  - что получилось;
  - что потратил.
  Владелец может заглянуть в любой момент и понять, где ты. Рядом складывай данные и отчёт.
- self/ — для тебя. Пиши туда что угодно: мысли, план, напоминания, незаконченные цели, выводы
  на следующий раз. Структуру выбираешь сам. Это твоя память между сессиями и прогонами: в
  начале прочитай, в конце обнови. Память Claude Code для этого не нужна.

ВРЕМЯ

Засеки старт командой date. run.md обновляй по ходу: если контекст сожмётся или прогон
прервётся, работа продолжится с него. Последние полчаса оставь на отчёт.

В КОНЦЕ

Отчёт-артефакт, форма свободная. В нём должно быть видно:
- что ты попробовал и что из этого вышло;
- что сделал руками: ссылка на PR и что в нём;
- сколько, по-твоему, это может принести и почему ты так думаешь;
- что нужно от владельца;
- сколько потрачено.

Опирайся на данные: у вывода есть число и источник, догадка остаётся догадкой, пока не
проверена. «Ничего не нашёл, и вот почему» — тоже честный результат.
