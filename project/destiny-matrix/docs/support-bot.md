# Поддержка в Telegram

Один бот, живущий целиком в Cloudflare Workers. Клиент пишет боту в личку — сообщение уходит в
тему группы поддержки; ответ, написанный в теме, возвращается клиенту. Наш сервер в этом не
участвует вовсе.

```
клиент ↔ личный чат с ботом
                ↕
       Cloudflare Worker + KV
                ↕
   супергруппа поддержки, тема на клиента
```

## Почему не на нашем сервере

Первая версия жила в `api` и не заработала: **у машины в Yandex Cloud нет связи с Telegram ни в
одну сторону.** Замер 12.09.2026:

| проверка | результат |
|---|---|
| Telegram → наш вебхук | `Connection timed out`, в логах nginx ноль соединений с подсетей Telegram |
| сервер → `api.telegram.org`, IPv4 и IPv6 | не соединяется (`000`, `Network is unreachable`) |
| сайт из-за рубежа | 200 — сервер сам по себе доступен |
| сервер → сеть Cloudflare | 200 |

Firewall тут ни при чём: `ufw` выключен, `iptables` пуст, 443 открыт для `0.0.0.0/0`. Поэтому не
работает ни вебхук, ни long polling с сервера. Узлы Cloudflare видят и Telegram, и нас — бот
переехал туда целиком, а заодно перестал требовать релиза сайта ради правки пересылки.

## Что где лежит

| файл | зачем |
|---|---|
| `infra/cloudflare/worker.js` | весь бот: две ветки пересылки и хранение пары «тема ↔ чат» |
| `infra/cloudflare/worker.test.js` | 10 сценариев, `node --test infra/cloudflare/worker.test.js`, без зависимостей |

Состояние — два ключа в KV (`chat:<id>` → тема, `topic:<id>` → чат), потому что искать надо в обе
стороны. Переписку хранит сам Telegram, дублировать её незачем.

## Включение

1. **Бот.** `@BotFather` → `/newbot` → токен.
2. **Группа.** Создать группу → включить **Темы** (в английском интерфейсе Topics) → добавить
   бота → выдать ему администратора с правом **управления темами**. Без этого права
   `createForumTopic` отвечает отказом — первая причина «ничего не работает».
3. **Cloudflare.** Аккаунт, KV-хранилище, воркер. Переменные воркера: `BOT_TOKEN`,
   `SUPPORT_CHAT_ID`, `WEBHOOK_SECRET`; привязка KV — под именем `THREADS`.
4. **Вебхук** ставится на адрес воркера:

```bash
curl -s "https://api.telegram.org/bot<токен>/setWebhook" \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://<воркер>.workers.dev/","secret_token":"<секрет>","allowed_updates":["message"]}'
```

`chat_id` группы: пока вебхук не поставлен, написать в группе сообщение и вызвать `getUpdates` —
идентификатор приходит в `message.chat.id` (у супергрупп он отрицательный).

Локальные секреты (`~/.config/arcana/telegram.env`, `cloudflare.env`) в репозиторий не попадают.

## Что важно знать

- **Бот не может написать первым.** Пока человек не нажал `/start`, отправить ему нельзя — это
  ограничение Telegram. Поэтому с сайта ведём ссылку на бота, а не собираем контакты.
- **Секрет вебхука обязателен.** Адрес воркера открыт всему интернету, и заголовок
  `X-Telegram-Bot-Api-Secret-Token` — единственное, что отличает апдейт от чужого POST.
- **Воркер всегда отвечает `200`,** даже когда отправка не удалась: на любой другой код Telegram
  повторяет обновление, и одно неудобное сообщение стало бы бесконечным циклом доставки. Причина
  отказа уходит в `console.error` и видна в логах воркера.
- **Копии бота в группе не зеркалятся обратно** — сообщение в теме от `is_bot` пропускается,
  иначе диалог зациклится.
- **Переписка проходит через Cloudflare.** Это сторонний посредник, и токен бота хранится там же.
  Плата за то, что другого сетевого пути к Telegram у нас нет.

## Чего здесь намеренно нет

Deep link с токеном заказа, история переписки в базе, команды модерации, уведомления о платежах.
Почту клиент называет сам, историю показывает Telegram. Если понадобится связь с заказом, воркер
умеет ходить в наш `api` по HTTPS — снаружи сайт доступен.
