# Чем отличаются стенды

Три контура: локальный стенд разработчика, тестовый контур на боевой сборке и прод. Код у них
один, поведение разное — здесь собраны все различия, чтобы не искать их по конфигам.

| | local | test | prod |
|---|---|---|---|
| адрес | `http://127.0.0.1:3000` | `https://test.arcana-sense.ru` | `https://arcana-sense.ru` |
| `APP_ENV` | `dev` | `prod` | `prod` |
| откуда образ | собирается на месте | из реестра, тег `test-<коммит>` | из реестра, тот же коммит после приёмки |
| **хранилище отчётов** | **`local`** | **`local`** | **`s3` → Cloudflare R2** |
| **эквайринг** | **мок** | **тестовый терминал Т-Банка** | **живой Т-Банк** |
| почта | в лог (`MAIL_TO_LOG=1`) | в лог (`MAIL_TO_LOG=1`) | настоящий SMTP |
| счётчик Метрики | выключен | выключен | включён |
| вход на домен | открыт | Basic Auth на nginx | открыт |
| база | своя, чистится свободно | своя | боевая, трогать нельзя |
| порт фронта на машине | 3000 | 3100 | 3000 |
| секреты | `~/.config/arcana/*.env` | `/srv/arcana/.env.test` | `/srv/arcana/.env` |

## Хранилище отчётов: `s3` и `local`

Готовый PDF на проде лежит в Object Storage и отдаётся подписанной ссылкой на час, а на стендах
— в каталоге внутри контейнера, который чистится при запуске приложения и наружу ничего не
уносит.

Переключается переменной `REPORTS_STORE` (`s3` по умолчанию), реализации — в `api/app/store.py`.

С 19.09.2026 прод хранит отчёты не в Yandex Object Storage, а в **Cloudflare R2**: тот же
S3-протокол, другой endpoint (`S3_ENDPOINT`, `S3_REGION=auto`), бакет `arcana-reports`. Причина —
деньги: 65 ₽/мес против бесплатных 10 ГБ и бесплатного исходящего трафика. Код не менялся,
`S3Store` работает с любым S3-совместимым хранилищем.

Зачем разделили: до 19.09.2026 все три контура писали в один боевой бакет, и прогоны e2e
накопили там 8611 файлов на 28 ГБ — при пяти пользователях в боевой базе. Платили за хранение
чужих прогонов.

Что при этом теряется: подписанные ссылки Object Storage и заголовок с именем файла проверяются
теперь только на проде. На стендах их заменяет свой пропуск — JWT на тот же час, маршрут
`GET /api/reports/file?token=…`. Тесты `api/tests/test_store.py` следят, чтобы обе реализации
вели себя одинаково: ключ не уводит за пределы каталога, просроченный пропуск не открывается,
пропуск на печать не годится для файла.

## Эквайринг

| контур | провайдер | деньги |
|---|---|---|
| local | `mock` | не участвуют, оплата подтверждается сразу |
| test | `tbank`, тестовый терминал | не настоящие, карты из [t-bank-test-ac.md](t-bank-test-ac.md) |
| prod | `tbank`, боевой терминал | настоящие |

Провайдер выбирается в `api/app/payments/__init__.py`: берётся заданный в `PAYMENT_PROVIDER`,
иначе первый включённый — сперва Т-Банк, потом мок. Поэтому `MOCK_PAYMENTS=1` в боевом `.env`
ничего не ломает: живой терминал включён и перекрывает мок.

Подробности: [тестовый эквайринг](t-bank-test-ac.md), [приём денег вне России](foreign-acquiring.md).

## Что можно делать где

- **local** — всё: чистить базу, ломать, гонять e2e (`compose/scripts/run.sh`, мок-оплата обязательна).
- **test** — то, чего нельзя на проде: входить в админку, заходить под пользователем, выдавать
  матрицы, доводить покупку до формы банка. Контур для того и живёт.
- **prod** — только чтение. Действия с данными живых покупателей — на тестовом контуре.

Порядок выкладки и приёмки: [release-process.md](release-process.md).
