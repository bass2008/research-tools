# Окружения приложения

Три окружения: local, test и production. В каждом один frontend, один API и одна БД.
Домены `.ru` и `.com` — профили одного приложения; они не отдельные стенды.
Правила языков и переключения описаны в [runtime-localization.md](runtime-localization.md).

| | local | test | production |
|---|---|---|---|
| русский профиль | `http://localhost:3000` | `https://test.arcana-sense.ru` | `https://arcana-sense.ru` |
| международный профиль | `http://127.0.0.1:3000` | `https://test.arcana-sense.com` | `https://arcana-sense.com` |
| Compose-проект | `arcana-localized` | `arcana-test` | `arcana` |
| `APP_ENV` | `dev` | `prod` | `prod` |
| образы | локальная сборка | общий тег `test-<commit>` | общий тег `<commit>` после приёмки test |
| отчёты | `local` | `local` | `s3` → Cloudflare R2 |
| эквайринг | `mock` | тестовый терминал Т-Банка | боевой Т-Банк |
| почта | в лог | в лог | транзакционная почта |
| Метрика | выключена | выключена | отдельные счётчики доменных профилей |
| вход на сайт | открыт | Basic Auth на nginx | открыт |
| БД | изолированный локальный том | `arcana-test_test-api-var` | `arcana_api-var`, прежняя русская БД |
| frontend для nginx | порт 3000 | порт 3100 | порт 3000 |
| конфигурация | `compose/docker-compose.localized.yml` | `/srv/arcana/.env.test` | `/srv/arcana/.env` |

В каждом окружении правила доступа общие для языков: `ALL_FREE_WITHOUT_PAYMENT=0`.
Отдельного бесплатного английского приложения и отдельной действующей английской БД нет.
Старые английские тома сохранены без подключения к общему приложению.

## Локальный стенд

Из корня проекта:

```sh
docker compose -f compose/docker-compose.localized.yml up --build -d
```

Администратор: `snborodaenko@mail.ru` / `123`. API для отладки — `127.0.0.1:8010`.
Остановка без удаления БД — та же команда с `stop` вместо `up --build -d`.
При проверках на этом стенде контейнер API — `arcana-localized-api-1`.

Старые `run-eng.sh` и `run-python-eng.sh` теперь вызывают общий запуск, не создавая
отдельную БД и не включая бесплатность. `docker-compose.full.yml` включает общий локальный стенд.
Состав остальных Compose-файлов — [compose/README.md](../compose/README.md).

## Хранилище отчётов: `s3` и `local`

Готовый PDF на проде лежит в Object Storage и отдаётся подписанной ссылкой на час, а на стендах
— в каталоге внутри контейнера, который чистится при запуске приложения и наружу ничего не
уносит.

Переключается переменной `REPORTS_STORE` (`s3` по умолчанию), реализации — в `api/app/store.py`.

С 19.09.2026 прод хранит отчёты не в Yandex Object Storage, а в **Cloudflare R2**: тот же
S3-протокол, другой endpoint (`S3_ENDPOINT`, `S3_REGION=auto`), бакет `arcana-reports`. Причина —
деньги: 65 ₽/мес против бесплатных 10 ГБ и бесплатного исходящего трафика. Код не менялся,
`S3Store` работает с любым S3-совместимым хранилищем.

Зачем разделили: до 19.09.2026 все три контура писали в один боевой бакет, и прогоны e2e
накопили там 8611 файлов на 28 ГБ — при пяти пользователях в боевой базе. Платили за хранение
чужих прогонов.

Что при этом теряется: подписанные ссылки Object Storage и заголовок с именем файла проверяются
теперь только на проде. На стендах их заменяет свой пропуск — JWT на тот же час, маршрут
`GET /api/reports/file?token=…`. Тесты `api/tests/test_store.py` следят, чтобы обе реализации
вели себя одинаково: ключ не уводит за пределы каталога, просроченный пропуск не открывается,
пропуск на печать не годится для файла.

## Эквайринг и границы окружений

| Окружение | Провайдер | Деньги |
|---|---|---|
| local | `mock` | не участвуют, оплата подтверждается имитацией |
| test | `tbank`, тестовый терминал | тестовые карты из [t-bank-test-ac.md](t-bank-test-ac.md) |
| production | `tbank`, боевой терминал | настоящие |

Таблица относится к RU-профилю. COM во всех окружениях имеет пустой список провайдеров:
оплата недоступна, но купленные права общие. Разрешённые подключения перечислены в
`SITE_PROFILES`; автоматического выбора любого включённого провайдера больше нет.
Локальная переменная `PAYMENT_PROVIDER` лишь формирует подключение RU-профиля.
Правила origin, callback и языка описаны в [runtime-localization.md](runtime-localization.md).

Callback тестового банка направляется на `.ru/api/payments/notify/tbank`, где Basic Auth
отключён только для этого маршрута и старого `/api/payments/notify`. API проверяет подпись.
COM callback банка не принимает; банковский маршрут не должен вести на этот домен.

- Local предназначен для изолированных проверок, мок-оплат и тестовых данных.
- Test предназначен для приёмки обоих доменов, интерфейса и тестового банка.
- Production при диагностике — только чтение; изменения и выкладка требуют разрешения.

Обе тестовые версии выкладывает один `release-test.sh`, обе production-версии —
один `release-prod.sh`. Команды `release-*-eng.sh` перенаправляют в общий релиз,
повторно запускать их вслед за ним не нужно. Полный порядок — [release-process.md](release-process.md).
