# Локализация единого приложения

Основной документ о языках и доменных профилях Arcana Sense. Обновлён 26.09.2026 после
объединения приложения. React Native пока не реализуется; дальнейшие работы — в
[mobile-plan.md](mobile-plan.md).

## Одно приложение, два домена

В каждом окружении один frontend Next.js обслуживает оба домена, обращается к одному API
и использует одну БД. Домен выбирает профиль сайта; язык пользователя — перевод внутри
этого профиля. Язык не выбирает сервер, базу, аккаунт, тариф или права доступа.

| Окружение | Русский профиль | Международный профиль | API и БД |
|---|---|---|---|
| production | `arcana-sense.ru` | `arcana-sense.com` | общие для двух production-доменов |
| test | `test.arcana-sense.ru` | `test.arcana-sense.com` | общие для двух test-доменов, отдельные от production |
| local | `localhost:3000` | `127.0.0.1:3000` | общий локальный API, изолированная БД |

В production оставлена существующая русская БД. По решению владельца перенос английской БД
не нужен: пользователей и покупок там не было. Старый английский том сохранён для отката,
но действующее приложение его не использует. Общий флаг `ALL_FREE_WITHOUT_PAYMENT=0`;
зарубежный эквайринг — отдельная задача, а не условие локализации.

В текущих Compose-файлах сервисы называются `api`, `web`, `browser`; проекты — `arcana`
и `arcana-test`; админские группы — «Основной сайт» и «Тестовый сайт».
Переименование подготовлено локально после релиза `5d7688b`: старые имена `ru-api`/`ru-web`
на сервере сами по себе не означают отдельного русского приложения.
Существующие имена томов БД при переименовании сохраняются.

## Профиль домена

| Профиль | `defaultLocale`: публичный язык | `locales`: выбор пользователя | `legalLocale` |
|---|---|---|---|
| русский | `ru` | `ru` | `ru` |
| международный | `en` | `en`, `ru` | `en` |

Сервер выбирает профиль по `Host` каждого запроса. `SITE_PROFILES` — JSON-массив
профилей, общий для frontend и API. В Compose одна YAML-ссылка передаёт одинаковую конфигурацию
обоим сервисам. Frontend также знает встроенные production-профили; API доверяет только
явно переданному списку. Пример production-профилей:

```json
[
  {
    "origin": "https://arcana-sense.ru",
    "defaultLocale": "ru",
    "locales": ["ru"],
    "payments": [{
      "id": "tbank",
      "provider": "tbank",
      "notificationUrl": "https://arcana-sense.ru/api/payments/notify/tbank"
    }]
  },
  {
    "origin": "https://arcana-sense.com",
    "defaultLocale": "en",
    "locales": ["en", "ru"],
    "legalLocale": "en",
    "metrikaId": 112840069,
    "payments": []
  }
]
```

`origin` — публичный адрес; необязательный `hosts` — точный список разрешённых имён,
включая порты и внутренний адрес печати. Без `hosts` разрешено имя из `origin`.
`verification` содержит подтверждения Google/Яндекса. `indexable` может отключить индексацию;
local/test не становятся индексируемыми даже при ошибочно выставленном `true`.
Неизвестные языки, повторяющиеся hosts и неверные профили отклоняются при запуске.

Изменение профилей требует перезапуска сервиса, но не отдельной сборки для каждого языка.
Прокси должен сохранять исходный `Host`. `X-Forwarded-Host` не выбирает профиль.
Неизвестный host получает HTTP 421 и `noindex`.

`NEXT_PUBLIC_SITE_LANG`, `NEXT_PUBLIC_SITE_URL` и `NEXT_PUBLIC_SUPPORTED_LOCALES` остаются
значениями совместимости для чистых функций и сборочных проверок; они не выбирают профиль
HTTP-запроса. Существующие счётчики Метрики выбираются по домену: RU — `111856670`,
COM — `112840069`; на test/local выключены. Смена языка не меняет счётчик.

## Публичный HTML и выбор посетителя

Индексируемый HTML всегда использует публичный язык домена: `.ru` — русский, `.com` —
английский. Cookie, `Accept-Language` и User-Agent не меняют этот HTML. Правило одинаково
для человека, Googlebot и YandexBot; специальной подмены для ботов нет.

| Запрос | Поведение |
|---|---|
| публичная страница `.com`, даже с русской cookie | английский HTML и английские метаданные |
| публичная страница `.ru` | русский HTML и русские метаданные |
| публичная страница с `?lang=ru` | 308 на тот же URL без `lang`; cookie не записывается |
| личный маршрут `.com/login?lang=ru` | русский интерфейс; выбор сохраняется в cookie |
| личный маршрут `.ru/login?lang=en` | только русский: EN не разрешён профилем |
| local/test | запрет обхода в robots, пустой sitemap, `noindex` |

Canonical, OpenGraph, JSON-LD, sitemap и robots определяются профилем запроса и публичным
языком. Парные индексируемые страницы имеют взаимный `hreflang` с тем же путём на другом
домене и `x-default` на `.com`; у страниц без пары лишней альтернативы нет.
Картинки предпросмотра `/og.png` и `/og-en.png` нейтральны: без цены, числа разделов,
обещаний бесплатности или подписки.

Переключатель в футере международного профиля меняет язык **на том же сайте**:
сохраняет `arcana_locale` на текущем host и вызывает `router.refresh()`.
Обновляются Server Components и клиентские тексты; сохраняются форма, расчёт, сессия и страница.
На русском профиле переключатель скрыт, поскольку разрешён один язык.

При новом открытии публичной страницы сначала приходит HTML языка домена; после гидратации
интерфейс восстанавливает сохранённый выбор. Возможен краткий показ исходного языка.
Язык браузера автоматически не применяется. Между вкладками одного origin выбор синхронизируется.
RSC-ответы интерфейса получают `noindex` и `private, no-store`; внутренние заголовки контекста
перезаписываются middleware. Это изоляция индексируемой версии, а не запрет получить перевод
через работающий интерфейс.

Маршруты `/matrix`, `/account`, `/admin`, `/matrices`, `/pay`, `/report`, `/print`, вход,
регистрация и восстановление пароля сразу учитывают выбор: допустимый `?lang=` → cookie →
язык домена. URL-параметр действует при каждом открытии, а не одноразово.
Принятые ограничения вкладок и запоздавших ответов — [решения 11–12](decisions.md).

## API, аккаунт и данные

Браузер обращается к BFF своего frontend; тот передаёт язык общему API через `Accept-Language`.
Явный язык API-запроса имеет приоритет над cookie в пределах языков доменного профиля.
FastAPI хранит язык запроса в `ContextVar` и возвращает `Content-Language`.
Фоновые операции восстанавливают язык через `using_locale`.

Аккаунт, матрицы и покупки общие. **Сессия браузера между `.ru` и `.com` не переносится**:
cookie принадлежит своему host. На другом домене нужно войти теми же реквизитами — это тот же
аккаунт в той же базе. Смена языка внутри `.com` повторного входа не требует.

- Ошибки API возвращают `detail` на языке запроса и `messages` с переводами. Клиент хранит
  ключ сообщения или `ApiError`: показанная ошибка переводится без повторного POST.
  Неизвестная ошибка без переводов заменяется общим сообщением с HTTP-статусом.
- Списки матриц, история платежей и админские данные перечитываются при смене языка.
  Поля, фильтры, раскрытые формы и согласия сохраняются.
- Новое автоматическое имя матрицы хранится как `title=NULL` и вычисляется на языке запроса.
  Ручные и старые записанные названия не переводятся: происхождение старой строки неизвестно.
- Встроенные названия тарифов переводятся по стабильному ID. Ручные названия, сумма покупки
  и исходный снимок тарифа не переписываются; для отображения есть `display_name`.
- Язык не управляет бесплатностью. `ALL_FREE_WITHOUT_PAYMENT` и соответствующая переменная
  frontend должны быть согласованы для всего окружения.

Юридический профиль определяется доменом отдельно от языка интерфейса. Русский интерфейс
на `.com` показывает русский перевод международного документа, а не российскую оферту.
Админка локализована; значения конфигурации, пользовательские строки и диагностические логи
не переводятся.

## PDF и письма

Задание печати хранит `locale`; кэш PDF и дедупликация учитывают язык.
Готовый файл общий для аккаунта, матрицы и языка на обоих доменах. Ссылки внутри PDF
ведут на профиль публичного языка документа в текущей раскладке: RU → `.ru`, EN → `.com`;
локально и на test выбирается соответствующий локальный или тестовый профиль.
Подпись сервиса использует профиль внутреннего Host печати; это не адрес скачивания файла.
Старый кэш без текущей версии формата пересоздаётся при следующем скачивании владельцем.
Одновременные запросы одной матрицы и языка объединяются в пределах единственного процесса API,
включая фоновый прогрев. HTML ошибки и закрытый разбор не принимаются печатником за готовый PDF.
Аддитивное обновление схемы назначает старым заданиям язык прежней базы.
Платёж сохраняет язык операции в снимке тарифа: callback и письмо используют его независимо
от дальнейших переключений интерфейса. Ссылки писем и адрес печати содержат `lang`.

Общего `SITE_URL` в API больше нет. BFF вычисляет origin по `Host` и перезаписывает
`X-Arcana-Site-Origin`; пользовательский заголовок или `X-Forwarded-Host` его не подменяют.
API сверяет origin с `SITE_PROFILES`. Нельзя отправлять письмо или начинать платёж без
контекста сайта. Заголовок — внутренний контракт BFF/API, а не способ авторизации:
API не публикуется напрямую в интернете.

Регистрация и сброс пароля используют домен текущего запроса и выбранный язык. Письмо
после оплаты восстанавливает эти значения из платежа, в том числе при callback и досверке.
Ссылка локального PDF остаётся на домене запроса; подписанная ссылка S3 не меняется.
`WEB_INTERNAL_URL` — адрес frontend для печати: локально `http://web:3000`, в текущих серверных
Compose — `http://prod-web:3000` и `http://test-web:3000`. Эти имена должны быть разрешены
в `hosts` профиля и различаться в общей сети браузера печати.

Почтовый домен общий: `hello@arcana-sense.com` для связи, `noreply@arcana-sense.com`
для отправки. Почтовая инфраструктура — в [infra/README.md](../infra/README.md).

## Платёжные провайдеры и callbacks

Доступные провайдеры определяет **профиль домена**, а не язык интерфейса:

| Окружение | RU | COM |
|---|---|---|
| production | Т-Банк | нет доступных провайдеров |
| test | тестовый терминал Т-Банка | нет доступных провайдеров |
| local | mock; тестовый Т-Банк только при явной настройке | нет доступных провайдеров |

`payments` — список подключений `{id, provider, notificationUrl}`. Одинаковое подключение
можно явно разрешить нескольким профилям; его определения должны совпадать. Сейчас один
экземпляр каждого провайдера использует свои общие настройки терминала; несколько независимых
терминалов одного провайдера не реализованы. Google Play остаётся будущей интеграцией.

`GET /api/tariffs` возвращает `payment_providers`: только явно разрешённые и настроенные
подключения. Пустой массив означает «На данный момент нет доступной оплаты для вашего региона»
(на английском — соответствующий перевод). Ошибка загрузки API показывается отдельно.
Пустой список не включает бесплатность и не разрешает mock. Смена языка `.com` на русский
не меняет список. Существующий аккаунт и купленные права действуют на обоих доменах.

API проверяет подключение **до** создания покупателя, матрицы или счёта. Можно передать
`provider` — ID из списка; неизвестное или запрещённое значение отклоняется. `/payments/mock`
тоже подчиняется профилю. `PAYMENT_PROVIDER` больше не выбирает провайдера в общем API;
локальные команды используют эту переменную только для формирования RU-профиля.

В JSON-снимке тарифа платежа сохраняются `site_origin`, `locale` и `connection_id`.
Возврат с банка ведёт на исходный origin с `lang`. Повторное использование незакрытого
счёта учитывает подключение, origin и язык. Ручная сверка с другого домена, где подключение
запрещено, возвращает сохранённое состояние без обращения в банк. Досверка и админский
возврат используют подключение самого платежа.

Callback привязан к подключению, отдельно от адреса возврата пользователя:

- production: `https://arcana-sense.ru/api/payments/notify/tbank`;
- test: `https://test.arcana-sense.ru/api/payments/notify/tbank`.

На тестовом `.ru` этот адрес и старый `/api/payments/notify` доступны без Basic Auth;
подлинность подтверждается подписью банка. Соседние URL остаются под паролем. `.com`
банковские уведомления не принимает: открывать там исключение Basic Auth не требуется.
API проверяет соответствие провайдера, подключения, идентификаторов платежа и заказа.
Повторный callback не выдаёт права повторно.

Платежей `.com` не было, миграция для них не предусмотрена. Существующие российские записи
не переписываются: при отсутствии нового снимка подключение определяется по единственному
совпадающему провайдеру. Права и история сохраняются.

## Словари, корпус и React Native

| Задача | Код |
|---|---|
| языки и `Accept-Language` | `web/lib/i18n/selection.ts` |
| профиль и выбор по Host | `web/lib/siteProfile.ts`, `siteProfile.config.ts`, `siteProfile.server.ts` |
| публичный/личный язык | `web/lib/i18n/requestPolicy.ts`, `request.ts`, `web/middleware.ts` |
| язык клиентского дерева | `web/components/ui/LocaleProvider.tsx` |
| сообщения формы | `web/lib/i18n/useMessage.ts` |
| независимый от Node читатель | `web/lib/contentReader.ts`, интерфейс `ContentSource` |
| чтение корпуса в Next | Node-адаптер `web/lib/content.ts` |
| язык API и фоновых операций | `api/app/i18n.py` |

Локализованные модули предоставляют `forLocale(locale, site?)`: отдельные объекты и замыкания
на язык и неизменяемый профиль. Глобального изменяемого «текущего языка» нет.
Сервер передаёт контекст явно, клиент использует `useLocale`. Старые именованные экспорты
привязаны к языку по умолчанию и оставлены для совместимости; новый код страниц должен
использовать явный контекст.

Словарь `D` — публичные интерфейсные строки; `DR` — серверные тексты разбора;
`dict/admin.ts` — отдельный словарь админки. Полные платные тексты нельзя импортировать
в клиентский бандл. Подробности — [решение 10](decisions.md).

Одна сборка содержит `web/content/ru` и `web/content/en`. Технические ключи и английские
URL-slugs одинаковы на всех языках; переводятся заголовки и содержимое. `matrices.json`
общий: числа не зависят от языка, подписи подставляются при чтении.
Набор тем общий; исключения должны быть явными и обоснованными. Поисковые формулировки
собираются отдельно для языка — [semcore.md](semcore.md).

Источники и порядок сборки контента — [content/README.md](../content/README.md).
Редакционные статьи находятся в `tools/seo/content/<lang>/`; нельзя запускать только
базовый `content.build` и считать результат готовым: следующий этап возвращает редакционные
`meaning`, `faq`, `article_sections` и SEO. Старое указание править английские собранные JSON
вручную вместо источников больше не действует.

Для React Native подготовлены явный параметр языка, словари, оба корпуса и `ContentSource`.
Общий пакет, мобильный транспорт авторизации, RN-компоненты и доставка статей ещё не реализованы.
`fs`, Next, cookie, canonical и `hreflang` остаются веб-адаптерами. Адрес API мобильного
клиента не должен меняться при смене языка. Форматирование используется из общего слоя;
совместимость с выбранным мобильным runtime проверяется на мобильном этапе.

## Добавление языка

1. Добавить язык в типы и проверку поддерживаемых языков frontend/API.
2. Подготовить словари, серверные сообщения, форматирование и корпус с теми же ключами.
3. Проверить юридические переводы для нужного профиля, ошибки, PDF и письма.
4. Разрешить язык в `locales` международного профиля; `.ru` оставить с `[ru]`.
5. Проверить переключение и независимость аккаунта/покупок от языка.

Одной записи `de` или `fr` в `SITE_PROFILES` недостаточно. Перевод интерфейса не создаёт
отдельную индексируемую версию: маршруты и публичные профили для неё требуют отдельного
решения. Сейчас языковых префиксов `/de/`, `/fr/` нет.

Остаётся ограничение расширения: `LANGS` и `SITE_HOSTS` в `web/lib/i18n/hosts.ts` ещё описывают
одновременно языки приложения и публичные языковые версии. Перед третьим языком нужно
разделить эти наборы или явно согласовать публичные адреса; механическое добавление языка
в общий список повлияет также на `hreflang`.

## Локальный запуск и проверки

Из `project/destiny-matrix`:

```sh
docker compose -f compose/docker-compose.localized.yml up --build -d
```

`localhost:3000` — RU; `127.0.0.1:3000` — EN с выбором RU/EN; API — `127.0.0.1:8010`.
Администратор: `snborodaenko@mail.ru` / `123`. Оплата имитируется, письма пишутся в лог.
Остановка с сохранением БД: `docker compose -f compose/docker-compose.localized.yml stop`.

Проверки выбираются по изменению; полный релизный цикл — в [release-process.md](release-process.md).
Для общего локального стенда браузерные сценарии используют
`E2E_API_CONTAINER=arcana-localized-api-1` и нужный `E2E_URL`.

| Проверяем | Существующие проверки |
|---|---|
| словари и чистые функции | `web`: `npm test`, `NEXT_PUBLIC_SITE_LANG=en npm test`, `npm run typecheck` |
| язык API | `api/tests`, в том числе `test_localized_admin_payments.py` |
| переключение и состояние | `e2e/test_runtime_localization.py`, `test_locale_client_state.py` |
| админка, документы, ошибки провайдера | `e2e/test_locale_completion.py` |
| публичный HTML, SEO, cookie и боты | `e2e/test_domain_localization.py` |
| корпус и страницы | `web`: `npm run check`, `CHECK_LOCALE=en npm run check` |

Браузерная приёмка включает RU → EN → RU, узкий экран, заполненные формы и ошибки,
покупки одного аккаунта, PDF обоих языков с отдельным кэшем. Доменная — противоположные cookie,
`Accept-Language`, Googlebot/YandexBot, sitemap/robots, canonical/OG/JSON-LD и неизвестный Host.
Для чтения PDF в проверках нужен `pdftotext`. Результаты отдельных прогонов хранятся в `reports/`.
