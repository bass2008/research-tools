# worker — исполнитель очереди задач Arcana Sense (Claude Code / Codex + MCP `arcana-tasks`)

## ИНСТРУКЦИЯ ДЛЯ CLAUDE CODE (выполнить сразу при чтении этого файла)

Ты — **диспетчер** очереди задач сайта. Задачи сам не выполняешь и их данные не читаешь: через твой
контекст идут только `job_id` и `type`.

1. **Проверь связь:** MCP-инструмент `status` (сервер `arcana-tasks`) — строка на каждый стенд
   (test, prod). Ни одного стенда или все недоступны — не начинай, скажи, что чинить («Настройка»).
2. **Встань в ожидание** — в фоне (Bash, `run_in_background: true`):
   ```
   /home/sergey/miniconda3/envs/research3.12/bin/arcana-tasks wait-jobs --timeout 60
   ```
   Команда опрашивает все стенды и завершается не позже чем через 60 с — раньше, если задачи есть.
   В stdout — `[{"job_id": "test:1", "type": "..."}]` (стенд и номер), без данных задач; пусто — `[]`.
3. Команда завершилась — одна строка статуса: время и что пришло. На каждый `job_id` подними
   **отдельного суб-агента** (Agent, `subagent_type: general-purpose`, модель opus) с заданием ниже
   и **сразу снова встань в ожидание**, не дожидаясь агентов. Одновременно — не больше 5 агентов.
4. `[]` — нормальный простой: строка «задач нет» и снова в ожидание. Пользователя не спрашивай.

Задание агенту (подставь `job_id`):

> Ты исполнитель задачи `{job_id}` очереди `arcana-tasks` (до двоеточия — стенд). Вызови MCP `get_job("{job_id}")` и
> выполни её строго по полю `prompt`: прочитай файлы, на которые он ссылается, напиши тексты, сдай
> через `submit_result`. `accepted: false` — исправь перечисленное в `problems` и сдай снова. В ответе —
> одна строка: принято или почему нет.

Без MCP (запуск без интерфейса, другой агент) — те же операции командами:
`arcana-tasks get-job test:1`, `arcana-tasks submit test:1 result.json` (или `--error "причина"`).

## Типы задач

| `type` | Что делать | Промпт |
|---|---|---|
| `test` | Проверка связи: сдать короткую строку «Связь с MCP работает.» | Встроен в MCP, без генерации контента |

Задачи создаются в админке: «Очередь задач» → «Добавить» → «Тестовая задача».
Чакры пары входят в статический корпус сайта и не используют очередь MCP.

## Как это устроено

```
админка → work_tasks → watch (job_id, type) → get_job (данные и промпт)
                                         → submit_result → done / failed
```

MCP работает с Claude Code и Codex. Исполнитель приходит за задачами через `wait-jobs`;
само подключение MCP не запускает обработку в фоне. Если сессия перестала опрашивать очередь,
через 4 минуты в админке появляется «офлайн». Ошибку можно вернуть в очередь кнопкой «В очередь».
Новые типы задач добавляются отдельными обработчиками; очередь не публикует произвольный контент.

## Настройка

1. Пакет (один раз): `pip install -e ../task-worker-mcp` в окружении `research3.12`.
2. Токен стенда выдаёт сам API (живёт год, подписан ключом API стенда — у local, test и prod свои):
   ```bash
   docker exec arcana-api-1 python -m app.worktasks                      # локально
   ssh root@<сервер> docker exec arcana-test-api-1 python -m app.worktasks   # тест
   ```
3. По файлу на стенд, вне репозитория: `~/.config/arcana/worker-<стенд>.env`. Есть файл — стенд
   обслуживается, нет — пропускается.
   ```
   # worker-test.env
   ARCANA_URL=https://test.arcana-sense.ru
   ARCANA_WORKER_TOKEN=<токен теста>
   TEST_BASIC_USER=...          # Basic Auth тестового домена
   TEST_BASIC_PASSWORD=...

   # worker-prod.env — после прод-релиза очереди
   ARCANA_URL=https://arcana-sense.ru
   ARCANA_WORKER_TOKEN=<токен прода>
   ```
   Локальный стенд — `worker-local.env` с `ARCANA_URL=http://localhost:3000`. Каталог меняет
   `ARCANA_TASKS_DIR`.
4. Регистрация MCP (user-scope, один раз):
   ```bash
   claude mcp add -s user arcana-tasks -- /home/sergey/miniconda3/envs/research3.12/bin/arcana-tasks mcp
   ```
   Проверка: `claude mcp list` → `arcana-tasks … ✔ Connected`.
5. Запуск: `cd project/destiny-matrix/worker && claude --model opus` — сессия прочитает этот файл и
   уйдёт в петлю. Лог MCP — `~/.cache/arcana-tasks/mcp.log`.

## Codex

Тот же MCP-сервер работает с Codex по stdio, отдельный API не нужен:

```bash
codex mcp add arcana-tasks -- /home/sergey/miniconda3/envs/research3.12/bin/arcana-tasks mcp
```

В новой сессии Codex поручите обработку очереди. Протокол тот же: `status`,
`arcana-tasks wait-jobs --timeout 60`, затем `get_job` и `submit_result`.
Для параллельной обработки явно поручите запуск субагентов: Codex использует доступный
ему инструмент субагентов, а не команду Claude `Agent`. Модель по умолчанию наследуется;
конкретную модель указывайте только из доступных в текущей сессии.
Без команды обработки очереди чтение или редактирование этого файла не запускает исполнителя.

В админке «Добавить → Тестовая задача» создаёт проверку полного пути через MCP.
Ответ исполнителя виден в строке задачи. Доступность обозначает опрос очереди за последние
4 минуты, а не наличие установленной программы. Удаление задачи не удаляет уже написанные
тексты; поздний ответ на удалённую задачу отклоняется. Удаление незавершённой задачи чакр
останавливает её выполнение в очереди; ожидающий разбор сам по этому действию не готовится.
