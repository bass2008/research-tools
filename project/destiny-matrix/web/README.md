# apps/web — фронт «Матрица судьбы»

Next.js 15 (App Router, RSC + SSG), TypeScript. Контракт — `docs/api-contract.md`, он главнее кода.

```bash
npm install
npm run dev        # http://127.0.0.1:3000
npm run build      # 316 страниц, из них 298 — энциклопедия
npm start          # прод-сервер
npm test           # vitest: порт движка против эталона Python
npm run typecheck
```

## Что где

| Путь | Что |
|---|---|
| `lib/matrix.ts` | порт `engine/matrix.py` в TypeScript — расчёт идёт в браузере, дата не уходит на сервер |
| `lib/sections.ts` | порт `engine/sections.py`: 20 разделов, 6 бесплатных |
| `lib/__fixtures__/golden.json` | эталон, снятый запуском Python-движка на 28 датах (6 из них — 29 февраля, есть 1900 год) |
| `lib/arcana.ts` | корпус 22 арканов (нумерация матрицы, Шут — 22-й) |
| `lib/encyclopedia.ts` | состав энциклопедии: 22 аркана + 37 позиций + 231 сочетание + 7 чакр + корень = 298 |
| `lib/tariffs.ts` | тип тарифа, формат цены и загрузчик прайса из базы; числа в коде — только запасные |
| `lib/analytics.ts` | цели Метрики; фильтр не пускает в параметры дату рождения |
| `components/Octagram.tsx` | октаграмма на SVG, геометрия из рукописного лендинга |

## Переменные окружения

Смотри `.env.example`. `NEXT_PUBLIC_METRIKA_ID` пустой — счётчик не подключается, цели всё равно
пишутся в `dataLayer`. `API_ORIGIN` включает прокси `/api/*` на `apps/api` в разработке.

## Правила, которые легко нарушить

- **Дата рождения не уходит с клиента.** Она живёт в `sessionStorage`, не попадает в URL оплаты и
  в цели Метрики. На сервер уходит только по кнопке «сохранить матрицу» у авторизованного.
- **Формулы правятся в двух местах сразу** — `engine/matrix.py` и `lib/matrix.ts`. Расхождение
  ловит `npm test`; эталон пересобирается запуском Python-движка.
- **Медицинских формулировок и обещаний гарантий быть не должно** — это проверяется тестом на
  корпусе текстов (`lib/encyclopedia.test.ts`).
- **Цена нигде не зашита в разметку.** Прайс живёт в базе; страницы с ценой (`/`, `/pay/*`,
  `/oferta`) печатаются на запрос и читают его через `getTariffs()`, статика печатает запасную цену
  из `FALLBACK` и заменяет её живой сразу после гидрации (`TariffsProvider` → BFF `/api/tariffs`).
  Практическое следствие: после смены цены `UPDATE`-ом продающие страницы верны сразу, а проза
  энциклопедии в готовом HTML держит цену предыдущей сборки до гидрации — поэтому цену в `FALLBACK`
  держим равной задеплоенной.
- **Цена рекламируемого тарифа обязана быть в первом экране** и в машиночитаемом виде (JSON-LD).
- **Реквизиты — заглушки вида `⟨ИНН⟩`** в `lib/site.ts`. Перед запуском заменить и проверить,
  что заглушек на страницах не осталось.

## Приёмка сборки

```bash
npm run build && npm run check
```

`scripts/check-build.cjs` берёт статику из `.next/server/app`, а страницы по запросу
(`/`, `/oferta`, `/pay/single`, `/pay/month`) — с сервера, который поднимает сам на порту 3131
(`CHECK_PORT`). Валит сборку, если: нет `title`/`description`/`canonical`/`og:image`/favicon;
есть медицинская лексика или обещание гарантии; есть `href="#"` или битая внутренняя ссылка;
цена рекламируемого тарифа не совпала с прайсом (сверяется с `/api/tariffs`, а при выключенном
api — с `FALLBACK`), не попала в первый экран или в JSON-LD; в юридических страницах пропали
заглушки реквизитов; в ссылке оплаты появилась дата.

Апстрим для приёмки не обязателен: без него страницы печатают запасные цены, и сверка идёт
с ними же.

Сгенерированный контент из `content/*.json` подхватывается на сборке пофайлово и
пополю: поле с медицинской лексикой отбрасывается, вместо него идёт встроенный корпус
(`lib/content.ts`). Поэтому чужой генератор не может протащить на страницы то, что
завалит модерацию Директа.
