# web — фронт «Матрица судьбы»

Next.js 16 (App Router, RSC + SSG, сборка Turbopack), TypeScript.
Контракт расчёта — `../spec/method.json`; описание API и адрес OpenAPI — в [README API](../api/README.md).

```bash
npm ci
npm run dev        # http://127.0.0.1:3000
npm run build      # production-сборка; фактический состав маршрутов — в выводе Next.js
npm start          # прод-сервер
npm test           # vitest: порт движка против эталона Python
npm run typecheck
```

Для обычного локального просмотра использовать `npm run dev`: значок Next.js слева внизу
включён, правки обновляются сразу. Полный запуск вместе с API —
`../compose/scripts/run-python.sh` или `../compose/scripts/run.sh` через Docker.
`npm start` предназначен для отдельной проверки production-сборки.

## Переменные окружения

Смотри `.env.example`. `NEXT_PUBLIC_METRIKA_ID` пустой — счётчик не подключается, цели всё равно
пишутся в `dataLayer`. `API_ORIGIN` задаёт адрес бэкенда из `../api` для прокси `/api/*`.

Все app-owned переменные загружаются только в `lib/settings/public.ts` и
`lib/settings/server.ts`, после чего читаются из `SettingManager` в памяти. BFF
`GET /api/admin/settings` сначала подтверждает admin-сессию в API, затем объединяет группы
`Frontend` и `Backend`. Значения с признаками пароля, токена или ключа автоматически обрезаются;
полный секрет в ответ и React-компонент не попадает.

## Правила, которые легко нарушить

- **Дата рождения не уходит с клиента.** Она живёт в `sessionStorage`, не попадает в URL оплаты и
  в цели Метрики. На сервер уходит только по кнопке «сохранить матрицу» у авторизованного.
- **Контракт формул — `spec/method.json`.** Python и TypeScript исполняют один граф имён и
  обязаны пройти те же golden-векторы и exhaustive parity всех дат с 1900 года.
- **Медицинских формулировок и обещаний гарантий быть не должно.** Единственный список правил
  собирается из `../content/data/<lang>/text-policy.json`. Обнаружение таких слов даёт
  предупреждение для проверки смысла, а не автоматический запрет нейтрального упоминания.
- **Цена нигде не зашита в разметку.** Прайс живёт в базе; страницы с ценой (`/`, `/pay/*`,
  `/oferta`) печатаются на запрос и читают его через `getTariffs()`. Статика печатает «уточняется»
  и подставляет живую цену после гидрации (`TariffsProvider` → BFF `/api/tariffs`): показать число,
  по которому не получится купить, хуже, чем не показать ничего.
- **Цена рекламируемого тарифа обязана быть в первом экране** и в машиночитаемом виде (JSON-LD).
- **Реквизиты выбираются по юридическому профилю сайта** из `lib/site.ts`; документы —
  из `lib/legal/`. Для российского профиля реквизиты заполнены. Проверять соответствие
  профилю и согласованность юридических страниц, а не наличие заглушек.

## Приёмка сборки

```bash
npm run build && npm run check
```

`scripts/check-build.cjs` берёт статику из `.next/server/app`, а страницы по запросу
(`/`, `/oferta`, `/pay`, `/pay/single`) — с сервера, который поднимает сам на порту 3131
(`CHECK_PORT`). Валит сборку, если: нет `title`/`description`/`canonical`/`og:image`/favicon;
есть `href="#"` или битая внутренняя ссылка;
цена рекламируемого тарифа не совпала с прайсом `/api/tariffs`, не попала в первый экран или
в JSON-LD; реквизиты юридических страниц некорректны или заполнены несогласованно;
в ссылке оплаты появилась дата. Совпадения со словарём `text-policy` выводятся отдельными
предупреждениями и требуют проверки контекста. Заполненные реквизиты не являются ошибкой:
gate не требует сохранять заглушки.

Для полной приёмки API должен работать на `127.0.0.1:8010`: без него страница оплаты честно
скрывает недоступную цену и не создаёт счёт.

Сгенерированные корпуса лежат в `content/<lang>/`, общие данные — в `content/`.
Ошибки обязательной схемы останавливают загрузку через `lib/content.ts` и `lib/contentReader.ts`;
встроенного запасного корпуса нет. Лексические предупреждения сами по себе не означают
ошибку схемы. Подготовку корпуса выполнять по [инструкции сборки контента](../content/README.md).
