# landing — посадочная arcana-sense.com

Один бакет с одной страницей на домене, который должен начать выдерживаться в поиске. Зона
создаётся здесь же (у `.com` её нет), содержимое лежит в `../../landing` и загружается самим
terraform: файлов пятнадцать, rclone ради них не нужен.

## Порядок

Сертификат Certificate Manager проверяется CNAME-записью **в этой же зоне**, поэтому раньше
делегирования он не выпустится. Отсюда три шага, а не один:

```bash
tf apply                                  # зона, бакет, файлы, сертификат в ожидании
terraform output zone_nameservers         # ns1/ns2.yandexcloud.net -> вписать у регистратора
terraform output -raw certificate_status_command   # ждать ISSUED
tf apply -var enable_https=true           # прикрепить сертификат, домен по HTTPS
```

NS у регистратора менять **после** первого apply: если делегировать домен раньше, серверы
Яндекса ответят «зоны нет», и отрицательный ответ закешируется у провайдеров на часы.

Проверка до делегирования — по адресу бакета:

```bash
curl -sI "http://$(terraform output -raw website_endpoint)/" | head -3
```

## Что здесь не так, как в ../site

| | `site` | `landing` |
|---|---|---|
| зона | берётся `data`-источником, создаёт `server` | **создаётся этим корнем** |
| домен | A-запись на VM, поэтому `manage_dns = false` | CNAME на бакет, `manage_dns = true` |
| TLS | certbot на nginx | сертификат Certificate Manager на бакете |
| содержимое | `deploy.sh` + rclone, тысячи файлов | `aws_s3_object`, пятнадцать файлов |

## Стоимость

Бакет с 600 КБ и один DNS-домен — единицы рублей в месяц. CDN выключен намеренно: фиксированная
плата за ресурс на одну страницу не окупается.
