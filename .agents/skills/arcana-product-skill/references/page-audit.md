# Оценка существующих страниц для поиска

Для задачи «почему страница не получает трафик и что стоит обсудить с владельцем».
Это анализ: вывод «усилить» не разрешает переписать статью, изменить индексацию или
отправить URL на переобход. Границы и итоговый формат — в
[seo-product-coverage-audit.md](seo-product-coverage-audit.md).

Исторические таблицы и расчёт срезов 26.09 и 03.10.2026 остаются в
[tools/seo/seo-plans/page-audit.md](../../../../tools/seo/seo-plans/page-audit.md).
Их пороги и выводы описывают тот замер, а не постоянное правило переписывания страниц.

## Какие данные сопоставить

Составить список текущих URL по карте сайта, реестру маршрутов и фактическим страницам.
Для каждого сохранить:

| Поле | Что проверить |
|---|---|
| URL, тип, язык | Реальный адрес, canonical, назначение страницы и её основной вопрос |
| Целевые запросы | Соответствие содержанию и странице-владельцу; есть ли конфликт с другой страницей |
| Спрос | Конкретные частоты, период, регион, операторы и статус данных |
| Показы, клики, CTR, позиция | Источник, поисковик, период, запросы и способ агрегации |
| Индексирование | Состояние и дата проверки; причина исключения, если доступна |
| Последний обход | Успел ли поисковик увидеть проверяемую версию страницы |
| Ответ посетителю | Есть ли нужное объяснение, расчёт, результат и понятный следующий шаг |

Спрос измерять по [seo-research.md](seo-research.md). Сумма частот разных формулировок
не становится дедуплицированным спросом страницы. Поиск чисел по подстроке недопустим:
аркан 1 не должен совпадать с 11 или 21; повторы в тройках сохранять.

## Как сравнивать периоды

- Брать сопоставимые полные периоды без пересечения и с одинаковыми фильтрами.
  Сохранять часовой пояс, дату выгрузки, фактические даты данных и полноту выборки.
- Проверять, одинаков ли охват выгрузок. Рост числа доступных строк запросов может
  выглядеть ростом показов; сначала сверить итоги источника и правила выгрузки.
- Позиции усреднять или брать медиану только с явным определением метода.
  Средняя по запросам, средняя с весами по показам и медиана дневных строк различаются.
- Не смешивать позицию из статистики Вебмастера с местом разовой проверки выдачи.
  Для живой выдачи записать регион, устройство и органический порядок; рекламные
  блоки не считать органическими результатами. Не считать номер страницы, умноженный
  на десять, точной позицией при переменном числе результатов.
- Малые выборки и недельные колебания отмечать как ограничение. Не закреплять
  произвольное число недель или показов в качестве универсального порога решения.

## Как читать индексирование

Статус на дату проверки и показы за прошедшую неделю могут различаться без ошибки:
страница могла войти в поиск и выйти между замерами. `LOW_DEMAND` — вердикт источника,
а не доказательство нулевого спроса или отсутствия показов за весь период.

Не сводить всё к одному статусу. Сопоставить показы, клики, обход, даты и фактический
ответ страницы. Отсутствие URL в ограниченной выборке API не приравнивать автоматически
к доказанному отсутствию в индексе.

## Как формулировать вывод

| Наблюдение | Что исследовать перед предложением |
|---|---|
| Спрос подтверждён, показов нет | Индексирование, обход, соответствие запросу, существующие страницы той же темы |
| Показы есть, позиции низкие | Полноту ответа, намерение выдачи, конкретные преимущества конкурентов |
| Позиции высокие, CTR низкий | Состав запросов, устройства, сниппет и блоки выдачи; достаточность выборки |
| Клики есть, продукт не даёт обещанного | Путь запрос → статья → расчёт → результат; возможный пробел продукта |
| Поисковик ещё не видел новую версию | Отдельно зафиксировать задержку обхода, не оценивать новую статью по старой версии |
| Частотности нет в базе | Проверить сырой кэш и другие сигналы; сохранить неизвестность вместо вывода «не ищут» |

Не выводить «переписать» автоматически из частоты 500 или 2 000, статуса либо позиции.
Предложение требует конкретного недостающего ответа и доказательства, что он полезен.
Рост после публикации сам по себе не доказывает причинность: меняются спрос, состав
запросов и видимость сайта. Аналогично отсутствие роста не доказывает бесполезность
текста, если поисковик ещё не видел изменение.

В результате показать найденные возможности с URL, запросами, цифрами и периодами,
кратким объяснением проблемы, предложением и ограничениями. Исторические срезы
не перезаписывать новым результатом; сохранять исходные доказательства каждого замера.
